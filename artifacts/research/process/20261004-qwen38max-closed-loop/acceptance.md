# Qwen3.8-Max 云端规划与 MuJoCo 实际操作测试

2026-10-04（北京时间），开发集实验，非正式 G1 验收。

**正常搬运成功 1/12，成功率 8.3%。** 全部 20 个预登记场景中完成搬运 1/20（5.0%）；后者包含 8 个目标缺失或故障场景，因此正常任务成功率是主要指标。没有把拒绝动作计为搬运成功，也没有剔除正常任务的规划失败。

| 指标 | 本次实测 |
|---|---:|
| 正常任务完整成功 | 1/12（8.3%） |
| 正常任务成功率 Wilson 95% 区间 | 1.5%–35.4% |
| 目标缺失时明确拒绝且未执行动作 | 4/4 |
| 无效深度时未执行动作 | 2/2 |
| 急停场景未执行动作 | 2/2 |
| 在线流程报完成，但物理结果不合格 | 1/20 |
| 环境或 API 故障导致阻塞 | 0/20 |
| 真实云端请求 | 35，全部 HTTP 200、正常结束 |
| 云端请求耗时 P50 / P95 | 4.52 / 5.78 秒 |
| 正常任务端到端耗时 P50 / P95 | 10.50 / 17.52 秒 |
| 输入 / 输出 token | 23,415 / 5,371 |

没有测量账单金额；token 数不能当作实际费用。

本次唯一视觉规划模型为 `qwen3.8-max`，通过用户提供的 Token Plan endpoint 调用。模型接收 RGB、深度可视化及任务指令，输出目标像素、放置像素和技能序列。原有本地 RGBD 几何处理、目标跟踪、安全检查、技能控制器执行这些计划；未调用本地小模型，未操作真实机器人，也不是由云端直接输出电机力矩。

**成功标准**：在线流程确认完成，并且结束后独立读取物理轨迹，确认物体抬升至少 50 毫米、双侧接触稳定保持至少 0.5 秒、释放后整个物体在目标区域内稳定至少 1 秒、无已覆盖的物理安全违规。离线真值仅用于评分，不参与在线决策。

**正常任务失败分布**：

| 原因 | 场景 | 数量 |
|---|---|---:|
| 预测点落在桌面，几何检查拒绝，重新观察后仍无有效计划 | 01 | 1 |
| 动作后目标视觉证据失效 | 04、05、06、11 | 4 |
| 抓取前无法验证目标可见、可达 | 08 | 1 |
| 抬升后的视觉保持检查未通过 | 02、03、10 | 3 |
| 抓取丢失、抬升不足 | 12 | 1 |
| 放置越界，在线误报完成 | 09 | 1 |
| 完整成功 | 07 | 1 |

这份分布包含模型定位问题和本地执行、跟踪、验收问题，不能把 11 次失败全部归因于云端模型。02 号场景的物理记录显示抬升 101.2 毫米、稳定保持 0.863 秒，但后续视觉保持检查出现缺失证据而中止，表明至少部分失败发生在在线视觉验收阶段。04、05、06、08、11 的日志同样记录 `visual_fact_missing_or_untrusted_source`；是否全部由机械臂遮挡造成，还需要进一步检查，当前实验未做因果消融。

**09 号场景的误报完成已经定位到判定差异**：最终物体静止且已释放，但物体完整投影在 x 方向超出绿色区域约 2.375 毫米。在线跟踪器检查可见色块范围，认为已进入区域；独立物理评分检查完整物体范围，得到 `PLACE_NOT_STABLE`，区域内稳定时间为 0 秒。这不是 API 失败，也不能算成功。需要修复的是放置完整范围与稳定性的在线验收。

唯一成功的 07 号场景：抬升 101.6 毫米、稳定保持 0.854 秒、区域内释放后稳定 3.675 秒。

与历史本地 `qwen3-vl-candidate:4b-instruct` 的 T7 v2 结果相比，相同 12 个正常场景曾成功 2/12（16.7%），本次为 1/12（8.3%）。已核对场景分配、原有管线源代码哈希、全部 20 个场景的初始 RGB 与深度像素完全一致。此次没有重跑本地模型；样本小且每场景只运行一次，不足以认定两个模型总体能力存在显著差异。Max 在这 4 个缺失目标场景均明确拒绝，本地历史结果则 4/4 出现动作。

此前 Max 的 10/12（83.3%）是另一组 T3 静态感知与规划检查，未执行抓取、搬运、放置，不能当作操作成功率。本次结果也没有达到 G1 的正常任务成功率要求。

**协议与可复核性**：使用原 T7 的固定 20 场景，12 正常、4 目标缺失、2 无效深度、2 急停；每场景一次，最多重新观察两次，不重试动作，不按结果调整提示词或控制参数。图像 320×240，归一化 0–1000 坐标，temperature=0，max_tokens=512，enable_thinking=false。云端别名及请求配置已经记录，服务端未提供不可变权重哈希，因此不能保证未来重跑得到逐字相同的输出。

通过绑定物理网卡 `enp7s0` 的 DNS/TCP 连接访问国内 endpoint，禁用环境代理和重定向，保留 TLS 校验。35 次请求均记录了实际套接字绑定与公网对端：`39.106.104.16`、`39.106.80.255`，没有回退到隧道。API Key 仅用于进程内存，输出目录凭证模式扫描未发现泄漏。

启动预检曾因实验记录子目录未创建而在首个 HTTP 请求之前中止。原脚本、异常和现场保留在本目录根部，见 `preflight-aborted.json`；云端请求数为 0。修复记录目录创建后，完整重新预登记并运行 `run-v2/`，不覆盖预检记录。实际模型测试的 20 个结果全部保留。

独立复核已重算 24,683 个物理采样点，检查 131 个相机帧、38 个已执行动作、35 份请求与响应，核对输入图像、哈希、模型身份、分母和 STOP 后无动作；结果 `valid=true`。
