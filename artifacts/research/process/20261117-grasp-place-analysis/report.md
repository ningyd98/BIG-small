# 抓放问题分析

2026-11-17（Asia/Shanghai）。分析对象为 `ca8c67ab1b1dff643301ed10a98fbbbcf2cdf084`，其产品实现与 `295a8ff3` 相同。本轮没有修改产品源码、控制参数、手指轨迹或安全阈值。

当前最先阻断抓放的是低位抬升轨迹与动态安全判据不兼容。抓持证据、中途掉物检测和未执行到的运输/放置仍有独立缺口；不能把一次解除拦截等同于完整抓放已成功。

## 1. 已复现的直接停止原因

在上轮三个 worker 原件之外，再进行一次零付费、同场景的 worker 复现。只在 `SafetyContextBuilder.build` 外包观测函数：调用原函数一次，记录 LIFT 输入，返回同一个对象。控制器与实际 SafetyShield 的判断未被替换。模型仍是原软件协议替身。

| 检查 | 物理步 | TCP 高度 | 目标高度 | 目标与 TCP 的横向距离 | MIN_HEIGHT |
| --- | ---: | ---: | ---: | ---: | --- |
| PRE | 1672 | 48.017 mm | 160 mm | 0 | ALLOW / UPWARD_CLEARANCE |
| 首次 SERVO | 1672 | 48.017 mm | 160 mm | 0 | ALLOW / UPWARD_CLEARANCE |
| 第二次 SERVO | 1680 | 48.021 mm | 160 mm | **0.017818 mm** | REJECT / MINIMUM_HEIGHT_VIOLATION |

规则在 TCP 低于 80 mm 时允许向上脱离，但条件是 `target.x == tcp.x` 且 `target.y == tcp.y`，同时目标高度达到安全高度。该条件在动作起点成立。第一段运动后，TCP 实际发生约 17.8 μm 的横向变化，固定目标不变，浮点全等比较随即失败。偏差来自物理运动，不能简单称为数值舍入误差。

控制器通过目标位姿 IK 得到关节目标，再用受速度、加速度限制的关节指令逐步接近。该路径没有提供整个 TCP 轨迹严格竖直的保证。因此，安全规则的“当前目标必须严格位于当前 TCP 正上方”与当前连续运动方式不一致。

主流程的 `SAFETY_SHIELD_SERVO_REJECTED_OR_LIMITED` 描述停止原因；独立物理评分的 `LIFT_BELOW_THRESHOLD` 描述停止后的结果。增加规划中的抬升高度本身不会消除这个起步阶段的拦截。

相关源码：`edge/safety/rules.py:697`、`simulation/mujoco/visual_servo.py:178`、`vision/execution.py:516`。完整输入见 [LIFT 上下文](lift-contexts.json)，实际拒绝与记录的规则结果一致。

## 2. 已确认双侧接触，尚未证明有效持物

`MuJoCoSkillRobot.grasp` 执行原闭合指令，步进约 1 s 后，依据左右手指均有接触来返回成功并设置持物 ID。其成功含义是接触成立；物体离台和搬运稳定性要由后续动作验证。

上轮三个 worker 的独立物理原件在此次读取前核对了 SHA256，六个输入文件与冻结清单一致。三轮轨迹相同：

- MOVE_ABOVE、APPROACH 均收敛，控制残差分别约 1.72 mm、3.53 mm。
- GRASP 返回成功，闭合结束有左侧 3、右侧 4 个接触点。
- LIFT 的 8 个物理步对应 9 个边界含端点采样；全部同时有双侧手指接触和桌面接触。
- 独立评分记录整轮最大物体升高 **0.248 mm**，未达到 **50 mm** 的要求；合格保持时间为 **0 s**。这包含闭合阶段的微小运动，不能当作 LIFT 已拿起物体。
- 记录中关节/手指限位、关节速度、工作空间和自碰撞违规计数均为 0。

本轮证据没有展示先掉物再停止的过程。夹力是否足够支撑后续搬运仍待完成实际抬升后验证。GRASP、RELEASE 沿用既有手指动作，没有在闭合/打开的每一帧重新进行视觉纠偏。

另一个验收边界是：LIFT 技能自身以 TCP 抬升和双侧接触保持判成功，独立物理评分才检查物体真实抬升、稳定放置等条件。后续必须保留这两层证据，不能用 TCP 抬高代替物体抬高。

详见 [接触与分阶段物理摘要](contact-summary.json)、`simulation/mujoco/skill_robot.py:133` 和 `simulation/mujoco/skill_robot.py:192`。

## 3. 途中持物丢失缺少即时终止条件

这是代码分析与软件反例发现的独立问题，不是本轮发生过掉落的证据。

当前动作开始时检查持物状态；`_move_while_holding` 在整个 `_move` 返回后再次检查。每帧 `servo_sample` 检查硬状态和 SafetyShield，但没有显式要求 LIFT/MOVE_TO_REGION/PLACE 始终仍持有预期物体。`CarrySafetyRule` 遇到 `holding_object=False` 返回 `ALLOW / NO_CARRY`，没有把它解释为正在执行的持物任务失效。

用同一组件合同构造新鲜、合法的 MOVE_TO_REGION 上下文：TCP 为 `(0.45, 0, 0.16)`，目标为 `(0.2, 0.25, 0.16)`，速度/加速度与实际 resolver 相同。只改变持物状态：

| 输入 | 完整 SafetyShield 结果 | CARRY_MARGIN |
| --- | --- | --- |
| 持有 object | ALLOW | CARRY_OK |
| 没有持物 | **ALLOW** | NO_CARRY |

这是纯软件反例，没有执行机器人动作，也没有绕过实际 worker 的动作入口检查。它证明单独的动态 Shield 没有表达“该运动必须持续持物”这一条件。结合边界检查的实现，途中持续掉物可能到动作结束才由适配器报告。

详见 [软件反例](counterfactual-carry-state.json)、`simulation/mujoco/skill_robot.py:412`、`research/sol_molmo_components.py:711` 和 `edge/safety/rules.py:830`。

## 4. 放置链尚无本轮执行证据

三个 worker 和本次观测复现均未执行 MOVE_TO_REGION、PLACE、RELEASE、RETREAT。因此，本轮不能判断实际放置误差、释放后物体稳定性，以及松手/退让时的遮挡是否满足要求。

静态核查表明：运输/放置要求当前完整目的地几何；注册标记丢失会停止；工具高度偏移在技能开始时冻结。PLACE 的高度计算采用目的地支撑高度与初始工具/支撑偏移，原件中支撑高度接近桌面，未发现把物体顶面误当作该支撑高度的证据。其物理落位效果仍需要完整运行验证。

最终成功需要物体落在目标区域、夹爪释放、机器人退至安全位，以及至少 1 s 的放置稳定证据。RELEASE 单独返回成功只说明夹爪打开。

## 5. 朝向与实时性限制

当前夹爪姿态使用固定向下四元数，没有在视觉循环中按物体朝向调整。由当前 XML 的指体初始位置、厚度和 40 mm 单侧行程计算，理想最大内间距约 **82 mm**；方块边长为 **70 mm**，偏航 45° 时沿夹爪闭合轴的投影约 **99 mm**。这是固定夹爪朝向、无形变/物体重定向假设下的几何风险；本轮没有做该角度的物理抓取，不能据此宣称它是当前 0/3 的原因。见 [几何计算](static-geometry.json)。

此前三轮测得完整 worker 墙钟频率为 15.55–21.18 Hz；独立伺服最大处理时间 96.345 ms，最大实际采集间隔 100.046 ms。现有 30 Hz 调度按仿真步运行，墙钟间隔没有独立硬上限。该限制影响高速跟随能力，但三次抓放的实际停止原因都明确为 MIN_HEIGHT，不能把频率波动作为此次停止的已证归因。

## 修复顺序与验收重点

1. 先统一低位抬升的轨迹与安全语义：绑定起点和冻结终点，约束整个竖直脱离路径与横向偏离，保留 80 mm 的安全高度要求。容差需要根据测量/控制误差界限确定；本次 17.8 μm 的一个样本不足以确定新阈值。验证正常脱离可完成、低位横移仍被拒绝。
2. 明确持物任务中的接触/滑移丢失判据和最大停止延迟，使动作途中失去持物资格就退出。在线用接触、机器人反馈与可用视觉测量，离线独立物理证据继续隔离。
3. 验证物体真实抬升至少 50 mm 并保持 0.5 s，再执行完整运输、放置、释放与稳定性验收。一次技能 success 或一个软件测试通过不能替代这个条件。
4. 在固定场景完整跑通后，冻结版本，分别测试朝向、遮挡、相机位置与新 seed，再处理墙钟调度和采集归档开销。
