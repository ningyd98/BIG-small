条件定位只计算命中真实目标且深度有效的预测点，参考独立方块顶面几何中心。Gemma 首轮全部有效预测点的 P90 为 105.66 mm、覆盖 12/12；它包含错误目标或桌面点，与命中条件下的 28.59 mm 不同。[Qwen 审计](shared/qwen4-audit.json)、[Gemma 首轮审计](shared/gemma-contended-audit.json)均核验了 20 次实际同消息双图传输及度量运算。

目标缺失时的模型可执行建议和实际误操作不同。上述筛选没有执行物理动作，不能把 0 次动作解释为已测误操作率，也不能给出物理任务成功率。闭环入口仍要求固定场景几何定位与完整契约通过，候选设置冻结后才可开始新的独立测试。

Gemma 实际下载的是 Google 固定版本 Q4_0 QAT GGUF 与 projector，图像预算为 280；不是另一官方 Ollama 标签的权重。MiniCPM BF16 与 Transformers 5.7 隔离环境使用 4x 图像模式。两者均实际完成 20 次推理、JSON 合规 20/20。MiniCPM 的缺失场景依据模型自行报告的低置信度被守卫拒绝，并非四次都输出 null 目标；全部有效预测点 P90 为 466.38 mm，命中条件 P90 因 0/12 命中而无定义。

Molmo2 每例分别查询目标点、目的区域点和自由生成的完整证据，共 60 次实际推理。第一版目标命中 12/12、原生缺失查询明确 ABSENT 4/4，但目的区域及技能、存在性证据不合格，未创建闭环服务。[第一版结果](molmo/development-full20-v1-offline-scores/summary.json)保留。

随后只调整任务描述与最终点查询的顺序，再完整运行 20 例、60 次推理，属于开发诊断。第二版有 16 例技能序列不合规、3 例存在性证据矛盾，1 例缺失场景的拒识契约合规；可执行例数仍为 0。17 个目的地点原始输出在 label 中复述含 ABSENT 的指令，被冻结的严格解析器拒绝，故不能写成模型完全未生成坐标。未修改解析器去挽救分数，停止继续调参。[第二版结果](molmo/development-full20-v2-offline-scores-corrected/summary.json)、[原始输出与解析审计](molmo/development-full20-v2-raw-parser-audit.json)保留。离线评分脚本首次进入非空决策分支时发现 API 参数漏传；修正评分调用后重放保留结果，没有重跑或更改模型决策。

MolmoPoint 首次推理配置已预登记为 INT8 线性层、其余 BF16；34 个上游文件全部通过大小与完整 SHA 校验，CPU 原生测试 26/26 通过，实际显存可行性尚未测。首测租约在外来 Qwen 自动退出后授予；首次启动真实报错为 Triton 编译缺少 Python.h，在模型加载和推理前中止，0/60 推理，GPU 峰值仅 309 MiB，不能据此称显存不足或质量不合格。随后复核并复制既有匹配 Python 3.12.3 头文件，用原 Triton driver.c 和原 gcc 实际预编译通过；只调整进程编译路径与本地缓存，模型、提示、解析器、精度未变。另一任务再次加载 Qwen，重试尚未开始，未停止或卸载对方任务。[完整校验](molmo/MolmoPoint-complete-integrity-after-resume.json)、[环境修复预登记](molmo/point-toolchain-environment-prospective-amendment.json)保留。
