# Runtime composition adapter — approved bounded design

Root approved this scope on 2026-10-04 after the T10/T11/T12 interface review. Implementation follows independent re-review of the corrected visual-repair snapshot.

The adapter composes the existing online evidence, repository-backed `AutoModeStatus`, active `TaskContract`, `ExecutionCheckpoint`, verification budget and role/network snapshots into the existing `DecisionContext`. It recomputes canonical condition verdicts and action evidence, extracts registered online risk features and uses the existing calibrated risk estimator. Missing risk artifacts or accepted calibration remain `UNKNOWN`; cloud numeric error bounds cannot stand in for native calibrated certificates. Full task, episode, observation, plan, command, mode and context identities must agree.

Provider and source/current-state callbacks receive or return recursively isolated snapshots. Recheck source identity and a fresh injected clock after callbacks, including failures. The source binding validates the actual implementations and settings; it does not admit a method. Actual INITIAL, calibrated provenance and qualified selection remain unavailable, so this adapter cannot enable JOINT or LOCAL_RECOVER. A flag, valid-looking typed object, saved summary or bare hash cannot open the physical path.

The adapter returns a composition result containing current `DecisionContext`, the existing `CandidateSet`, action and any existing audit trace/envelope. It does not dispatch, create an executor, switch modes, establish persistent budget transactions or activate repairs. Its only submission-facing operation is a read-only validation against a newly acquired authoritative snapshot, using `validate_decision_commit` and canonical `validate_evidence`, plus current source identity, cancellation, atomic boundary and absolute budget checks. Software diagnostic envelopes have no physical submission permission. STOP remains a disposition for the existing immediate safety path.

Root owns the real observation reader, native geometry/motion certificates and cloud-return/pre-Safety/pre-Skill wiring. The existing `TaskExecutor` and `ReplanApplyService` remain the execution and activation entries; their SafetyShield checks remain mandatory after this adapter's validation. The adapter cannot substitute a recapture or a prior PASS for the final current-state guard.

Owned implementation is limited to new `src/cloud_edge_robot_arm/auto_mode/runtime_composition.py`, new `tests/test_runtime_composition.py` and this artifact directory. Existing vision execution, role binding, policy/configuration, T11/T12 modules and UI are read-only. CPU TDD and targeted evidence/policy tests cover identity and version mismatch, source drift, UNKNOWN calibration and bounds, callback mutation and late return, duplicate-event handling, software trace rejection and closed actual admission. No endpoint, GPU, actual research run or physical acceptance is part of this software stage.

The initial adapter is a conservative JOINT composition seam. It must not silently broaden baseline or B3 ablation semantics, bypass existing native gates, or create an alternative research admission verifier. Any subsequent method-specific execution integration requires the existing frozen method contract and a separate reviewed admission implementation.
