# Runtime composition adapter — software preparation

The new adapter composes the existing T10/T11/T12 types and exposes a read-only guard for the existing executor. It revalidates complete current task/checkpoint/pending-step/episode/frame/plan/command/mode/context identities, recomputes canonical conditions and action evidence, and derives registered online risk features. Missing risk artifacts or genuine calibration remain UNKNOWN. Native model/fact-map numeric bounds do not create a certificate.

Actual composition always returns STOP/NOT_ADMITTED because the actual INITIAL/calibration/selection admission verifier is absent. There is no admission boolean or flag/hash shortcut. LOCAL_RECOVER remains unavailable. Software diagnostics require explicit `software_only=True`; their copied verification pool never modifies the authoritative pool, and every trace has zero future submission lifetime. The read-only guard rereads current source/state, recomputes envelope/candidate/physical evidence checks and still cannot return VALID for actual admission. Its result must pass the existing SafetyShield and executor boundaries after a future qualified integration; this module cannot dispatch, activate a repair or switch modes.

The `source_validator` contract is the owner-provided existing role-binding validator: return None after checking actual sources/settings, or raise. It is not an admission verifier, and a callback completion marker is not independent source/physical acceptance. Boolean/string return flags are rejected. Source validation and the authoritative snapshot are rechecked after callbacks; changed state, malformed identities, hard faults, expiry and late exceptional returns produce STOP. Arbitrary synchronous owner callbacks cannot be forcibly interrupted, so checks occur after return and provide no blocked-callback deadline guarantee. Owner-thread snapshot acquisition, real source registration and final native execution wiring remain root-owned work.

Full mutable descendants are isolated, including Pydantic observations/RobotState, condition values, capability collections, contracts and software budget. The bounded in-process event cache preserves one software audit decision, returns separate copies, and rejects changed or expired duplicate candidates. It is not a persistent idempotency/execution or budget transaction. A discarded late software intent may remain in the policy audit history, but cannot publish a capture or physical permission through the adapter.
