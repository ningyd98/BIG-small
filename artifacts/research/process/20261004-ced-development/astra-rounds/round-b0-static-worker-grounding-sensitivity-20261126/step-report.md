# B0 首帧的点位扰动如何传到抓取输入

固定真实首帧、整套标定、深度、任务颜色及目的区像素，枚举原 tracker 唯一目标支持内可通过 `normalized_1000` 表达的 256 个像素。通过原落地、抓取几何、tracker 和语义颜色门的候选为 182 个。独立原生实例读回确认这 182 个候选在该窗口的每张图上均落在原工件。其余 74 个保留拒绝，其中 16 个未证明目标表面高出台面，58 个未通过原 3×3 深度平面门。[Astra 计划](plan.md) · [结果与原件散列](sensitivity.public.json)

最远的 planner 点对是 `(162,106)` 与 `(174,119)`。这一扰动改变单像素 X/Y，但 worker 以 tracker 面中心取代 X/Y，且在原图中 182 个合法样本给出同一个 Z 偏移。独立参考由实际工件中心、原台面支撑、直立方向与现行工具的 +10 mm 偏置构成。这里测量的是静态目标坐标，实际 TCP 轨迹和动作末态未采集。11 帧的 RGB、深度和有效掩码字节一致，帧身份、时钟和标定分别核过。整个窗口属于同一个开发场景，枚举点也没有云模型回复的概率含义。

## 实际 owner 的证据缺口

源码顺序审计确认 `run_worker_online` 在首次 `prepare_worker_step` 之前就进入 `CLOUD_RETURN` 的原生证据门。此时还没有该步骤的 worker 落地发布，应用的原生校准源索引也缺失。原生 `native_action_contract` 显式保留空几何误差界和运动界。冻结的 `native_references` 将 MOVE_ABOVE、APPROACH、GRASP 归为物体接触参考。固定世界坐标仅适用于原定义的其他动作，坐标固定不提供工件未来运动界。

后续本地证据须取得实际 owner 原合同、checkpoint、落地发布及真实时钟，并能保持 CLOUD_RETURN、PRE_SAFETY、PRE_SKILL 和派发复核之间的身份一致性。动作完整时域取原合同、编译动作、owner 的已验证时域。被动观测长度及单调采集间隔只支持已观测数据。放稳还有独立缺口，当前 tracker 要求跨观测间隔的线速度上界和解除四分之一转对称性的角速度上界。当前静态数据不会把该事实推进到有效。

本轮结束于 worker 的可复算坐标输入，实际 owner receipt、动作时钟和真实云语义仍缺。新增曝光、动力学积分、动作、远程请求、真实 B0、正式 G2、独立正式评分和硬件均为零。该场景未见单像素 X/Y 偏差传入 worker 抓取输入，因此暂无证据支持在这里改写 worker 的 X/Y 几何。
