# G2 原始请求文件与尝试身份的独立读回

Astra 规划模型 gpt-6.2-astra。研发起点 `add414e4a01dd182e5234803df1753f00250405f`。原资源读回反例有四个不同 ledger ID，但两次尝试共用同一原请求与响应文件，仍计四次远程发送。B0 冷读同样只检查 ID、散列、长度和各自角色，未排除两个 ID 共享同一物理文件。

1. 扩展独立读回的共有路径，用同一已打开的普通文件句柄核对身份与字节。任一请求和存在的响应共用物理文件身份集合。拒绝跨 ID、跨收发方向、同路径或硬链接别名的复用，保持原根目录和符号链接边界。符号链接不进入原件读取。不同原件文件允许内容 SHA256 完全相同。
2. 原 ID 模式逐项对应已派发结算尝试、原请求和可选原响应。V2 或原 B0 强制核对完整的请求/响应角色、版本和 ID，记录有的字节数严格匹配。原 V1 保留现有字段接受，声明过的归属字段仍须相符。历史长度兼容入口保持可用，且无完整 ID 核对时不作为新的正式来源。资源、B0 和用量读回使用同一词义。B0 继续强制核对原角色及用当帧重新构造原请求内容。用量解析消费已校验字节，原始冻结清单仍是外部可信绑定。
3. 以一套共享集合覆盖 B0 一个阶段的所有案例。资源和用量入口的文件唯一性按各自核验的一次原始范围报告。原超时无响应、空响应、派发前失败、零派发证明、未知费用与完整分母照旧。变化限于离线源码和回归。确切复现拒绝同一收发文件、跨方向复用、硬链接、V2 角色漂移和冻结清单外原件更改。对独立文件中相同内容的真实重试保持两个已发尝试。
4. 本轮验证不授予新的物理或质量资格。现有 GOAL 继续等待实际合格 B0 与实际匹配试次。无外部请求、仿真、正式评估、硬件或冻结原件改写。
