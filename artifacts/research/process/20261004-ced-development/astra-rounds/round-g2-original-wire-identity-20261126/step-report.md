# G2 原始请求证据去重验证

原反例的四个不同请求 ID 仅对应三组原始收发文件，旧读回仍报四次远程发送。共用读回现在按打开文件的设备和 inode 核对原件身份，B0 阶段的全部案例共用检查集合。相同路径、跨收发复用和跨案例硬链接均拒绝。两个独立文件中的相同字节仍保留为两个已派发尝试。原 V2 的双向角色、快照和尝试 ID 与结算账本逐项核对，供应商用量从已验证的原始字节解析。[登记和输入散列](plan.json)

封存的旧名义探针四次远程尝试仍对应八个独立原始收发文件，并与当时清单的 SHA256 一致。该读回仅说明历史原字节兼容。当前执行代的角色探针、合格固定周期基线和正式配对验收均仍待真实来源。[历史兼容读回](historical-wire-compatibility.public.json)

八个 RED 反例复现。中间回归保留一项测试钩子仍指向旧读取函数的失败，钩子改为原件联结入口后，该测试继续检测读回期间的文件改动。最终 157 项回归通过，Ruff 检查通过。用量读回拒绝源清单未更新的等长原件及索引同时替换。保持旧账本、无响应与空响应的区别，证据复用及未知计费均未计入正式收益。
