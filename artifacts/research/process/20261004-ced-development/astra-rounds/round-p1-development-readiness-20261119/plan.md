# 开发批次预登记、B0 前置与交付环境

## 原始证据

- 四槽仅 1802 组件和独立物理同时成功，4 例不足以隔离位姿与运行方差。N≥20 是下一开发批次，非正式研究。ced_selection.yaml 四字段为空；历史四槽 3 次云请求金额缺失。当前 native 0/9，B0 真实未运行。文档首报 25 项（链接 10、脚本引用 7、敏感规则 8）。主工作树 config.py 只有默认场景的一行偏差，/tmp 中保有历史 checkout、wheel 及其回执。

## 实施范围与假设

- ⑥ 修复并验证后冻结 N≥20 个全新独立 development seed，与历史、教师、B0、后续 pilot 均做交集校验；预登记可复现的种子产生方法、位姿、冻结版本/角色、每组一次、无重试、预算与全部退出。另列固定 1802 或困难位姿的独立复测，登记为新 assignment/目录及事前重复次数，位姿 seed 与运行实例分开；不占旧四槽、重复位姿不加入独立 seed 的分母。预先固定二项 Wilson 95% 区间、每项成功的原始判据及处理全部失败/未执行的口径。给出组件和独立物理 n/N 与区间、复测逐次结果，申请/核对实际外部付费及本地窗口后再开真实批次。
- ⑦ 按 scripts/run_rgbd_pilot.py 的真实消费阶段分别查证 pools_path（互斥实际池）、role_probe（当前冻结角色/源的正常探针）、selection_evidence（通过独立审计的真实 selection 目录，供后继阶段）、protocol_evidence（按实际使用阶段和审计规则确认）。历史、干跑、派生摘要或路径占位不能填入；selection 不能使用自己尚未生成的结果当先决条件。提交已有真实材料与来源 SHA，逐字段给出 READY/待取得及取得途径。对账以实际费用台账/供应商凭据关联 request ID、金额与币种、未结项目；没有真实金额的请求保留 null，禁止拿 token 估算冒充账单。付费上限、币种、请求/重试规则、停止规则由实际预算授权确定；缺明示金额可推进离线准备，不能编造已获预算。0/9、480 干跑和每个真实 B0 前置分别列状态。
- ⑧ 先以当前 Git 及本地修改生成仅针对 config.py 的可恢复证据（原文件、限定路径 patch/哈希、基点与恢复验证），再清理该一行主树改动，保持其他修改及暂存区完整。对冻结 worktree、源 SHA、证据路径、wheel 哈希和安装回执做目录清单；在同文件系统持久区迁移并验证 Git worktree 索引/原路径消费者，迁移已有字节时留兼容入口或更新明确依赖。避免无谓复制和挤占教师空间。保留旧 SHA、所有历史失败和 raw 的私有交付边界。
- ⑧ 文档按基准 25 项逐条归类。CommonMark 含空格/百分号的链接先按真实目标验证；脚本引用区分实际入口及历史/提案文字；真实地址与四段软件版本分别处理。给 checker 增加正负控时同时检出真实坏链接、真实敏感地址；修复真实引用与文档，不泛化忽略规则。继续以 research/harness-candidate-20261118 为研发线。建议在本次准备交付的已验证代码/文档分别推送并复核、要纳入 main 的确切提交和私有排除范围完成评审、树及合并差异核验后进行集成；开发合入时点与正式资格分列，未明确授权向 main 发布则仅登记决定与条件。

## 运行前置

- P1 三项可独立衔接 P0；真实 N≥20 执行须冻结修后来源及资源；新 B0 需按现有资格/角色/恢复性、付费和运行授权。仅对明确归属的路径执行清理；迁移前核对可用空间、Git worktree 归属、读写进程和摘要，避免移动正使用的树。外来作者未提交状态/草稿继续独立保留。

## 验收

- 预登记与独立复测无旧 seed/claim 冒充或 denominator 混入；报告计数、区间算法、全部终态和成本。四字段逐项能由实际消费者复核；未取得部分、付款/预算状态逐项如实披露。check_docs --json 前后逐条核对，并跑相关治理测试、坏目标/真实敏感值拒绝的负控。检查清理后主树正确还原且原修改可恢复，冻结目录 SHA/wheel 可读，Git commit/本地、上游、远端一致。保留公私边界，执行证据与正式验收分别记录。
