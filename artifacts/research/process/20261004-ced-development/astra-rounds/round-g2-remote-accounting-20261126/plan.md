# G2 远程请求与观察成功率口径

Astra 规划模型为 gpt-6.2-astra。研发起点为 `672c549e50092d1fff6f50f23a1d5c3f23b39cc9`。本轮只修正本地账本和配对判定。源文件散列见 [plan.json](plan.json)。

`CostLedger.snapshot` 的逻辑云计数会纳入部署角色为 CLOUD 的本机提供者。旧 G2 直接使用该字段计算请求降幅。已有资源读回按 provider location 计算远程请求，保留原有逻辑云字段和历史文件。G2 的旧成功率判断只检查预登记的 −3 个百分点非劣效界，允许小幅观察下降。本用户目标还要求观察成功率与固定周期持平或提高。

1. 给成本快照加可空的严格非负远程计数。用唯一请求 ID 上的远程提供者、非空发送时间计数，涵盖规划、监督、重规划和裁判及其已登记失败、超时、重试。保留已知零的序列化。旧记录缺此项时继续省略新字段，字节化哈希可往返，禁止拿逻辑云或空默认值补数。
2. G2 在原固定周期 B0 与 JOINT 的全部正式 split 配对中计算远程请求效果。全分母和已知计数数各自报告。任一已配对记录缺数、无口径或基线为零时不发出达标结论。保留原分层配对、区间、Holm 五假设族、成功非劣效和安全上界。另要求观察成功差 `>=0`，较低即失败。软件指标不升级为实际证据。
3. 先保留 RED 证据。覆盖本机逻辑云角色和远程角色混合、超时及重试、未发送取消、同 ID 完成去重、旧记录摘要往返、已知零、缺配对计数及较低观察成功率。重跑原统计、分析、运行器和费用读回验证。纯软件运行无外部模型或仿真。
4. 正式评分仍关闭。当前适配器会在网络注入和实际 transport 调用之前登记发送。现有请求原文不能单独证明真实网络派发。正式资格仍需实际运行器、完整来源读回及 transport 派发与注入前拒绝的独立归属。保持已封存 B0 探针、请求预算、无外发状态和各门限。
