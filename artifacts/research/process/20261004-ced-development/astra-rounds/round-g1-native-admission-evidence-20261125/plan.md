# 原生 PRE 准入记录与冷读修复计划

基线 8e084282135ae3efbf817e481361f15a0e5fc4e3，原生代 d336529e21f5b0dab289c24ba8edcdab76bf284e7dc1f159e22bf4bf2859e9d9。完整输入散列见 plan.json。

## 原始失败

两次 MOVE_ABOVE/PRE 均在首派发前按预检设计中断，issued=0。两个原生冷读均报 admission evidence count differs from live observations。包装器在 super().check_shield 返回后抛出异常，原 admission 尚未完整产出 PRE trace、shield 与 action.pre 配对。原证据原样留存。

## 限定修复

只变更新开发包装的附加 PRE 净空判定与预检停点，将其移到原 admission 全部完成、第一条实际命令发出之前，绑定同一当前帧、步骤、合同与时钟；失败立即停。FEEDBACK 附加净空必须仍在每条相应运动命令之前。禁止补写 PRE 证据，禁止更改原 Shield、计时、频率、数据库、控制器或评分器字节。

## 前置与验证

复核输入清单、冻结 build 和原始 archive。建立全新预登记训练分配与 build，在原生 NVIDIA EGL、相同入口上真实采集并封存。每个新 case 用两个隔离的全新冷进程从原生证据逐项重跑原 check_audit 和读回，核对原 trace/shield/action.pre、帧与数据库一致，预检命令数为零。对缺项/替换和附加净空拒绝作负控。旧失败只作 RED。通过后优先实跑原控制器收集正常运动反馈。

## 计时边界

t01 同一帧 registered_handoff 692.345806 ms，首静止 PRE 到净空结束 1918.045757 ms，两者各自含采图，不能相加。两例运动 FEEDBACK 均 0。t02 cProfile 显示 pin_worker_source_inventory 14 次累计 2.849203063 s，含剖析开销。单列静止准备、首 PRE、各运动反馈；运动反馈逐次在原定采图至反馈完成边界判定 ≤100 ms，并保持原计时器起止和拒绝，任何更严格原门限仍生效。零样本不能通过。

## 性能假设与后续边界

首先在不剖析的原生反馈试跑上量分段耗时。仅在确证同一不可变注册数据的重复 I/O 影响门限时，允许在新开发包装内消除同一次完整验证内的重复解析/读取，前提是能证明每次原安全检查对源字节、完整目录集合/增删、路径/替换、期间变化仍等价拒绝。用同大小同时间戳改字节、替换、移除、增项、并发变化作反例；无法证明时保留逐次完整校验。禁止跨时段信任 stat 或缓存结果，禁止省略动态帧、净空、时钟及控制权限检查。若需修改受保护源或出现新的根因，暂停另立计划。

## 验收

分别报告两冷进程原生证据一致性、真实训练反馈次数及每次时间、原八阶段与独立评分。开发预检与耗时剖析不能充当训练通过。正式运行及硬件动作均为 0，冻结原件保留。
