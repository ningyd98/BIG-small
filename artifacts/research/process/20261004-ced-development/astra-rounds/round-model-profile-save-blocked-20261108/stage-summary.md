# 模型配置保存阻塞修复阶段总结

## 问题与实现
全局摘要请求在 ASGI 主线程同步遍历历史 artifacts，使模型列表与保存排队。原始接口读取在8秒内超时；运行中后台主线程95.2% CPU并打开历史证据文件。

按本轮 Astra 计划将触发扫描的 dashboard 请求移入线程池。EvidenceIndex 合并同时进行的刷新，并完整发布 records/errors 快照；后续刷新仍重新读取文件，无隐式陈旧缓存。保存表单提供等待、成功和固定错误提示；失败保留输入，成功清空密钥框。未增加持久密钥存储或现有配置编辑流程。

## 开发验证
- backend-red.log：9个回归用例按预期失败，证明扫描阻塞保存、重复扫描和半完成错误快照。
- frontend-red.log：2个用例按预期失败；原有未捕获保存异常也被记录。
- backend-green.log：相关后端37项通过，含证据路径安全和模型配置契约。
- frontend-green.log：保存反馈2项通过；frontend-suite.log：前端全部45项通过。
- 类型检查、修改文件 ESLint、Python Ruff、前端生产构建通过。
- 已知非失败提示：Starlette弃用警告、jsdom伪元素getComputedStyle提示、构建chunk大小警告。
- 独立只读审查未发现阻断问题；异常扫描通知多个等待者路径经代码审查，未添加直接行为覆盖。

## 真实运行
原后台无仿真任务，保留启动参数/环境于内存，只重启已识别后台。原进程18秒内未退出，核实进程身份后停止并重启；配置数据库和原始历史证据未删除。环境与密钥未落盘。

真实网页成功保存无密钥RULE_BASED测试配置（save-success.png）。实际API保存HTTP201耗时0.0104秒，列表读取0.0169秒；两条测试配置已精确删除，两条用户原有配置保留。截图ready-for-key.png显示用户原接口https://api.openai.com、模型gpt-6.1-sol已填好，等待用户录入密钥。没有读取用户密钥，没有新收费模型调用。

## 验收边界
本轮确认保存通路恢复，并非模型认证或正式研究验收。此前真实模型测试provider401；重启会丢失session-only密钥，用户必须重新录入才能测试。模型能力、机器人硬件、正式研究验收均未验证。
