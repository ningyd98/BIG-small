# 20 个新开发位姿、两次独立复测及真实 B0 角色探针

## 原始证据

- 用户已明确授权 B0 与本次开发批次付费“不限制次数和金额”。原始四槽 1/4 组件及物理成功，计费金额缺失。开发批次与正式 B0 的样本、资格、证据和账本分开。

## 实施范围

- 注册 owner 在首个 BEGIN 前发布完整 22 个 assignment：20 个互不重叠的新 development seed/位姿，与历史、教师、selection、foundation 等实际池核交集；另选预登记的一个已知位姿做两次完整独立复测（可取 1802），复用位姿 seed 和同一场景参数/分布，分别使用新 assignment、独立输出和独立 BEGIN。冻结生成规则、实际几何、次序、每例零重试、源码 commit/tree、安装 wheel、角色、观测/控制参数和成功判据。不同 seed 若产生同位姿查明并处理后才冻结。重复位姿作为单独分层，不加入 N=20 分母。
- 发起 owner 沿真实 CLI 与已验的 worker/安全/模型控制链派发，研究侧使用新轮与新路径的 owner/claim；复用先前单次启动/恢复方法，不能沿用指向旧四槽的固定路径和 seed。任一已 BEGIN 的 slot 无论成功、保护停、模型错或主机中断均保留，永不重发。恢复时只启尚未 BEGIN 的 slot，原始保护停止不阻止后续有资格的独立 slot。未知退出不能当成功，分开记录软件故障与物理结论。
- 独立 reader 逐槽读原 episode/动作、物理状态与接触/稳定性、命令/safety、worker/包装退出及实际云/本地计费原件；20 例分别报组件和独立物理 n/20 及 Wilson 95% 区间，所有失败与未执行状态都披露、未执行不得宣称已达到完整分母。两次复测逐例列出并另列事先固定的历史同位姿对照，注明不同版本或条件，勿将仅两次的结果解释成位姿难度的确定因果。
- B0 owner 可立即独立执行与候选真实角色配置绑定的正常 gpt-6.1-sol probe，使用 scripts/probe_rgbd_roles.py --execute --allow-paid 并传 config、当前选定 profile、受控 model-control-db 与新 output。确认当前正常角色及 source/hash，把实际出站、响应、CostLedger、用量与可取得的币种/金额独立绑定；保留原失败或未结账项及重启后的真实状态，无账单的金额为 null。按既有真实入口将通过材料绑定 role_probe，独立 reader 校验安装/配置/来源匹配。其余 selection/protocol 前置随实际证据补齐；达到教师完整资格、真实池与相关既有研究条件后再运行 B0。实际付费授权已具备，无需另设金额上限。

## 运行前置

- 先做已授权、可并行的注册、冻结准备、真实角色探针与独立读回。实际 20+2 正常链需修后同版冻结、通过适用的 worker 正控，验证模型绑定、持久原件输出目录、唯一 claim 与已有运行前置；无需等待正式教师九组合格。教师独占 GPU/EGL/CPU/重 I/O 窗口优先，真实 20+2 与使用同一资源的 probe 在专用时段串行调度。资源问题先测该输出卷和模型缓存实际可用空间、已占用/可释放部分与真实消费者阈值；延续既有阈值，避免跨卷误判或自行增加新的准入条件。

## 验收

- 研究分工有明确注册、派发、独立物理读回与付费对账责任；顺序、批次冻结、22 个不可重复开始与 20+2 分母均可核对。实测原件/结果/费用/未知状态如实入账；供应商原生请求按事实统计，“次数不限”不授权重试已开始的试次。所有终态保全并独立验收；未满足原资格的真实 B0 继续显示待运行。


## 同卷容量处置

生产 model_resources.admit_resources 用 shutil.disk_usage(model_directory).free 核对 60 × 1024³ 字节，另核 GPU、RAM 与锁。本机同一 ext4 卷规划时约 56.72 GiB。原阈值继续使用。为 20+2 预估旧同类四槽的真实占块和新增原件需求，在每槽启动前记录模型卷/输出卷、可用字节、累计增长；约 15 GiB 是候选回收目标，实际以核验通过的空闲量及批次剩余空间为据。角色探针若不加载该本地模型，取其自身实际前置。

执行人先列出已迁移三套冻结临时检出或其三套可重建安装依赖中同卷的合格重复文件。按 inode 与 st_nlink 去除重复计数，仅最后一个真正释放的独立 inode 计入回收，排除稀疏块/共享 extent 的逻辑重复。对每个候选核对大小、两端全字节 SHA、文件类型/执行位/所有者/权限/时间及 ACL/xattr 等适用元数据。Git 文件另核两套确切提交的 blob ID 与 Git 模式，并保证同名源与持久产品仍有独立 inode。安装依赖只选可从同一固定 wheel、SDK 及安装记录验证且全部消费者只读的稳定包文件；排除可变环境文件、解释器生成缓存、raw、日志、Git 内部数据与临时 pack。

优先在小样本用同卷支持的块级去重/写时复制保留不同 inode，实际确认支持及释放块后再扩。在确定永久只读、元数据相同且不要求 inode 独立的副本间，才可用临时硬链接加同目录原子替换保留每个旧名；不对共享 inode chmod、改属主或写入。运行时可能改写或无法证实所有权/稳定性的文件跳过。先保存原清单、映射、还原来源和设备/inode/mode/SHA，再分批操作；每批核所有名字、链接、元数据及内容、Git 工作树与三套 wheel/CLI 的正常入口；记录实际 df/statvfs 差和观察到的其他并发占用。未能取得足够真实空间则保留具体剩余量与下一类合格候选，不能编造回收或删除其他工作。教师独占期间避开批量扫描、哈希及替换。
