# 《面向边缘智能场景的小型机械臂云边协同控制系统的设计》项目整体规划与提示词工程

## 现行项目计划书（2026-11-17）：BIGsmall Embodied Harness

**最终工程交付定位：面向具身智能的云边端协同 Harness。** 本项目将在现有机械臂系统上形成可安装、可配置、可追踪、可评测的运行与实验支撑框架，暂称 **BIGsmall Embodied Harness**。Harness 负责把任务、模型、观测、技能和环境连接为受约束的闭环，并统一组织执行记录、版本比较和复现；首个参考实现仍是既定小型机械臂的受控桌面抓取、搬运和放置场景。

本节更新最终成果形态、封装任务和排期，配合[11月8日六工作包路线图](superpowers/plans/2026-11-08-proposal-roborsi-development-update.md)、[云边端研究设计](superpowers/specs/2026-10-04-cloud-edge-device-research-design.md)及[整体执行计划](superpowers/plans/2026-10-04-cloud-edge-device-research-roadmap.md)使用。三项研究问题、G0—G5、B0—B5、INITIAL/METHOD/FINAL及原实验协议继续有效。下方“历史原文”仅保留规划沿革；其中旧模型、旧日期、旧成果目录和提示词不覆盖本节。本轮是计划与开题材料修订，Harness 封装、正式研究和实机能力均不因文档更新而验收。

### 1. 研究目标与产品定位

论文题目继续使用《面向边缘智能场景的小型机械臂云边协同控制系统的设计》。共同工程基础是云边端功能划分和接口设计，研究主线为：①视觉观测与动作条件一致性；②风险与通信成本约束下的云边协同决策；③执行反馈与有界局部修复。Harness 将这些方法组织成可复用成果，框架封装本身不作为独立的算法创新或性能提升证据。

预期使用者包括本项目实验人员、需要复现实验的研究者及接入新模型或设备的后续开发者。最终应能选择已验证配置、运行规定任务、检查每次动作的依据、比较相同条件下的策略并定位失败。对外提供扩展接口，但能力声明只覆盖实际验证过的组合；首版不以跨机器人通用性或覆盖所有外部 benchmark 为完成条件。

采用在既有模块上提炼接口和发布封装的路线，执行器、持久化、控制器与安全边界继续复用。11月8日“近期不新增通用框架或执行引擎”的约束继续适用：先完成正常动作正链和合格基线，再逐步收口接口、配置与发行物。

### 2. SenseNova-RoboRSI 的参考与本项目适配

参考资料固定于官方提交 `9e7e7ad17b8957a5b8a530b8f4a0bbc11bb00555`，核查日期为2026年11月17日。RoboRSI 将共享运行时与递归改进分开介绍，提供 Agent 配置、轨迹记录、评测和安装包导出机制。[官方说明][HARNESS-overview]、[Agent配置][HARNESS-agent]、[评测指南][HARNESS-evaluation]

| 参考机制 | BIGsmall 计划适配 | 适用边界 |
| --- | --- | --- |
| 模型、技能与环境通过共享运行时连接 | 提炼云端 provider、观测证据、技能和环境适配契约，统一配置与生命周期 | 复用现有云边端系统，不复制上游执行栈 |
| Agent 配置、上下文与预算显式化 | 固定模型身份、提示生成规则、上下文预算、技能白名单和超时；展开配置形成指纹 | 云端保持用户选定方案；接口可扩展不等于模型可任意切换 |
| 环境保留原生执行与评分 | 在线依据允许的视觉和本体反馈决策；独立物理评价在离线端计算 | 教师真值、测试标签和环境成功标志不得泄漏给在线 Agent |
| 轨迹、状态、恢复与可比较性检查 | 将候选、拒绝、提交、动作、效果及成本串成同一 episode；检查实际运行版本再比较 | 恢复保留旧记录、原预算和失败分母，不能重启后重置次数 |
| 声明源码与资源后导出可安装包 | 发布本项目接口包、CLI、配置、示例、依赖清单和复现说明 | 模型服务、模拟器和第三方 SDK 按各自条件准备 |
| 固定模型参数下评测并保留改进 | 后续从隔离开发轨迹提出提示、上下文或经验候选，经回归与审查发布新版本 | 经验改进作为可选扩展，模型训练和在线自改安全规则不进入近期范围 |

上述映射是本项目的设计选择。外部排行榜、模型规模和收益数字不作为 BIGsmall 的已得结果或验收承诺。

### 3. 云边端架构与拟定契约

| 组成 | 拟承担的职责 | 现有基础与约束 |
| --- | --- | --- |
| 任务与配置入口 | 解析任务、场景、策略、模型及预算，生成完整运行身份 | 延续现有任务契约、研究配置和冻结规则 |
| 云端 Agent / provider | 接收允许的当前观测与结构化反馈，输出规划或修复候选 | 当前 `gpt-6.1-sol`；不进入实时伺服环，每 provider 在途请求上限1 |
| 边缘证据与决策 | 复核身份、时效、能力及风险成本，决定继续、重观测、请求云端或停止 | 规则/成本 provider，边缘模型选型后置；尚未验收的联合决策/恢复不得提前开放 |
| 端侧感知与技能 | OpenCV、RGB-D、可见姿态标记和顶视相机构造证据，经原控制器执行 | 保留 SkillExecutor、仓储 CAS 和 SafetyShield；提交前复核、幂等与硬停止保持 |
| 环境和机器人适配 | 统一观测、复位、受控技能执行与反馈，声明能力与时间语义 | 首先适配既有 MuJoCo 场景；软件替身仅验证接口，真实设备另行准入 |
| 轨迹、成本与独立评测 | 保存完整因果链、终态、资源与成本，输出可比较报告 | 区分声明配置与实际运行身份；独立物理评分不回流在线决策 |

运行闭环为：**任务与配置 → 云端候选 → 边缘能力/证据/风险检查 → 既有执行器和安全层 → 新帧效果验证 → 继续、重观测、有界修复、请求云端或停止**。Agent 不能通过新增工具接口绕过执行器直达关节控制；普通决策在技能边界应用，硬停止独立于模型响应。

下表是拟统一的契约要求，具体类名、函数签名和序列化版本由后续实施计划确定，不表示当前已导出这些接口。

| 契约 | 必要信息与行为 |
| --- | --- |
| 任务与运行身份 | task/episode、方法ID、场景与seed、源码及配置hash、模型/provider实际身份、数据来源组、预算、依赖与资产版本 |
| 观测与证据 | observation ID、采集时间及时间域、标定/目标身份、有效期、三值条件及原因、允许的本体反馈；旧记忆不能替代当前证据 |
| Agent 候选 | 输入任务、当前允许观测、动作schema和余预算；输出有计划版本绑定的候选意图，缺失依据保持 UNKNOWN |
| 技能与执行反馈 | 技能能力、参数约束、前置/后置条件、超时/取消/停止语义；区分接受、提交、启动、完成和新帧效果验证 |
| 环境适配 | 观测、复位与受控执行生命周期；物理时间/墙钟映射、等待期间环境推进方式、能力声明及资源清理 |
| 评测与轨迹 | 每次请求到效果的关联、拒绝原因、终态和失败分母；独立评分单独存储；请求、tokens、字节、费用和本地资源分别记账 |

模型请求超时、重复消息、旧计划、取消、重启和恢复均受原版本、CAS、预算及TTL约束。未获得真实账单或纯推理时间时记为 null，不能以端到端RTT替代纯推理耗时。

### 4. 当前基础、缺口与验收口径

本次读取的角色配置声明 `gpt-6.1-sol` 与 `deterministic_rules_cost_v1`，同时保留 `dispatch=false`、`local_recover_enabled=false`、`status=NOT_ACCEPTED`。这些是配置事实，不是当前正常物理任务成功证据。[现行角色配置](../configs/research/ced_roles.yaml)

11月8日路线图记录了已形成的软件框架、历史真实API回放和限定采集证据，也记录了动作资格、正常正链与合格基线仍待补齐。本次不将该历史快照称为11月17日最新运行终态；后续实施必须查阅对应范围的最新验收记录。新增统一接口、安装包、CLI、版本比较及发布验收均为待实现项，不能因已有同类底层模块而标为完成。

| 研究项 | 保持的目标与比较规则 |
| --- | --- |
| G0/G1共同基础 | 原G0门禁保持；有效目标定位误差P90≤10 mm并报告覆盖率；独立静态抓放≥90%；抬升≥50 mm保持≥0.5秒，释放后目标区稳定≥1秒 |
| B0合格基线 | 在0.5/1/2/5秒周期中筛选；静态≥90%、整体≥80%、安全违规≤1%，无合格者不宣称云调用节省 |
| G2协同决策 | 云请求均值减少≥30%；成功率差单侧95%下界>−3个百分点；安全违规率差单侧95%上界≤+1个百分点 |
| G2a工程成本 | 应用字节减少≥25%、含失败惩罚的任务耗时P95减少≥15%，两项分别评价 |
| G3证据一致性 | 相对B3误放行减少≥50%且绝对≤2%；有效安全机会误拒≤5%；UNKNOWN单列 |
| G4有限恢复 | 正式200故障组恢复≥80%；含失败惩罚恢复耗时中位数减少≥30%；已完成不可重复动作重提交0 |
| G5与可选扩展 | 维持原可选性质，经验包、跨引擎与训练不自动变为毕业核心目标 |

实验继续按开发/标定、selection、基础先导、方法冻结、功效先导和正式测试分组隔离。四周期selection采用120个组，新基础先导另120组，METHOD后的功效先导再用互不重叠的120组；正式每方法N从600/1200/1800/2400按原α=0.05、power=0.8规则选择，不追加至显著。场景聚类和条件分层配对bootstrap≥10000、95%区间、Holm校正及原比较族保持。任务惩罚 `Tcap=clip(ceil(P99_B0成功耗时×2/10)×10,120,600)` 秒、恢复惩罚 `Rcap=60` 秒不变。

失败、超时、停止、BLOCKED仍计入预分配分母。主比较固定共同模型、提示生成规则、上下文预算、经验版本、技能和安全层；不同触发时刻产生的观测差异属于方法作用，不能用共同旧帧覆盖。软件验证、真实API、实际仿真、正式研究与实机分别记录，在线效果与离线独立物理成功同时成立才计任务成功。

### 6. 最终发行物与复现验收

计划形成下列成果；目录仅表达预期发布结构，不是当前已生成的发行包或可执行命令。

```text
BIGsmall-Embodied-Harness/
  package/          本项目可安装Python接口包、CLI及版本信息
  configs/          模型/方法/场景/预算配置与schema
  adapters/         Agent、技能、环境适配规范与最小示例
  examples/         受控桌面抓放参考配置、离线接口示例
  evaluation/       任务/数据划分协议、比较及报告入口
  manifests/        依赖、资产、配置hash、许可证与证据索引
  docs/             安装、使用、扩展、故障排查和验收边界
  research/         论文、图表、限定演示及可公开的派生结果
```

发行验收要求：

1. **安装与接口验收：** 在声明的清洁环境中依锁定依赖安装本项目包，使用无凭据的离线示例验证schema、配置解析、状态与清理；自定义最小provider/环境替身按公开契约接入。该层只证明封装可用。
2. **首场景运行验收：** 在已满足动作资格、资源与授权条件的环境中，经正式入口完成至少一个受控正常闭环和规定的过期/失败拒绝用例；保存真实来源及独立物理读出。软件替身结果不抵作仿真闭环，单例不抵作成功率结论。
3. **评测复现验收：** 依据冻结manifest检查源码、模型实际身份、配置、资产和环境版本；复算指定结果与分母，记录差异。随机模型输出按协议比较统计结果，不承诺跨服务字节级相同。
4. **研究验收：** 原G/B、样本、消融及统计要求单独判断。安装通过可形成限定开发版；正式研究未通过或未完成时，发行说明与论文必须保留该状态，不能标为完整研究验收版。
5. **交付边界：** 发行包含本项目可交付代码、配置、示例与小型派生材料。凭据、完整批量raw、运行数据库、模型权重和第三方SDK按既有边界单独管理；依赖下载条件、授权和不可公开部分明确列出。缺完整数据时只称可复算的指定材料或部分复现，不称完整远端复现包。

### 7. 受控离线改进与后置扩展

可选的经验改进流程为：**隔离开发轨迹 → 候选提示/上下文/经验或策略 → 固定条件评测与回归 → 审查批准 → 冻结新版本 → 发布并保留回滚版本**。候选未改善或引入退化时不晋级，原失败保留。近期模型参数保持固定，正式测试集不能用于选择候选或调参，不跨测试episode写入自适应记忆；经验中的坐标必须经当前帧重新定位。

若独立评价经验或上下文改进，其开关与主云边策略分开对照并计入额外调用和资源成本。VLA/27B训练、自动经验检索、更多机器人、外部benchmark、Isaac跨引擎及真实机械臂验证均后置，按新增范围单独制定计划和验收条件。
