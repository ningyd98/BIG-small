# 首次 MOVE_ABOVE 提交时的双门读回

八个已提交的开发动作都能从原件还原。每个动作使用同一个 RGB-D 观测、原始 PRE 机器人状态、执行契约及提交前最后一次来源复核时刻。B3 八次返回 VALID，JOINT 八次返回 UNKNOWN，理由均为缺少标定的几何或运动误差界。八个历史动作的原始 SafetyShield 全部放行且未修改参数。

| 两门调用 | B3 和 JOINT 各 8/8，配对结果全部为 VALID / UNKNOWN |

## 采集来源与时钟

预分配绑定 Astra 计划的 77 项输入，对四个摆放逐一取登记顺序中的首次真实 MOVE_ABOVE。每个 episode 的交接帧均与 PRE 条件、PRE Shield 和最后一次 dispatch_source_recheck 的 frame ID、逐像素内容校验和、物理步及 episode 一致。原源清单的 456 个条目与原始计划和注册绑定逐项相符。最后一次来源复核记录有 UTC，第一条关节目标命令记录有同一物理步 120，原件没有单独记录关节命令的墙钟时刻。

提取进程只向盲目录写入白名单中的原帧、原状态、原始任务计划、完整当前契约和绑定、参考像素、历史回执、时钟角色与第一条命令。盲进程重新计算注册目标像素、目标区像素、参考 TCP，并与历史记录比对。它使用产品的归档颜色跟踪器，以同一个 Python 观测对象初始化跟踪并生成首次 PRE 事实。实时入口没有单录颜色检查的微秒时刻。分别使用原件记载的初始化与条件检查区间两端，确认整个区间处于同一有效分支且完整事实相等。独立读回另外交叉组合两个区间端点，八例再次得到相同事实。准备阶段的空事实与最终结果、物理真值均未作为盲门输入。

完整步骤模型中的 current_step_id 在这些原件中为空。所取动作由原契约第一步、prepared.grounded_step、第一条提交和 PRE action clock 一致确定。原契约序号均为 1。底层实发命令序号在四个名义视角为 1、在四个平移视角为 2，分别与各自命令记录的首序号核对。预检中这两项字段差异和处理依据记入 reproducibility.public.json。

## 核验与结论范围

从混合归档再次独立读回八次原始提交、完整规则与条件回执，重算 16 个原生门返回。十项负控全部受拒，包括跨例帧、错误动作、错误时间、错误物理步、截断规则、准备阶段冒充 PRE、空事实、错拼 MOVE_TCP 标签、调包机会，以及从盲进程读取混合记录。八个测试模块共 88 项通过，三份脚本及测试模块通过 Ruff 检查。用最终代码在第二个独占私有目录重做预分配、抽取、盲判、评分和核验，五份主要公开 JSON 的 SHA256 逐一完全一致。

此前四个固定 MOVE_TCP 机会的独立物理标签仍为两例 VALID、两例 INVALID，缺少可证明的注册技能语义等价关系。本轮 MOVE_ABOVE 有共同安全层与双门输出，缺少逐机会匹配的物理标签。毕业设计可据实比较同批开发动作上的判定差异，开题要求的两种错误率仍缺对应实验分母。本轮新增的正式 claim、MuJoCo 仿真、模型请求和实物动作均为零。
