# 历史开发 d02 的原生反馈窗口和候选预算

候选的 350 个完整顺序配对窗口估算 P95 为 53.557 ms，最大 65.241 ms。加入末端相邻帧的 60 次重复后，410 个估算窗口的 P95 为 64.528 ms，最大 65.421 ms，均满足 80 和 90 ms 的设备前预算。原动态窗口只有 70 个；多次软件采样重复使用同一帧的原始动态窗口。候选构建和原生零步预检均已封存。[预算计算与每一次配对](paired-d02-window-budget.public.json) · [构建、正常预检与原件摘要](candidate-preflight.public.json)

每个原始窗口以物理步、frame_id 和载荷 SHA256 与当次采样配对。第二、三行使用原相机与角色登记的 UTC 时间，第四行使用同一帧两个原生单调时钟区间相减。第四行含两端的 owner/hard-state、目标检查、原 IK 和之间的 Python 调用。原日志没有逐条 SQL、单独 Shield、复制或 IK 的各自耗时。候选预算对每行原实测总时长加上同一份原始 RGB-D、同次交错运行得到的候选与基线视觉耗时差，最后对这些估值取分位数。原停机帧 0073 的全部 35 次配对估算 P95 为 65.270 ms，最大 65.421 ms。实际的新调度和动态轨迹只能由新一次正常运行测量。[原始 70 帧的登记、摘要和时间](native-d02-window-segments.public.json) · [计算脚本](diagnostics/d02_window_budget.py) · [逐对视觉计时](pixel-timing-samples.public.json.gz)

额外的零步计时尝试在取得两张复位帧后，被原注册 handoff 明确拒绝。该原函数要求物理步号为 120，现场步号为 0。未执行 feedback，零后端命令，旧作业正常释放，保留失败状态。首次计时器在初始化失败时只保存了两帧的标识与载荷摘要。随后用原正常预检独立完成两次复位与八张实采帧，可见分支通过，全遮挡分支执行一次保护保持，物理步数为零。这个预检独立验证来源、当前目标和失标反馈。[额外零步拒绝原件](diagnostics/zero-step-handoff-refusal.public.json) · [正常预检读回](candidate-preflight.public.json)
