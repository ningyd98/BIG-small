# V10 Phase 3 步骤报告

## 协议与来源

基线为 `fc6520c0`。Astra 计划的 34 项输入 SHA256 已核对。原软件探针证实 prepare 可生成 v10，`read_protocol` 拒绝，非零派发时绝对步又会造成超限误判。现在 v10 读取和运行前来源核对都比较固定配方。临时 CLI 验证只释放首组，9 组均为 `NOT_RUN`。启动与重试负控使用临时目录和软件 worker 夹具。[Astra 主计划](plan.md)

## 相对步与原件关联

runner 从实际派发绝对步计算控制器已用步。普通动作按返回步判断。LIFT 以返回记录里的实际总步数和 120 步接触保持为依据，推算运动完成步。RELEASE 在控制器返回后还需保持至少 240 步。控制器截止含等号。保持后实测终步必须精确匹配注册值，且终端采集须产生新帧。回执保留绝对步，Shield 的 v10 活动窗口使用动作相对步。

非零派发步下已验证三个代表技能在等号处允许、超出一步拒绝。补充 Astra 轮保留夹具 JSON 编码失败及回执外层 step_id 错配的原始证据。八动作软件时间图读回在 12,960 步结束。伪造 LIFT 保持步数或外层步骤 ID 均遭拒绝。[补充计划](../round-v10-phase3-reader-fixture-20261121/plan.md)

## 兼容与验收

159 项聚焦回归通过。语法、导入与 Ruff 检查通过。周边回归的同 33 个节点在基线和候选中均报现有 SQLite 夹具数据库身份错误。两个 mypy 口径的既有诊断逐条相同。

当前代码可以用历史读取模式读取 Phase 2 生成的 v9 协议。更早的正式 v9 档案由其对应冻结源码只读验收，当前代码回读该档案的合约原件也保持载荷与哈希。

完整离线准入读回仍有既有版本缺口。v2 记录未输出完整 reader 所依赖的 v7 字段，例如 `registered_pose_evaluated_at`。本轮正式仿真运行数为 0，正式研究资格待验收。[详细验证](validation.public.json)
