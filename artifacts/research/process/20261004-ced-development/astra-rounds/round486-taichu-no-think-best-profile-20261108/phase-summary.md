# ZDTaichu FP8 思考开关与 FLA 对照结果

本次最快是 FLA-only + 关闭思考，warm 端到端中位数 12.169 秒。但四种配置均未达到 4/4 完整质量门槛，因此本轮没有可推荐正式接入的最佳配置。

| 运行环境 | 思考 | 输出 token | warm 端到端中位数 | 严格 JSON | 完整质量 |
|---|---|---:|---:|---:|---:|
| 基础 PyTorch | 开启 | 512 | 36.412 秒 | 0/4 | 0/4 |
| 基础 PyTorch | 关闭 | 194 | 14.035 秒 | 0/4 | 0/4 |
| FLA-only | 开启 | 512 | 34.299 秒 | 0/4 | 0/4 |
| FLA-only | 关闭 | 176 | 12.169 秒 | 0/4 | 0/4 |

同一 RTX 4070 Ti SUPER 16GB、同一官方 FP8 权重和固定 S01 RGB/深度可视化双图。每组重复 4 次；warm 为该组首次之后 3 次中位数，顺序 ON/OFF/OFF/ON/ON/OFF/OFF/ON。仅有一个静态场景，不估计泛化质量、稳定 p95 或统计显著性。

基础环境关闭思考缩短 61.5% 耗时；FLA 关闭思考相比基础关闭思考的观察耗时再缩短 13.3%。后者输出由 194 变为 176 token，内容与坐标数字也改变，不能将全部差额归因于内核。

开启思考的回答均达到 512 token 上限；关闭思考均正常结束，但完整原始回答带 Markdown JSON 围栏，严格解析拒绝。没有剥离围栏/思考、补全文本或修坐标。严格 JSON 未通过时坐标不可评分，不能把 0 hit 当成已测定位失败，也未证明关闭思考保留空间能力。

两个环境都真实加载 248 个 FP8 GPU 层，原 ViTPatchLinear BF16 层与 SDPA 范围不变；全部 16 次生成后 FP8 保留。FLA 的两个 GDN 实现被选中并实际调用；causal-conv1d 仍用 PyTorch fallback，因此不是完整快速路径。原 68 包版本/来源均保留，FLA 两包安装在独立 overlay。

FLA 第一模型请求 58.166 秒，包含模型内核首次编译。之前另有 10.907 秒的 driver/4096 元素数值/processor 就绪检查，已单列；该组不是全冷启动。TTFT 未测量。

R487/R488 保留了两次生成前证据记录失败及实际 Astra 计划；集合与 JSON 原生字符串子类处理均有 CPU 证据。R489 只将匹配开发包解压到隔离缓存并以子进程 CPATH 引用，系统未安装新包；真实 CUDA/JIT 数值门槛通过后才执行 B。共 4 次 load、16 次生成，没有额外模型 warmup。

软件兼容、真实模型运行、固定场景质量和正式研究验收分别记录；正式验收未执行，未进行硬件派发或闭环抓取。完整 raw、权重、wheel、headers、venv 和 JIT 留本地；提交的是脚本、计划、清单和派生报告，不是完整远端复现包。

复核入口：comparison.json、request-metrics.csv、scores-base.json、scores-fla.json 与各轮 step-report。研发提交以已交付 8b4a88b 的模型测试分支为父，仅加入本轮明确 artifact；复用的关键源码已核对与当前 live 输入字节一致，共享工作区的其他改动不在交付内。
