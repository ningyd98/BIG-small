# t01 原 5.5 s 补偿发令冷读

两次独立 CPU 冷读逐数字段复现了真实 t01 的 44 条关节命令和 216 步实际驱动，结果逐字节相同。入口原末次 arm 命令是第 1392 步的原生 HOLD。第 1632 步从实测关节位置计算并发送第一次补偿目标，没有重申保留目标。此轮不改控制器。[计划](plan.md) · [机器读回与散列](compensation-readback.public.json)

初次读回错误要求入口重申旧关节目标，原命令回执否定了这一假设。改按原命令类型重建后，仅从积分末态做 `mj_forward` 的质量矩阵仍无法闭合 1632 的首次发令。用原曝光的七轴及双指位置重建入口质量矩阵，随后按密封状态真实重积分，原实发目标与实际控制量最大误差均为 0。两次读回共使用 432 个 CPU 积分步。已存 1840 即时制停见证再次核出 ID8 板沿世界负 Z 超原容许量 0.162402 mm，没有新增制停积分。

历史入口没有保存原 RK4 的 `qfrc_actuator` 与 `qfrc_passive`。只对积分末态执行 `mj_forward` 时，核对得到的手臂 `qfrc_bias` 与真实入口缓存最大相差约 1.149×10⁻⁵ N·m。这不足以复验基于真实入口反馈的备选初始化。候选未获资格，安排另轮核查原复位至入口的受限回放能否恢复缓存。新增曝光、真实任务派发、整机、正式仿真、独立正式评分、硬件及远程均为零。
