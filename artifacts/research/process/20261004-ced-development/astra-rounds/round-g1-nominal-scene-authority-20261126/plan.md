# G1 名义静态端翼装配的来源与运行写边界

Astra 计划由 gpt-6.2-astra 制定。基线 a535ac9c050ca8d64c737d9edc47fc10be559fc5。

原 LIFT 三次未归属近面首停及一次注册体积首停继续有效。封存五次近面拒绝的十个问题像素均与完整 8+240 步保护包络相交，旧 t02 的针与空场原 RGB-D 逐位一致，独立原制停首碰撞在第 176 步。先前闭场夹具只证明一个写入口可控。B03 的连续 RELEASE 已通过隔离实测，覆盖不到较早的 LIFT。本轮假设是，真实运行端可证明名义资产的编译来源，拒绝公开场景改写，并记录低层状态写入的缺口。该结构只为进一步净空证明提供输入。

1. 核对 plan.json 的 SHA256、实际导入源码、运行时资产与父分配。独立解析端翼 XML 的资源闭包及直接加载分支。登记实际 handle、owner 线程、原 seed/reset、装配、相机配置、进程作用域和输出。按原模型独立核对编译体、关节、全部几何、传动、材质、相机、灯光与静态/载物/机械臂归属，以及额外自由体、外部作用和依赖。任何未映射资源拒绝。真实额外静止细针只离线编译核实，不能进入名义端翼接收路径。
2. 用冻结 MuJoCoPhysicsBackend 真实 initialize/reset，保留原 render 布尔及初始关节。在 reset 前进入原 on-demand，使用已有清理哨兵杜绝结束时隐式曝光。每个探针使用独立私有后端。复用原同步 enforce_execution_guard，观察公开 API 的真实调用和原安全停机。唯一正控执行原生一步，核对原生 RETURN/CONTROL/PHYSICS 前后边界以及 owner、episode、控制和原相机无曝光。
3. 实际请求一次复位、重初始化、移动相机、on-demand 模式改变、非急停故障、另线程关节命令。每例用全新后端，保留原拒绝与守卫终止日志。三个受控低层负控独立检查持久编译模型变动、同进程修改后恢复，以及直接写入自由体状态。最后三个夹具用真实 step(0) 的 RETURN 前置检查观察边界，不产生积分，不执行技能。直接低层写入只在负控夹具由离线审计标记，不进入正常 G1 控制器或感知判据。
4. 两个新的 CPU 进程冷读封存原件，独立重新编译并比对资产归属、同会话指纹、白名单、真实调用顺序、步骤与拒绝。复用已封存的十像素、旧针及体积对照，报告闭场、完整未知占据分离、当前光学来源和原门资格，不用端点哈希代替持续闭场。保留正式配对按原单标及低位双标的原范围。

预算至多 12 个一次性真实后端，1 次负控模型编译，1 个原生积分步，2 份 CPU 冷读。光学曝光、GL、任务技能、整机、正式及独立正式评分、硬件、远程全部为零。安全关闭的固有 hold/STOP 单列。失配、超预算或原件异常立即封存并止。原守卫和所有既有拒绝保持，诊断证明不可作为在线放行凭据。
