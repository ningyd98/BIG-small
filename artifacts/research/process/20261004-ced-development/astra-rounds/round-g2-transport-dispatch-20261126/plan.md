# G2 原生请求派发归属

采用 gpt-6.2-astra 对网络注入路径的补充计划。起点为 `9f463b60d9e000f9a8ea5e15a442ed9e46c4675f`。原请求观察器和有发送时间的账本行产生于 `NetworkInjector.begin` 之前。已登记的上行注入丢包可在从未调用 transport 时留下相互匹配的请求原文和发送计数。

1. 先通过无套接字的假 transport 复现。使用真实网络注入器制造上行丢包，确认旧路径没有调用 `opener.open` 仍把请求计入远程发送并留下 wire 原件。验证派发后超时、下行丢包和后续成功重试各保留一个独立已发尝试。
2. 只变更原 `RGBDPlannerAdapter._post` 的派发归属和 B0 pilot wire 绑定。构造请求与 opener、完成上行注入，再执行原请求观察回调。观察通过后，紧贴 `opener.open` 写已派发账本。派发前失败保留唯一终态尝试 ID，发送时间为空且字节数为零，不占 wire 编号。若观察器自身留下部分原件，读回保持完整性失败。派发后的超时、响应丢包和错误保留原本发出的请求。
3. 用现有 B0 pilot collector 做闭环软件检查。零派发的上行失败需没有 wire 条目。多尝试须保持身份及响应 presence，原资源读回仍按唯一已发 ID 对齐。保留现有请求协议、模型、提示词、角色、故障注入设置、预算、原始证据及正式门限。
4. 当前证据只证明应用层 transport 调用边界。历史原件仍用原版本读回，匹配的原文和账本不能补证服务器收讫。新版源需要重新登记角色指纹。未获授权时不运行名义探针或真实 B0，没有外发、付费调用、正式评分、仿真或硬件。
