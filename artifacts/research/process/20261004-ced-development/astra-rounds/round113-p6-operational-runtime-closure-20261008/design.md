# R113 — P6 architecture and stage A contract

This document binds the accepted P5 implementation. It authorizes no execution on its own. Only stage A is eligible for the current ROOT activation; B/C/D require later actual Astra stage plans bound to then-current inputs. The complete six-unit P6 objective and all 47 proposed CPU cases remain requirements.

## 1. Evidence and acyclic exit structure

Master Task6 requires current reads inside real transactions and immediately before real dispatch, original budgets and complete D/S segments. Task7 explicitly accepts P6's **corresponding source/time scope** and permits producer/reader CPU development ahead of actual collection. R91 design sections4–6 distinguish application-owned TEACHER_COLLECTION authority from native execution qualification. Therefore the order is:

`P5 accepted -> A lease/transaction authority -> B local publication/budget migration -> C real mutation/observer source-time closure -> P7 collection/reader + P8 native integration -> D full native positive Memory/SQLite closure`.

A/B/C are useful independently reviewable work. C can qualify the specified source/time mechanism for P7 when its implementation and evidence actually pass. It is not full P6, native qualification or a collection-run authorization. D's two positive cases are mandatory and cannot be deleted, skipped, xfailed, replaced with all UNKNOWN or replaced by teacher execution. P7 CPU software may also progress without writing protected P6 sources. The same original Sol is the only writer of shared source/test files.

Current evidence is a read-only gap map, not an executed failure: job `publication_guard` yields None and is not an issuer; acquisition takes UTC now before BEGIN; heartbeat/release do not share that guard; P5's `_check_live` still invokes the real UTC lease reader. Event Memory uses a nonreentrant Lock; event SQLite uses a nonreentrant write lock and persistent connection. The true handler is `edge/runtime/skill_executor.py:112`, not the older `edge/skill_executor.py`. Joint commands may queue, gripper commands write immediately, and all three backend loops advance actual physics. Exact pre-change lines and hashes are in Sol's API preflight and temporal-callsite-observations.json.

### New module and interfaces

`simulation_runtime/operational_lease.py` owns these opaque types and private registries:

- `OperationalLeaseSession`: one exact worker/repository/source policy registration, main thread identity, process/boot identity, broker thread/clock and epoch. No copy/pickle/public reconstruction. A module-private construction token and object-identity registry are required; matching strings/digests do not register objects.
- `LockedLeaseView`: actual transaction-issued handle, bound to concrete resolved DB/repository, owning thread, exact connection/transaction nonce, job/lease/worker/attempt, fencing generation, row revision, purpose, operation SHA and current row snapshot. Snapshot construction stays inside the concrete repository after BEGIN. A dictionary or caller-built view cannot be evaluated.
- `LeaseProposal` and `LeaseCommitAck`: single-use live handles; public receipts are detached evidence only. Proposal binds original acquisition/previous segment, new segment, exact CAS expectation and intended row digest. Ack is created only after the repository's actual successful commit, under the same publication guard, and confirms that exact proposal/row generation.
- `OperationalLeaseObservation`: detached versioned result with status/reasons, domain, original acquisition event, current segment event/deadline/current receipt and job/attempt/fence/source identity. It has no synthesized UTC validity interval and does not subclass the old UTC observation merely to pass its constructor. Stage A does not pass it through old P5 codecs.

Required callable interfaces (private means only actual lifecycle/registered repository can authorize it):

```python
_open_worker_lease_session(worker: SimulationWorker) -> OperationalLeaseSession
_worker_lease_scope(session: OperationalLeaseSession) -> ContextManager[None]
_close_worker_lease_session(session: OperationalLeaseSession, *, reason: str) -> None

OperationalLeaseSession.evaluate_locked(view: LockedLeaseView) -> OperationalLeaseObservation
OperationalLeaseSession.propose_locked(view: LockedLeaseView, *, ttl_ns: int) -> LeaseProposal
OperationalLeaseSession.confirm_committed(ack: LeaseCommitAck) -> OperationalLeaseObservation
OperationalLeaseSession.invalidate(reason: str) -> None

SQLiteSimulationJobRepository._operational_transaction(
    session: OperationalLeaseSession, *, job_id: str | None,
    purpose: str, operation_sha256: str
) -> ContextManager[LockedLeaseView]
SQLiteSimulationJobRepository.terminate_orphaned_operational_attempts() -> list[str]
```

Existing acquire/heartbeat/release/CAS public signatures remain compatible. The current worker scope resolves their private session; the real heartbeat thread receives a narrowly bound lease-session reference installed by `poll_once`, never a copied main-thread context or D_app clock. Repository detects operational rows independently of the caller's requested mode. If a caller lacks that live session it cannot renew/acquire/reattach an operational row by using a legacy method. Normal cancel/release/controlled termination may revoke without granting positive permission. Add the orphan-termination protocol method; retry remains a concrete SQLite API unless a genuine protocol consumer needs its declaration. InMemory job repository inherits this SQLite implementation; it is not an independent dictionary backend.

Both actual heartbeat producers are in scope: `poll_once.maintain_lease` and the main worker's `_run` delay loop. Register their exact live thread identities privately from this worker lifecycle; the main thread has its worker scope and the heartbeat closure installs a distinct narrowly bound heartbeat scope. Arbitrary callers possessing only a public repository/lease_id are rejected. Neither heartbeat producer reads the other's D_app clock. Add the new operational_lease source path to worker.py's actual VISUAL_WORKER_FACTORY_SOURCE_PATHS so the existing software source-copy factory and actual source pinning include it; do not silently refresh unrelated source hashes.

Private repository implementation helpers may be named to fit existing conventions, but must implement the concrete interfaces above. No generic plugin registry, alternate repository or new source tree. Test-only clock injection is private and must still use OC1's real owner/thread checks. It must not inject verdicts or replace transaction/view/CAS methods.

In CPU fixtures construct each raw identity inside the actual thread that opens that clock. `tests.test_operational_time_v1._identity` reads real PID/Python/native thread IDs; do not construct the broker identity in main and pass it across. Raw counter movement and CPU boot/namespace fields are explicit fixture inputs, not evidence of real suspend. Record both true thread IDs and exact original-domain references.

### Broker temporal contract

The broker creates, reads and closes its own original OC1 clock in its actual dedicated thread. Main D_app stays with the original worker thread. A broker request contains an exact registered view identity, operation kind and immutable policy, not a caller current time. Registry locks are released before queue/RPC waits. Broker never acquires repository, SQLite, event or physics locks and never calls back into the waiting repository.

Validate the actual requesting thread and its private lifecycle scope at RPC ingress before enqueue. The broker checks that registered request/view relationship, rather than pretending the broker itself is the view's transaction-owning thread. Only the broker reads D_lease; it never invokes an OC1 handle issued on the main thread.

Acquisition reads only **after** publication guard and BEGIN IMMEDIATE, then creates the first true acquisition event and hard-open lease segment. A queued acquisition timeout/abort cannot later produce an ACTIVE orphan. Heartbeat requires the previous segment still live, same real row/attempt/fence, no cancel/release/reassignment, and the frozen TTL policy. A legitimate heartbeat creates a new event/segment according to existing renewal policy. It cannot change original acquisition, task/verification/recovery origin, task timeout, limits/spend/retry, or manufacture a new attempt. At exact segment deadline the lease is expired. Late heartbeat and rollback do not resurrect it.

RPC failure wait cap is `min(1.0, max(0.05, frozen_lease_ttl_seconds / 3))` seconds, derived from existing heartbeat cadence and one-second worker join. Validate finite positive original TTL. This cap is conservative failure handling only, not an added successful-execution deadline or a future-wall guarantee. Timeout marks the request/proposal cancelled and session unusable; a late reply cannot activate it. Recheck the original broker domain on response consumption/confirmation. A delayed response beyond the original lease bound fails even if the queue wait itself did not time out. Do not translate either D domain into UTC or a shared minimum deadline.

### Registry and transaction state

View states are `OPEN -> DECIDED -> CONSUMED -> COMMITTED -> CLOSED`. Rollback, CAS rowcount !=1, connection error/close, scope exit without commit, wrong thread or duplicate consume causes `INVALIDATED`. Historical COMMITTED/CLOSED descriptions are not reusable views. Issuance checks actual transaction/connection and the repository's private active-txn registry; possession of publication_guard alone cannot issue a view. Purpose and operation digest cannot change after issuance.

Broker segment states are `PENDING -> ACTIVE -> REVOKED/EXPIRED`. SQL durable phase is a **different field/state machine**: `COMMITTED | REVOKED | TERMINATED`. Use one SQL transaction per successful acquisition/renewal/bind operation, followed by one broker acknowledgement; no second activation transaction or recursive commit-ack protocol:

1. Under publication guard and actual BEGIN, read the current row/revision and issue the private view. Broker fresh-read/proposal enters PENDING, binding the exact proposed generation and canonical target row whose durable_phase will be COMMITTED. Suspend positive use of the replaced generation while this proposal is unresolved.
2. Execute the real INSERT/CAS (rowcount1) writing the target receipt, generation, proposal_id, operation hash, row revision and `durable_phase=COMMITTED`; commit once. These bytes remain uncommitted until that actual commit returns successfully. On rollback/CAS0/commit ambiguity invalidate the view/proposal and fail closed.
3. Still holding publication guard, the concrete transaction owner records the successful commit and re-reads the committed row using that connection. It creates one private CommitAck bound to this real commit identity, proposal and canonical target-row digest. Read-only evidence/JSON or caller-supplied digest cannot mint an ack. Pass the exact registered ack to broker; broker performs its own fresh original-domain read and activates that exact generation only if the request/session remains live. For heartbeat/bind it rechecks the prior segment's original hard-open bound as well as the proposed segment; a commit that crossed the old expiry cannot renew retroactively. It does not acquire a database lock or query SQL itself.
4. Broker ACTIVE plus the exact SQL COMMITTED generation/digest/lifecycle is required for a positive evaluation. An SQL COMMITTED row with broker PENDING, absent, revoked or mismatched is unusable. Ack success changes only broker state, **not SQL**, and produces a detached audit receipt. Close the view/transaction handles after acknowledgement; their replay cannot authorize another operation.

Lost acknowledgement or late response leaves the committed row as nonauthorizing evidence and revokes/blocks that session. Subsequent safe release/orphan termination may write REVOKED/TERMINATED in its own cleanup transaction; this is not a second activation phase. A late reply never activates the blocked epoch. An old ACTIVE segment cannot authorize the new generation. Do not serialize broker ACTIVE as a durable live permission or infer it on restart.

Use an additive table owned by sqlite_repository (no new model/schema file): `simulation_operational_leases_v1`, keyed by lease_id, storing schema, job/run/worker/attempt, process/boot/start identity, epoch, generation, row revision, original job/policy digest, original acquisition receipt JSON, current segment receipt JSON, proposal_id, proposed row digest, durable_phase, terminal reason. The canonical target-row digest excludes only its own digest column; it includes the exact durable_phase/lifecycle and all original/segment/source/CAS fields. Broker state is not a durable authority column. Detached receipt fields contain both domain identity and integer-ns event bounds; bool/nonfinite/mixed-domain inputs reject. UTC columns remain legacy/diagnostic and continue the explicit stage-A extra veto; new D lease decisions never use them to create, renew or expire authority.

The table also stores lifecycle `ACQUIRED|ATTEMPT_BOUND|TERMINAL`; attempt is null only in ACQUIRED and must equal the actual unique open attempt in ATTEMPT_BOUND. This is not a budget-reset state machine.

All actual job writers participate in the same publication guard. In particular: acquire, heartbeat, release, expire, request_cancel, status CAS, retry, start/finish/finish_open_attempts; also job-associated append_event/save_metrics/save_artifacts and create_job/create_batch/initialization must not race the guarded state. For an operational row, each relevant mutation uses the single actual connection/transaction and generation/CAS rule; internal event append must not open a second writer transaction while the first holds BEGIN. Do not globally pretend the current `_connect` commits: it uses isolation_level=None and only rolls back on exception/closes. New transactions explicitly BEGIN/COMMIT/ROLLBACK. Preserve legacy row content/semantics and avoid unrelated SQL redesign. Internal `_..._unlocked` helpers may not become an external guard bypass.

A transaction keeps the job guard only for its finite row mutation. No lock covers model requests, broker shutdown, RESET, a complete skill, renderer or N-step loop. B will extend lock order to job guard -> job txn -> event lock/txn -> registry -> broker -> main app check. Never event -> job: Memory/event locks are nonreentrant.

### Termination and restart

Cancel/release/reassignment revoke the old generation under the same guard. Worker finally invalidates every live view/proposal, stops heartbeat, requests broker close in the broker thread, and joins using the existing one-second bound. Failure to join is recorded and remains fail-closed; revocation does not depend on a daemon returning. No thread may close/read the broker clock on its behalf. Keep e-stop reachability unchanged in A.

ArtifactRecoveryService calls `terminate_orphaned_operational_attempts` before ordinary expiry/requeue handling. It terminates old operational attempts when the previous process/boot/start identity is demonstrably gone or the same process's registered session has ended. A foreign still-live process that cannot be authenticated is UNKNOWN, not proof of orphanhood and not permission to overwrite its active work; safe cancellation remains possible. Terminal operational attempts cannot be requeued under the same job by recovery, retry_job or raw update_status_cas-to-QUEUED. Both manual-retry and recovery paths are tested. A genuinely authorized new job has a new identity and real new acquisition; same-job retry does not refill budgets. Legacy recovery policy remains as before. Real suspend and automatic same-boot resumption are not supported/qualified here.
