# R608 不可变审计边界数值拷贝优化

R604数据库缓存候选未展示收益，已恢复原产品并保留全部失败。本轮按实际Astra计划改为定位采集结果构造成不可变审计边界的纯CPU处理。只使用新合成的320×240 SensorFrame、76800深度float和76800实例int，不读原图/深度/原数据库，不构建或运行真实引擎/相机。

修改前执行固定3组、每组8次完整Boundary构造，另1次cProfile。直接通用deepcopy调用153639次；detach独占时间与其直接is_dataclass/deepcopy调用边累计时间之和，占profile总self时间约68.27%。计算排除了asdict调用者及递归detach的重叠累计时间，满足预注册的合成机制支持门；该profile不能归因原R595的624秒。

产品只在_operation_detach开头增加精确type身份判断：内置int/float不可变，直接返回原对象。bool、数值子类、NumPy标量、model_dump、自定义deepcopy及所有容器仍沿用原路径。去掉新增前缀后，整个模块AST与冻结原件完全相同。

原4项软件控制先通过；确定性RED证明原数值仍调用通用拷贝。20项新语义/反例与同4项控制合计24项通过，覆盖大整数、负零、NaN/无穷、bool/NumPy、子类hook/错误、可变嵌套及ndarray、dataclass字段顺序、模型属性访问、异常原件、非法边界先拒绝。前后Ruff均0诊断，diff检查通过；未重新跑全仓库，既有无关中文docstring基线问题不在本轮范围。

修改后按同一脚本和固定预算执行3×8+1次。三组未剖析墙钟从[932038268,925465561,943549039]ns变为[104433972,104509213,108831420]ns；中位数约932→105ms/8次，约8.92倍、下降88.79%。所有after批次低于所有before批次，CPU中位数也降低。profile直接deepcopy剩15次，输出/输入语义摘要前后一致。两阶段合计50个大合成边界；软件测试44次小边界启动、42次完成，差额是2个有意非法ID/kind拒绝；8个Python backend shell只服务既有纯软件控制。真实native、相机、解码、教师、模型/云端/硬件、原raw/DB访问均为0，13个其他输入及助手绑定未变。

结论仅为这段合成CPU路径的收益，不能乘以历史帧数推算节省量，不能声称完整仿真快8.9倍或已满足8秒墙钟。原身份遮挡、native资格及0/9分组仍待解决；下一实际验证必须另行绑定新来源并取得Astra计划，不能重用旧教师额度。交付仅产品小前缀、新测试及三个派生报告，完整本地材料不公开。
