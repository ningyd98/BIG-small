# B0 真实先导的原生 PRE 前置判断

依据 gpt-6.2-astra 的限定方案，在 `02e3bac9e478b8b329f25715cb5b2de6cc68a4dd` 核对应用源码。B0 先调用云端规划，随后由实际 OpenCV worker 进入原生 PRE。已知版本无条件将几何界与运动界置空，原验收会拒绝这个 PRE。现有应用来源 index 缺失，现有 reader 工厂即使拿到 index 也未接入这条执行路径。缺界前支付规划费用无法越过 PRE。

1. 用正常 `run_ced_pilot(..., execute=True)` 处理原六池和排除源，覆盖 selection 与 foundation。在隔离网络和不可接触凭据的哨兵服务下记录修复前两条完整未运行结果和凭据访问次数。另以原证据门用例复核实际边界。名义角色探针保持独立。
2. 使用已核查源码 SHA256 识别当前无条件生成双空界、且固定走 OPENCV 的 worker 实现。只在正常真实 selection/foundation 启动前返回 `B0_NATIVE_PRE_BOUNDS_UNAVAILABLE`。配置、原排除和六池检查照常。工厂在前置判断后才构建；已知实现不读取凭据、不创建真实 executor、不采图、不发送请求。未知源码 SHA 继续经过原全部实际门，SHA 本身不授予资格。保持 PRE 验证器、名义探针、干运行、power 及其他动作不变。
3. 通过原 `run_pilot_stage` 保留 480/120 条 `NOT_EXECUTED`、原分配、原因和零请求。验证可调用入口及 CLI 在已具备 DB 路径时均先拒绝；同时测试未知源码不绕过原角色门。保留修复前后回执和独立安全测试。
4. 真正放行仍需应用绑定的原始校准目录、可重建且运行时当前动作/时域有效的几何和运动界，以及原 PRE 对具体观察的 VALID。检查修改是否影响已经封存的名义角色探针来源。正式、独立、硬件及付费外部试次为零。
