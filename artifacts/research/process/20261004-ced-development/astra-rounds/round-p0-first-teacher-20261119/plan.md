# 零云教师首组的生产入口、独占窗口与独立读回

## 原始证据

- R595 v5 的首组实际 COLLECTION_PARTIAL，在 2040 个物理步采得 3389 帧/8821 次渲染，MOVE_ABOVE 的 POST 仍可见标记，颜色身份不唯一；约 624 秒超过原 8 秒 Shield 墙钟，0/8 动作准入，独立 reader 退出 0 但组未合格。v6/v7/v8 零释放。R675 仅验证两个全可见朝向；当前完整资格 0/9。
- 真实 CLI collect-once → NativeCollectionApplication.from_startup → execute_once，与 verify → reconstruct_native_full_horizon_registry → read_native_full_horizon_group 均有生产版本判定。v8 在应用启动前拒绝，完整组与 registry reader 也显式拒绝，遮挡 trace 的局部 reader 仅作过程回读。

## 实施范围与假设

- 先并行于归档轮定位三处差距。在 R603 原 PRE/POST 几何依据上检验前景遮挡、同色候选与当前帧证据；基于 R613/R615/R616 分离渲染、复制、编码/同步落盘、实际墙钟。用新且有界的零模型 MuJoCo/EGL 片段测量当前生产路径，包括一段实际遮挡、实际姿态/当前帧、原采样密度、每帧原件及其 hash、真实单调钟和主机负载。记录最近可用的成本与能节省的具体部分；未经归因不得将 1801 时限与教师墙钟合并为同根因。
- 最小发行范围为新增版本及新种子组；沿用现有 v8 的已验证遮挡处理/原控制器。只在实际区别需要时增加版本判定；必须贯通 CLI 配方、真实工厂来源/一次性 claim、执行器各 PRE/POST、实际冻结 source/asset、序列原件、独立完整组和 registry reader。保留旧 v5 预算与 v6/v7/v8 按原版本拒绝。不要用复制旧 attempt、换 ID、仅改配置、手造行或 partial reader 替代新运行。对可证实的软件缺陷按其真实原因出窄 Astra 方案再修；观察不唯一、缺像素或时限用尽时保留拒绝。
- 用正常 CLI 在新目录准备新协议；首个 release 必须从九组全新预分配清单中唯一指定一组。先证实正常入口的有界集成正例与拒绝例可读，再冻结源码/环境/协议并在专用窗口跑 collect-once 一次，独立进程 verify 原件一次。记录 claim、父子进程退出、原件清单、租约、清退、资源峰值和零云计数；部分/拒绝仍应读取、报告并停止扩组。

## 运行前置

- 安排一个本机 GPU/EGL 独占窗口（有界诊断→单组→reader），与并行长测、模型运行错开；开始前登记实际时间、设备/驱动、负载、存储空间、捕获成本、目录、进程归属、合理 watchdog 和清退方案。使用零云/无需任务模型的教师和原传感器/控制器。保留现有 5 秒帧时效、8 秒 Shield、可观测性、作用时间、租约/安全及全部采集原件。独立窗口结束条件是取得当次终态与独立 reader 判定。若实测窗口或原件能力不足，保留具体差距，并先完成能独立推进的软件或诊断工作。

## 验收

- 负控覆盖过期/伪造协议、错组/旧组、重复 claim、源替换、遮挡不成立、多身份、过期观测、超时、缺动作/原件及 partial reader。完整正例必须真实包含八个动作的原时域、每阶段来源/时钟、可观测几何、接触/抓放/安全/终态，独立 reader 重新构造。首组只是九组之一；其组级 source/horizon 及原验收通过后方扩至其余独立组。九组完整、保守联合界有限且 ≤10 mm 等既有条件满足后再报告资格。每次新增根因或计划外失败记录原件、发 Astra，禁止消费旧轮剩余额度。

各输入的工作树路径与 SHA256 见同目录 plan.json。
