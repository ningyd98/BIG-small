# grid‑04 中段减速机械预检

- 采用同场景、同种子、同夹持入态及原 0.160 m 世界高度。候选参考的首个变化网格点是 1935。原相机、光学门、1 mm 路径约束、100 ms 时限、HOLD 与 240 步制停规则仍由原登记约束。
- 一次原生 reset。原轨重演闭合 78 个归档曝光状态、355 条接受命令，以及 LIFT 入口 1520 至原拒绝 2112 的 592 个实际驱动。原 PRE 与首 FEEDBACK 的空间净空最小值分别为 12.067 和 11.912 mm。9 个入口制停延迟的最小逐对与逐体余量分别为 0.749 和 0.750 mm。
- 1744 原 CLEAR 的延迟 3 步在旧世界边界下仍欠覆盖 1.906875 µm。新包络在该窗下最小余量为 +0.500 mm。对共帧重算了扩大后源台包络的光学体积和净空。历史 2112 的近面拒绝保留。
- 源台例外在共同前缀的 1864 依冻结光学规则永久退出。1935 首次改变已接受命令和驱动，1936 首次改变积分状态且没有对应的新曝光。分岔后按通用档检查，815 个窗／延迟对的最小世界余量 0.0580 mm，相对余量 0.3749 mm。这些数值只描述无图原生机械预检。
- 候选在 2002 首次抬高工件 50 mm，以 100.175 mm 的工件净升和 159.996 mm 的 TCP 世界高度走到参考终点 2660。最大工件净升 100.327 mm，TCP 最大侧移 0.97043 mm。保持闭指。141 个普通窗完整覆盖延迟 0–8。尾窗 2656 仅覆盖 0–4，未推到返回、保持或 POST。
- 320 个相同触发制停记录经校验复用，另生成 821 个原生制停。共 1274 个普通窗／延迟对和 9 个入口延迟，两进程独立重算逐一一致。开工前一次交接体积包装误用了预扩张框，修正在 reset 前完成。第一次冷读的 Python 元组与 JSON 数组比较失败，规范化后重跑冷读。两项初始拒绝均保留，修正后没有额外积分或采图。
- 200292 个 CPU 积分步。其中 2112 步原基准、1140 步候选、821×240 步停止分支。现场、EGL、新 RGB-D、正式仿真、独立正式评分、硬件、远程调用均为零。

散列和逐次读回回执见同目录 `midcourse-qualification.public.json`。原始命令、状态、接触和制停文件由私有目录 `experiments/results/g1-grid04-refit-midcourse-qualification-20261126` 托管。两个冷读进程对同一原生状态分别重算，未重新积分。
