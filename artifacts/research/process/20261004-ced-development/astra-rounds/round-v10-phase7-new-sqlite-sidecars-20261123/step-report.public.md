# 正式目录旁文件复原

阶段内的一次 SQLite `mode=ro` 表结构查询在冻结库旁生成了 WAL 和 SHM。Phase 6 记录显示，查询前正式输出仅有数据库和当时的发布锁，数据库 SHA256 为 `09fab63b235ab3317f27b2528aea724015629863fff287496cb45430d23f4b1a`。[复原计划](plan.md)

在主机进程命名空间三次使用 `fuser` 核对数据库、发布锁和两件旁文件，均无占用。按计划逐件核对设备、inode、硬链接数、生成时间、修改时间、长度与 SHA256，使用同一文件系统的无覆盖重命名将查询新建的 0 字节 WAL 和 32,768 字节 SHM 完整保存在本轮私有证据目录。

复核确认正式顶层恢复为查询前的七个条目。原数据库、历史发布锁、登记、claim 和正式原件清单的校验和一致。两个旁文件保留了原 inode、修改时间和内容，移动反映在旁文件的 ctime 与目录时间上。最终 SQL 核对使用数据库的私有冷副本。此操作产生 0 次仿真和 0 个正式 claim。[阶段总结](../round-v10-phase7-20261123/stage-summary.public.md)
