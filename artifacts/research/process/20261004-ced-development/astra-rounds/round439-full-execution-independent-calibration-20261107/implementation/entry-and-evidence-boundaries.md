# 完整执行入口与独立校准的交付边界

本轮实现三种互斥入口：`scripts/collect_native_calibration.py --prepare-only` 冻结协议，`--collect-once` 消耗一个已放行的采集分组，`--verify` 从原始记录独立读出。协议与采集目录必须新建；历史原件不覆盖，失败不自动重试。

完整执行入口连接真实 worker、owner、guard 与 MuJoCo backend；八个动作保留登记的完整时长，提前达到目标后继续保持原目标，失败立即保留部分来源。登记时间步为 1/240 秒，120 步稳定期与 12,840 步动作共 12,960 步。LIFT 与 RELEASE 的既有尾部等待计入登记预算。代码中的 SOFTWARE_ONLY 回归用软件模型和相机替换底层效果，不能当作实际物理运行。

独立读出核对冻结输入和源码代次、原帧及字节库存、命令到控制的效果重放、逐步物理关联、原始操作顺序、guard 检查与真实 hold/STOP 终止链。UTC 追踪按已保存的实际评价时刻重放；没有证据的旧时钟映射仍为 UNAVAILABLE。已返回的 render pass 在持久化前计数；中途未完整返回时保留计数下界与未知精度。

当前只登记首组 `native-r439-0001`、seed 439001 的一次实际采集资格。其余八组保持 NOT_RUN；缺失组保留在校准分母中。开发采集的 teacher 标签和成功软件测试均不授予 native 资格。缺少完整、合格的独立证据时，native 保持 UNKNOWN、正式研究验收保持 NOT_ACCEPTED。

后续执行采用本目录 `run_stage_r453.py` 的 `prepare`、`first-full`、`independent-read` 三个阶段及冻结命令。文件名沿用建立时的 R453 名称，最终 source overlay 汇入后续获准修复。该 runner 要求完成 scoped review、精确源码 overlay 和新协议；实际采集还要求 R450 的显式服务授权及现场前置条件。不得手工将占位或待授权记录改写为已通过。

R450 等待用户授权临时停止占用 GPU 的独立服务，并在唯一采集子进程退出、回收后立即恢复。无授权时允许交付软件、报告与准备好的协议，实际采集和其独立读出保持 NOT_RUN。停止服务不是本轮开发代码自动获得的权限。

推送范围为批准的源码、测试、计划、失败记录、有限验证日志及派生报告。完整批量 raw、运行数据库、凭据、模型权重和 SDK 继续按既有边界留在本地；源码与清单不构成完整远端实验复现包。最终状态与验证结果以同目录最终阶段报告为准。
