# OC1 Linux 检查与冻结帧重复率先导

CPU 先导使用生产 `open_operational_clock`、Linux BOOTTIME、有效 origin token 和 deadline。每个测量样本执行一次 `read_current` 再执行 `before_deadline`，实际覆盖九次 `_check`。无 EGL、模型、动作或新增真实试次。 [复现脚本](oc1-prestudy.py) [原始计数和环境](oc1-prestudy.public.json)

| 分项 | 每复合检查 | 样本及口径 |
| --- | ---: | --- |
| `_check` | 838.18 µs | 150 个复合检查，各九次，含 identity 和验证 |
| Linux identity | 783.01 µs | 同组，含原读取、解析和对象构造 |
| boot_id、进程 stat、timens_offsets 的打开/读取/关闭及 namespace stat | 621.69 µs | 三种独立文件读取和一次 stat，各九次 |
| 进程 stat 解析 | 23.31 µs | 同组，仍需每次解析 |
| offsets 解析 | 24.97 µs | 同组含探针，保留解析器的正常校验 |
| identity 对象校验 | 23.91 µs | 同组，包含 `_validate_identity` |
| boot UUID 与 offsets 纯文本解析重放 | 24.33 µs | 各用刚读入的真实文本重放 1,350 次，含探针 |

分项测量用两次独立的生产 owner 运行，各完成同量设置和收尾，计数差分为 150 个复合检查。时间差分会受两次进程观察路径及探针影响，表中包含的分项不可相加。Linux identity 减去列出的文件读取、两处在线解析及 boot 纯重放后，余约 99.87 µs/复合检查，包含 uname、线程标识、对象构造、探针和差分噪声。未独立归因于单一操作。

无探针配对按 AB、BA、BA、AB，每臂 150 次。A 使用生产 identity。B 仍按原顺序新读每个文件、stat namespace、解析当次进程 stat、构造当次 identity。只有本次 boot_id 或 offsets 原始文本与启动前刚采的对应文本精确相等时，B 重用相应不可变解析结果。其他内容走原解析。8 例控制覆盖合法等值文本、有效身份改变、坏文本、缺失进程 stat 和中途 offsets 读取失败，并比较返回值或异常及文本读取顺序。整个先导只在测试进程替换方法，未改生产文件。

四个配对的节省为 29.85、136.66、102.74、63.83 µs/复合检查，中位 83.28 µs。将这个中位乘历史 31,238 次为 2.60 秒，配对范围折算为 0.93–4.27 秒。仅以 boot UUID 与 offsets 的纯文本重放算术估计，全部省掉约节省 0.76 秒；这是该样本的解析开销预算，配对差额另含噪声、平台状态和原型实现差异。保留的新鲜文件读取和 namespace stat 折算约 19.42 秒，单独已超过 8 秒。上述折算依赖历史检查次数和可迁移成本，实际候选动作时间由真实新试次判定。

历史冻结 inventory 使用数值 acquisition ID 排序，共 3,385 帧。RGB 有 1,147 个唯一 PNG 摘要，3,384 个相邻位置中 2,237 次相等，约 66.11%。深度摘要 3,385 个均不同。摘要相等只界定历史同字节 RGB 复用机会，当前 RGB 仍须读取并绑定当前身份后判断，深度、实例、标定及时间身份仍各自处理。只取消 RGB 重编码时，上一真跑全 RawV3 编码 11.299 秒是极宽的历史算术预算，包含深度和模型验证。实际 RGB 节省须按窗口内 RGB 编码单独计时和逐文件等值读回。与 OC1 小改叠加的量级无法说明 8 秒可达。

首轮脚本对累积计数差分重复计入预备调用，九次检查断言提前停止。清空计数器后运行两组差分，检查、identity 及各叶读取计数一致，Ruff 通过。
