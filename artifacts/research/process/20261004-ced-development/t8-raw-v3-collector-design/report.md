# CED raw-v3 collector and clock: read-only incremental design

This is DESIGN_ONLY. It inspects the genuine CED collector, visual worker, simulator taps and offline teacher; it edits no production file and performs no collection, render, simulator state/step, controller action or model/provider call. The independently reviewed risk numerical fix2 is the current RAW consistency prerequisite (`4ed1a5a571cfca7d43a77ca79c86964ec08da887e87663031df55078cbfac552`, independent113 passed/2 pre-existing dynamics tests deselected). Existing raw-v2, marker raw-v1, their source manifests and the historical scope erratum remain unchanged. Actual INITIAL, calibrated motion/geometry, risk labels/selection, METHOD and executor/owner admission remain unavailable.

The smallest first code task is **two new files only: `research/raw_episode_v3.py` and `tests/test_raw_episode_v3.py`**. They define immutable strict records and pure structural/coverage validation. They do not sample clocks, open a simulator, install callbacks, write datasets, expose an acceptance flag or change the current risk reader. Later root-owned integration must record these fields at the real boundaries. A supplied valid-looking record or a passing pure validator is source-consistency software evidence, not an authentic clock certificate or execution authority.

## Stable proposed pure interface

Strict public constructors and `from_payload` must revalidate concrete nested types, reject bool-as-number, oversized/nonfinite numerics, naive UTC, duplicate JSON keys, unknown fields, placeholder IDs, cross-epoch aliases and mutated model_copy input. Freeze full policy/plan payloads as canonical bytes or use reviewed `OriginalActionRequirements` plus `VisualOriginalPlan` interfaces, returning detached serialization. Hash meanings remain separate: original source-file bytes, record canonical content and model/role/plan/checkpoint identities.

## Complete joins and clock support

Use integer step and command sequence identities, not rounded sim_time as the primary join. In the current backend, a pre-step actuator row for n contains state n−1 and control used by the transition to n; the following physical row is state n. Start/end indices and `(n0,n1]` are therefore deliberately different from half-open command ranges. Multiple command rows at step n remain ordered by command_seq, even if only the last target affects a later step. No effective command is dropped to make a span look coherent.

Every physics step is covered by an explicit purpose interval. Settle120 precedes evaluated actions; request waits, safety/verification reobservations, post-lift hold and shutdown/safe-stop traces are separate. Delayed targets may affect a later span: join them to original dispatch and actual control rows without moving their command ownership. Zero-step rejected executor attempts remain in the denominator. A partial action or missing after-frame stays incomplete, with the original attempt and available commands/steps preserved.

At a genuine stamp, sample `mono_before_ns`, aware UTC, `mono_after_ns` on the same owner clock domain and bind the sampler's current source. With UTC expressed in nanoseconds, the observed offset is bracketed by `[UTC−mono_after, UTC−mono_before]`, expanded only by a separately sourced UTC uncertainty when available. These brackets are observations, not authenticated oscillator calibration. Clock rollback/jump, domain change, nonmonotonic sequence, excessive acquisition/stamp uncertainty or absent source produces an explicit unavailable mapping. Monotonic order can remain useful within a single registered run even when UTC correspondence is unavailable; cross-process/restart timestamps are never compared without an independently registered domain bridge.

At backend integration, sample actual physics start immediately before mj_step and end immediately after it, excluding a misleading assumption that the pre-actuator callback time equals the numerical step boundary. Record readback/observer/acquisition latency separately. Pair command dispatch where it happens and acquisition start/end at camera render boundaries. For an action, pair entry just before the existing execute_attempt and pair return/exception in finally immediately after it; acquisition after return is a new interval. File serialization/flush duration is not silently included in a physics timestamp or claimed as simulator time.

A complete measured interval graph can support each recorded state, frame and action against actual wall intervals, including bursty unpaced actions and waits. It **does not prove a unique continuous mapping inside a numerical step**, nor a continuous wall-time geometric/angular velocity bound. Never interpolate endpoints, divide sim time by the whole episode duration, treat small endpoint displacement as a maximum-motion proof, or assume1sim-second=1wall-second outside a separately declared controlled clock. A future risk/T10 motion certificate still needs its own whole-geometry/motion/error/time-domain contract and genuine measurements; raw-v3 only preserves the evidence needed to evaluate that prerequisite.

## Ownership and bounded sequence

1. Delegate the two new pure schema/coverage files. Qualified missing-module RED then strict constructor, aliases, malformed/oversized numeric, cross-domain, index/range/frame joins and complete denominator GREEN. No actual clock/source positive fixture.
2. Root reviews the pure interface, then explicitly owns backend opt-in raw tap, camera acquisition hook, `_VisualEpisode`/ExecutionPolicy optional sink and sole existing SkillExecutor attempt boundaries. Default no-sink behavior and hard-stop/native/pre-Safety/pre-Skill ordering stay unchanged. A collector cannot accept a provider receipt as a real start, finish or frame. Guard read-only callbacks as current taps do; no reset/control/step/contract mutation or arbitrary thread activity from a callback. Sampling/recording failures stop collection and preserve partial evidence; they do not produce a successful episode by omitting rows.
3. A later two-new-file writer task (`research/raw_episode_v3_writer.py` and its tests) can stream append-only originals into a newly created attempt directory and close a full hash inventory. Root then integrates the CED CLI/headless entry. Use exclusive creation, explicit flush/durability policy, immutable terminal manifest and a separate failed/aborted record on writer failure; no automatic replay/resume of uncertain actions. Do not rewrite an existing raw-v2/v1 directory or label historical missing-clock rows v3.
4. After another freeze/review, a separate new v3 source auditor consumes owner-allowlisted roots, exact schema/source/role/assets and full original inventories. It can reuse corrected immutable RAW control/geometry logic only under an explicit reviewed adapter contract, not edit fix2's layout allowlist while collecting. Risk supervision/clock/billing/INITIAL and formal source acceptance remain separate concrete auditors. New code alters stage_source_paths/current source identities; freeze it before genuine collection, and never grant an old INITIAL's role/source bindings automatic admission.
