# T9 source supervision and finite-candidate replay: bounded next design

This is DESIGN_ONLY, based on the immutable RAW reader release `b8eedda6ef991631a175d8a9c0ee71c4f61e514a0b2a45f9ea92c50475b4cbe8`. No production/default risk/CLI/admission/collector file is edited, no model is fitted, and no capture/provider/account is accessed. RAW reconstruction is distinct from risk acceptance: current risk supervision remains UNKNOWN and actual calibration/METHOD remain NOT_RUN. The RAW reader is awaiting independent review; this design does not upgrade its verdict.

While this design was being written, independent review reported RAW consistency counterexamples for hold targets/current q, actuator gain/source basis, marker commands without action ranges, post-reset geometry size and actuator unknown-field/boolean coercion. The historical RAW package remains frozen and these findings take repair/re-review priority. A subsequent supervision implementation must consume a corrected independently reviewed RAW reader; the current snapshot is only the exact API/code inspection basis here.

The next independent modules are **risk_supervision.py + its dedicated tests**, then **risk_replay.py + its dedicated tests** after their source-view schema freezes. The first module reconstructs labels, source eligibility and original denominators. The second reconstructs candidate fitting/calibration/prediction and selection. They consume trusted server registrations; serialized receipts, supplied probabilities, file booleans or arbitrarily supplied VALID callbacks cannot provide actual authority.

## Source view and exact first owner API

Proposed `RiskSupervisionAuditor(registrations).audit(evidence_id) -> RiskSupervisionAudit`. A registration fixes a RiskSourceRegistration (the complete original RAW registry), genuine registered INITIAL evidence ID/auditor, original allocation/use-history/connected split inventories, the intended label/prediction horizon, actual role/policy/common-source domain, estimator registration, calibration measurement registration, clock registration and derived-dataset originals. Registrations are application-owned copies, not loaded wholesale from caller YAML or a self-declared accepted manifest.

The auditor calls the registered RAW reader and the existing concrete INITIAL source auditor, then independently rereads the same original inventory. It reconstructs offline risk labels and features from registered source paths. It must not access `RiskSourceAuditor._registrations` or infer truth from only its outcome summary. Its own registration carries the exact immutable source registrations/relative inventories necessary for the raw reread. Before/after original/current-source hashes must still agree. A consumer takes an evidence ID and reruns the auditor; an in-memory or persisted result saying VALID is not a reusable permission token.

`RiskSupervisionAudit` returns typed status/reasons, original allocation/attempt/source histories, eligible/missing labels and counts, full partition and ancestor identities, reconstructed records/features/labels, and source/INITIAL/role/asset/calibration/clock digests. It has no method/execution admission. Its scope can become conditionally valid only after **all actual required raw measurements** exist and recompute. At present all required measurement/source registries are absent, so a truthful implementation returns UNKNOWN with diagnostics, not a synthetic actual positive.

A root-owned current-source registration should freeze the new reader/replay program versions before the first genuine INITIAL collection. INITIAL can bind code without already containing the later fitted weights/calibrator/winner. Risk fitting changes output artifacts, not the frozen source program. If implementation/source/asset/common roles change after INITIAL, the affected source stage must be newly frozen/revalidated; do not edit an old INITIAL document or relax current-source checking to avoid this requirement.

INITIAL keeps its **baseline** RoleRuntimeBinding. A later METHOD registration has its own explicit stage/capability basis, while comparing the fixed common cloud model/settings, CV/controller/Safety and source domains with the INITIAL baseline. Risk source verification must not accidentally demand a future JOINT edge-policy hash from the original B0 capture or require its own completed weight winner. Neither the current baseline capability set nor method capabilities are changed in this design.

## Source label definition and missing-data rules

Before collection, freeze `risk.label-definition.v2` with:

* The task-level failure horizon relative to an original observation/decision, the assigned deadline/time domain, completion/safety evaluator/version and terminal status semantics. Complete raw task failure/safety must be recomputed with source-bound criteria. Skill return, provider confidence or a caller-written failure bool is insufficient. An incomplete physical trace is an unavailable label, even though that assignment remains a failure/UNKNOWN in the research denominator.
* Decision-action-specific outcomes and their horizon/endpoint. A CONTINUE decision must join its actual started contract/skill/command interval; it is not inferred from the teacher primitive name. REOBSERVE requires an actual new acquisition transition. REQUEST_CLOUD requires original local/provider request identity, response/provenance and the subsequently started plan/action or a preserved failed attempt. STOP requires explicit registered termination semantics and cannot falsely claim actuator execution. LOCAL_RECOVER requires a verified real lifecycle and matched development action feedback; otherwise it remains None. No unchosen action receives a counterfactual success/failure label.
* Registered geometric estimator, coordinate frame, units, target identity/offset and exactly which geometric scope the scalar residual covers. The estimator is replayed using only the actual online inputs it originally received (including original ROI/visual provider outputs if applicable). Independently reconstructed simulator geometry is used only offline for the label. Marker center, color bounding-box/depth target, grasp offset and object extent are distinct scopes; a center error cannot certify all of them.
* Original allocations and safe capture cadence, with every assigned attempt and every scheduled observation/action retained. Missing/cancelled/blocked/timeout/unsupported/out-of-domain rows keep reasons and counts. Define any eligible fitting/calibration population before seeing outcomes. Candidates cannot select their own favorable surviving prediction subsets; apparent probability/coverage is conditional on that declared population and must show the complete allocation denominator beside it.

The current one actual motion example is development-only and has nine post-action UNKNOWN observations. It supplies a real RAW reader regression seam, not an actual complete risk label population or measured bound. Do not fill those residuals with zero or use offline truth-projected occlusion output as an online estimator input.

## Calibration feature and clock are independent actual prerequisites

Current `extract_risk_features(observation, previous, calibration_residuals)` uses the provided residual sequence as an online feature. A calibration registration must bind original calibration target/measurement data, frame/intrinsics/extrinsics/depth convention, fit-only calibration procedure/current source and camera/asset/time domain. The auditor recomputes those residuals from independent calibration measurements. A current sample's true geometric error, failure label or future outcome must never generate its calibration feature. Version strings or a model's 48-bit floating calibration fingerprint do not attest that measurement source.

The current motion proxy divides depth-ray difference by **UTC captured_at wall acquisition interval**. Raw object velocity/time is in **simulation seconds**, while T10 evidence age/expected action timing uses wall time. Existing raw-v2 has physics_dt_s but no complete per-step wall/simulation mapping. Neither frame endpoints nor a caller rate multiplier supplies that mapping.

The collector/clock owner must independently persist monotonic step/acquisition/action timestamps and the authoritative simulation↔wall mapping/uncertainty used by the online timing policy. A registered controlled-clock alternative would require a separately versioned feature/T10 timing contract, not an implicit equality assumption. The source reader verifies complete window coverage, monotonicity/order, exact frame-step association and declared time domain. Missing mapping, zero/negative interval, burst advancement without sufficient timing basis, stale crop/frame, lateral/occluded target or missing geometry association leaves motion UNKNOWN.

A measured residual must compare quantities in the same registered time domain over the **full action-validity horizon**, not only between endpoints. Its registered physical entity/geometry displacement scope must include whatever the consumer needs; unsupported angular stability, obstacle/whole-object motion and hidden intervals remain UNKNOWN. No residual floor, guessed speed or new numerical threshold is introduced here. The existing depth motion feature is preserved until a deliberate new version is approved.

## Committed data and split usage

Current `SampleRecord.labels` and `labels.json` are bound to original committed content hashes. Therefore an auditor cannot simply add independently reconstructed `risk_supervision` to the in-memory labels and pass that record to `load_offline_observation`: it would no longer describe the committed source. There are two explicit outputs, with no historical byte rewriting:

1. A read-only reconstructed source view used for diagnostics and verification.
2. A **new derived committed risk-dataset version**, produced by a separately owned materializer/collector, retaining original camera/scene/state/ancestor references and group components, with correctly hashed risk labels/feedback/COMMIT/source/split records. Only this source-verified new version can feed the unchanged Sequence[SampleRecord] fit/calibration interface. `execution_verified=False` stays unchanged; execution claims live in independently verified label/action sources.

The original fixed split algorithm is source-content-local-rgbd-v1 with independent connected-component allocation80/5/5/10. Regenerate full committed splits and compare exact sample/role manifests; join group, physical+asset canonical source, episode, physics state, raw action/ancestor frame, content and perceptual duplicates. Frame/viewpoint/corruption derivatives stay in the same component. Train fits only; calibration calibrates only; selection chooses finite parameters; test evaluates the frozen result only.

Root clarified the exclusion interpretation after the earlier design: **authorized development feedback explicitly assigned to train may be reused for train**, preserving component/usage history and excluding it from formal/power/G3/G4. Historically viewed or tuned samples cannot be renamed independent calibration/selection/test. Apply each frozen protocol's exclusions to its actual source purpose rather than blanket-disabling all train data. Unknown use history is UNKNOWN. Risk parameter selection, B0 period selection and JOINT weight selection are separately bound purposes; each original history is checked. This clarifies the earlier broad “compare exclusions” language without changing any frozen inventory or reopening formal pools.

## Exact finite-candidate replay

Proposed `RiskArtifactAuditor(registrations, supervision_auditor).audit(evidence_id) -> RiskArtifactAudit`. A registration binds the complete preregistered candidate parameter objects and canonical hashes, recipe/source/library versions, source evidence ID, original model/calibration files and selection results/winner. Parameters consist of the current method, seed and SETTINGS; enabled/source-status fields are not selectable scientific parameters. Current config admits only the frozen settings; enlarging the grid requires a new versioned candidate inventory, not a hidden CLI override.

For every candidate, replay this exact flow:

1. Reconstruct original online-only RiskFeatures using the verified sensor/calibration source. Retain the full source/split/group and missingness view.
2. Call the existing source-bound train-only logistic/action fitting recipe with fixed seed/ordering/settings; normalization, coefficients, ranges, feature schema, calibration fingerprint set, fit groups/provenance and action model training sources must match. Fitting may use an isolated temporary artifact directory for existing APIs; it never overwrites the original committed model, dataset or report. No model service/GPU/renderer is involved.
3. Replay `calibrate_risk` from disjoint calibration-only records: raw predictions via `fit.predict`, global/action isotonic blocks, support/ranges, per-group maximum geometric and eligible fresh-motion residuals, current rank `ceil((g+1)*0.9)` and complete group/provenance/output digest. Current calibration filename/content/model hash binding remains exact. Geometry and motion eligibility/group counts are reported separately; missing rows are not full coverage. Under the existing rule a finite bound needs at least nine independently labelled groups of the corresponding kind. Missing action/both-class feedback remains None.
4. Reconstruct selection features and **calibrated** probabilities, using `isotonic_predict(calibrated['isotonic_blocks'], predict(data, features))` with current observable guards/support. Action predictions use `action_isotonic_blocks[action]` and the matched `action_models[action]`; final translational bound is `observed_motion_m_s + motion_residual_bound_m_s`. Do not use raw sigmoid values when the recorded field purports to be the final calibrated failure probability. Reject supplied predictions that differ from replay. Existing default `estimate_risk` stays closed on source_accepted=False; its flag is not flipped to obtain selection authority. Numerical prediction and actual-source eligibility are evaluated separately.
5. On the identical preregistered eligible selection population, recompute each Brier mean and choose current minimum-Brier-then-parameters-hash winner. Candidate IDs/objects/rows must be complete and exact. A missing required prediction makes selection incomplete rather than allowing a lower score over fewer rows. Compare original selected parameters/model/calibrator/predictions/scores/winner; the current `verify_selection_snapshot` supplied-probability check alone is insufficient.
6. Compare canonical artifacts under the frozen recipe and library/runtime versions. Default comparison is exact deterministic reproduction under the pinned environment. Cross-platform floating differences require a separately justified predeclared version/tolerance contract; do not silently widen tolerances after a failure. Reliability/coverage plots on calibration are labelled calibration diagnostics; test performs independent diagnostics without changing the winner/actions.

Existing APIs write `source_accepted=False` for preparation, while the old CLI may publish True after legacy summary checks. Neither bit becomes the replay authority. A verified artifact source view binds the rebuilt numeric artifact to actual originals separately. A later `VerifiedRiskEstimator` can derive a RiskEstimate from reread validated source/replay and current observable inputs; it must not mutate a model file to True or consume a persisted VALID receipt. Default fit/calibration/CLI/estimate/admission remain unchanged in the proposed two new replay files.

Keep digest meanings exact: RiskModelArtifact.model_hash is the canonical content_digest of the model data, not simply SHA256 of its newline-terminated file bytes. Independently bind the raw file SHA as well. Calibration's content_hash is computed before adding that field, binds model_hash, and must reproduce its `calibration-{content_hash}.json` filename. Preserve separately the source-registration digest, candidate parameters hash and raw artifact bytes; none can replace another.

## Planned RED matrix

Supervision: supplied rehashed labels/outcome/probe/source-status; incomplete reset/actuator/action/frame/raw allocations; task horizon/deadline mismatch; global failure inferred from perception status; missing/unstarted/duplicated action feedback; true error/future fault injected into online calibration/features; wrong coordinate/marker-offset/whole-geometry scope; missing/invalid wall↔sim mapping or mid-action motion; stale crop/acquisition; missing FIRST/INITIAL/billing/basic certificates; altered original/derived commits; hidden usage history; source connected-component leakage and wrongly relabelled independent holdouts.

Replay: candidate parameters hash without full object; incomplete/added candidate inventory; fabricated but Brier-consistent probabilities; raw-sigmoid vs calibrated probability substitution; train/calibration source crossover; absent/one-class action estimates; missing group residuals/fewer than nine independent groups/duplicated frames; out-of-domain prediction or favorable surviving subset; test-driven winner/threshold; incorrect coefficients/normalization/isotonic/group rank/filename digest; wrong deterministic tie-break; source_accepted rehash or receipt-based permit; source/role/asset/clock drift between audit and consumption.

Synthetic fixtures verify exact algorithm/source boundary math only, always SOFTWARE_ONLY. Tests with the actual excluded motion original can verify unavailable observations/source counts and RAW consistency, but do not mint complete risk positives. Actual risk supervision, fitting/selection, calibration, INITIAL/METHOD and formal results remain unavailable until their own original required sources exist.
