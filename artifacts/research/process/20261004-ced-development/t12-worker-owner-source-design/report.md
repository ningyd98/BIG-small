# Actual visual worker owner registration: incremental integration design

Scope: DESIGN_ONLY. This inspects existing real worker/visual boundaries and the reviewed pure owner module. It does not register a live owner, change an executor, modify production code, run a simulator, capture images or call a model. The five-file durable repository implementation is still undergoing its own verification; integration must wait for that frozen independent review. INITIAL/METHOD and native geometry/motion admission remain unavailable.

The headless visual worker currently passes only a LEGACY ExecutionPolicy, cancellation and an output directory. It owns the simulator lifetime and publishes historical episode records after shutdown. That publication is not a current owner source. The next integration must publish coherent original contract, checkpoint, budgets and current grounding at the actual live boundaries, retaining the existing SkillExecutor/SafetyShield/native guards.

## Genuine identity and source factory

Worker `_execute` obtains a lease-bound job and calls `start_attempt`, but subsequently passes its earlier job object to `_run`. That object can still have the previous attempt number. A factory must reread the concrete simulation repository, join the returned/current open attempt to the same worker/lease/job/run and verify the live running lease; it cannot copy `job.attempt` blindly or invent attempt1. Use the actual lease and attempt to derive a unique owner epoch. The actual capture supplies episode identity and the compiled contract supplies task identity. TaskContract and RobotState do not supply plan_id or robot_id: the factory must assign one immutable local plan identity at original registration and explicitly register the actual backend instance/resource identity and lifetime. An asset digest alone is not a physical device ID; simulation identity must remain labelled simulation. No placeholder robot, expired lease or stale attempt is accepted.

The worker's `_active_job_cancelled` already rechecks job, lease, heartbeat and cancellation. Keep that authoritative check immediately before and after any source publication and existing dispatch boundary. Event-repository initialization is atomic only inside its own domain; it is not atomic with the simulation job or separate auto-mode database. Loss of the lease or a failed publication stops the visual run and preserves partial evidence. A source publication alone grants no METHOD, execution or physical-completion authority.

An optional factory must be constructed by the concrete worker owner from actual repositories and explicit RoleRuntimeBinding. The default LEGACY worker remains unchanged. A LEGACY model digest cannot be renamed a role-bundle hash, and arbitrary callbacks/results claiming ACTUAL_SOURCE cannot supply the missing binding. If no explicit qualified role binding exists, the new path is unavailable before invoking a provider. Role/source registration must be frozen before genuine INITIAL collection.

## Freeze original policy before resolving a step

`grounded_contract` produces the runtime contract, including existing optional HOME omission and velocity constraints. Freeze this exact contract and its original proposal/compiler/source identity before `resolved_step` clears semantic lists or changes geometric parameters. The original plan remains the event repository's active immutable original for that version. A derived per-step contract is an execution view, never a replacement original with the same version.

OriginalActionRequirements must combine the complete original semantic requirements with the real local canonical per-skill requirements currently checked by `run_online` and `execute`. In particular MOVE_ABOVE/APPROACH and GRASP retain visible/reachable/open; LIFT/MOVE_TO_REGION/PLACE retain holding; RELEASE retains inside-region/holding and released effect; RETREAT retains released. The source inventory includes the compiler, local condition policy, native_action_contract and deterministic grounding implementation. Preserve full target/tolerances/sensors,0.01m allowance,5s ordinary TTL, original timeout/retry horizon and the earliest original task/verification/contract deadline. Adding required checks is permitted; dropping original or actual local checks is not.

Requirements for resolved TCP goals depend on real current grounding. Their full target parameters and duration inputs must be included in the per-step binding and checked at submit; merely hashing a duration input does not verify physical duration coverage. Native bounds remain None until separately measured and accepted. A stricter canonical requirement that is not currently measurable stays UNKNOWN.

## Boundary and budget sequence

1. Establish actual worker/lease/capture identity and original absolute deadlines. Initialize verification/retry definitions from the original policy exactly once; existing debits, history and deadlines win. Current per-episode in-memory verification state must subsequently be kept coherent with the registered pool rather than reset on a reobserve, restart or repair.
2. After original runtime compilation, initialize durable original/active/checkpoint/budget rows atomically through the reviewed event repository API. Publish initial cursor with no physical effect claim. No callback runs under the repository lock.
3. After inference, capture a new RGB-D frame and obtain actual current robot/role/source state. Publish the current checkpoint and source-only grounding with exact revision/generation CAS, preserving the completed prefix. Check lease again. Fresh generation does not make stale image/calibration fresh.
4. Before PRE_SAFETY and PRE_SKILL, reread current original/publication and current lease/role/source bytes. Verify exact original requirement digest, pending cursor, checkpoint/source/frame/grounding identity and deadlines. Recompute current grounding and native action evidence through the existing local path. Keep immediate hard-stop ordering; no collector/factory may dispatch.
5. Invoke only the existing SkillExecutor.execute_attempt. Preserve returned/exception/partial evidence. After actual new acquisition, Safety postcheck and canonical effect verification, update completed prefix once. A skill-return success or checkpoint write alone is insufficient to complete an effect. Failure/cancellation records available progress without turning it into a verified completion.
6. Reobserve and supervision budget debits update their persistent source. A legal debit can make an older source publication unavailable until a fresh coherent publication; this is not a reason to refill the pool. Recovery must pass the existing reserve/stage/activation/start/completion lifecycle and ReplanApplyCAS, with separately coordinated actual mode evidence. Mode remains NOT_INCLUDED in the first boundary integration.

`_VisualEpisode` currently iterates cached `contract.steps`; source registration alone does not implement a resumed/repaired cursor. A later recovery integration must use the accepted original/cursor/version after CAS and never replay completed physical effects. The first source-registration integration may stop when the original version changes, explicitly leaving resume unavailable.

## Bounded implementation and validation

First implement a concrete source factory/bridge plus dedicated software tests against the independently reviewed durable repository. Then modify explicit ExecutionPolicy and worker/visual boundary seams with separate ownership and baseline snapshots. Do not introduce a third executor or enable formal methods as a side effect. The actual raw-v3 recorder is independent and must observe the same sole executor boundary; its complete clocks are not an owner permission token.

Required tests include stale job attempt, lease reassignment/expiry/heartbeat loss, capture episode mismatch, no explicit role binding, source mutation, original semantic loss during resolution, same-version overwrite, deadline extension, pool refill, publication CAS races, failed/partial executor outcome, cancelled return, stale after-frame, completion prefix idempotence and default LEGACY behavior. No fake VALID callback or mock physical-success report can count as actual acceptance. Software fixtures remain SOFTWARE_ONLY. Source/CPU/static review precedes any qualified development capture and does not remove the separate native certificate, billing, INITIAL or METHOD requirements.
