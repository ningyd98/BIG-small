# Conditional repair planning without execution authority

This additive component addresses the already observed GRASP-to-LIFT limitation. The existing role visual repair provider requires actual evidence for every replacement before producing executable candidate steps. The new path will represent future requirements as planning intentions until each step is freshly grounded. It will not change the current provider, submission duration horizon, SafetyShield, SkillExecutor, replan CAS or method admission.

Inputs are the independently reviewed immutable `VisualOriginalPlan` and its original complete `OriginalActionRequirements`, an exact local repair window, a current source checkpoint and new RGBD source identity, plus a typed model replacement-intent payload. The original plan retains skill, object/destination identity, full preconditions and effects, timeout/retry policy, sensors, error allowance and duration. Returned pixels are intentions, not poses or commands. Completed and unrelated original steps must retain their original bytes and effect identities.

The result is a separate immutable `ConditionalRepairPlanningIntent` with scope PLANNING_ONLY and execution/method admission fixed false. It contains future requirement references and exact original/context/frame/version hashes, and exposes no `LocalReplanningResponse`, executable TaskContract, stage token, ActionEvidenceContract, executor or activation method. Calling the ordinary submission API with this type must fail strict type validation. A current FAIL or UNKNOWN future holding condition cannot be relabeled PASS; it remains a requirement to recheck after the earlier action.

The component will first validate the local source/version/checkpoint/window/deadline bindings. It will retain actual failed/unknown attempt information without authorizing another model call or allocating a new budget. A future role-bound cloud adapter may request only the existing bounded visual JSON schema with the already reviewed redacted payload policy; that integration requires its own source and budget review. The first bounded implementation is a pure local parser/binder and performs no cloud request.

Before physical use, the owner must independently recompute each next-step grounding from a new actual frame and registered deterministic policy, preserve the original requirements, verify current canonical prerequisites, and pass the unchanged full-duration submission gate and durable owner/mode/budget CAS. Failed or hidden holding evidence stops LIFT. The planning intent can neither resolve a recovery nor prove task completion.

ROOT will own two new files after the owner requirement API freezes: `cloud/replanning/conditional_intent.py` and `tests/test_conditional_repair_intent.py`. Required negatives include unauthorized/duplicate IDs, completed-effect replay, unrelated mutation, skill/target change, missing full requirement coverage, payload/versions/checkpoint/frame mismatch, stale or future capture, deadline extension, nested alias mutation and attempts to request execution/accepted scope. Software positives may preserve a future FAIL as a pending requirement; they never constitute actual native or method acceptance.
