## Three changes needed for the minimal actual pilot

1. **Place the later exchange after the captured pairs.** `plan.md:11` currently reads as saving all clock exchanges before entering the recorder. Such exchanges cannot supply B for any later RESET/SETTLE pair. Make the concrete order: verify A in the capture process; enter the sole observer; actual RESET; unchanged 120 SETTLE; stop acquisition and freeze the ordered original slab; send B whose nonce commits that slab and A; verify B; export and publish. Query work remains off the backend thread. Two successful exchanges can cover this short whole slab; missing B preserves unavailable UTC. If a separate helper process performs UDP/verifying, obtain send/verification brackets through an owned coordinator in the same clock domain rather than declaring foreign-process brackets equivalent.

2. **The stop branch must precede the planner factory.** `simulation_runtime/worker.py:691` invokes `planner_factory()` before backend initialization, RESET and SETTLE. Returning at the existing post-SETTLE position alone would not implement “before planner/model calls.” Route the application-owned prefix mode before that factory, and validate its frozen role/source configuration without constructing a planner. Share the real fresh-backend/borrowed-capture/sole-executor/RESET/SETTLE seam. Keep setup cancellation/timeout, lease and source checks. A CPU control should make planner construction fail if reached and exercise the real repository lease path; the actual prefix remains a separately reported acquisition.

3. **Export unbound prefix originals through a distinct owned publisher.** `vision/raw_recorder_v3.py:937-994` saves typed raw records/envelope only if `_identity` is bound; an unadopted prefix currently saves its allocation ledger but not its original interval/physics rows. `bind_worker_source()` requires `runtime.original`, so it cannot legitimately fix this. V2 must persist the detached RESET journal, tee pair inventory, original SETTLE/CONTROL/PHYSICS rows, failures, actual configuration and lease/source evidence from the same owned recorder into an explicitly excluded-prefix receipt. It must not fabricate task/plan ownership or call this a complete RawV3 calibration group.

For that publisher, make the already intended application receipt concrete: its live handle is issued and retained by the actual configured worker, binds the exact repository instance/database, active task origin, role configuration, current lease/attempt, recorder/backend/capture/executor and frozen clock policy, and is rechecked before publication under the existing repository guard. `RoleRuntimeBinding` (`vision/runtime_binding.py:45-80`) and `WorkerRuntimeSource` (`vision/worker_runtime.py:111-160`) are publicly constructible dataclasses. `read_visual_worker_lease()` (`vision/worker_owner.py:131-238`) proves joins in the provided repository; it does not itself prove that a supplied repository/role came from the active application. A copied dataclass/catalog cannot replace that live handle. This is a finite software guard, not a claim of resistance to arbitrary code execution inside the trusted process.

## Official clock evidence and the trust boundary

The official [usage page](https://developers.cloudflare.com/time-services/roughtime/usage/) still supplies port 2003, the stated key and a beta rotation notice. The official [service inventory](https://raw.githubusercontent.com/cloudflare/roughtime/master/ecosystem.md) describes Cloudflare-Roughtime-2 draft-08 support; the official [repository](https://github.com/cloudflare/roughtime) supports drafts 08/11 and excludes production use. These support a research candidate, not service reachability or actual wire support. No response was queried in this review.

[Draft-08 sections 5.1.5, 6.2.5 and 6.4](https://datatracker.ietf.org/doc/html/draft-ietf-ntp-roughtime-08) define Unix UTC seconds, signed radius and the issuer's accuracy assertion. Valid signatures authenticate issuance, not actual clock accuracy. Freeze the issuer/key/version/conversion policy as application source; a runtime accuracy flag is insufficient. An initial real packet/signature diagnostic can run without claiming trusted UTC. Accepted research UTC intervals require the explicit conditional issuer policy plus successful actual response and complete conversion/radius evidence. Neither demonstrates metrological calibration or finite robot admission.

The official [version source](https://raw.githubusercontent.com/cloudflare/roughtime/master/protocol/version.go) identifies draft-08 as `0x80000008`; choose that explicit sole version rather than the package default. The official [protocol source](https://raw.githubusercontent.com/cloudflare/roughtime/master/protocol/protocol.go), lines 762-928, verifies delegation/signature/nonce and converts IETF MIDP/RADI using seconds. Its current implementation discards the detected framing flag and does not reject leftover INDX bits after traversing PATH. The planned wrapper REDs must enforce both checks explicitly around the pinned official verifier. Freeze the upstream commit, dependency/compiler/binary and wrapper hashes before actual use. Missing Go is recoverable preparation: install a fixed official toolchain with verified hash when implementing; it is not a permanent blocker. Pin and conservatively include quantization/conversion uncertainty rather than borrowing Google variant smear semantics.

**Causal slab inference is valid under that accepted issuer accuracy policy and a valid ordered UTC conversion.** Let remote A's authenticated processing event occur before A is verified, and B's authenticated processing event occur after B is sent. The recorded condition `A.verified_after <= pair.mono_before <= pair.mono_after <= B.send_before` therefore puts the whole pair after A and before B. With true A time in `[L_A,U_A]` and true B time in `[L_B,U_B]`, the conservative enclosing pair interval is `[L_A,U_B]`. This inference uses causality, not oscillator drift, symmetric delay or RTT/2. Radius/conversion/quantization widen its endpoints; lost replies or invalid/domain-mismatched brackets leave pairs unavailable. It can cover every pair with low frequency exchanges, but actual width may fail unchanged TTL/deadline thresholds. Preserve that outcome.

The design's NTP conclusion is also sound: [systemd v255](https://raw.githubusercontent.com/systemd/systemd/v255/src/timedate/timedatectl.c), lines 397-403, computes client delay separately from upstream root delay/2 plus dispersion. The preflight telemetry supplies no per-pair independent UTC error bound.

No nine-group statistics implementation is a prerequisite for this minimal pilot.
