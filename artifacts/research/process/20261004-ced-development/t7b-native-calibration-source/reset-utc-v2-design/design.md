Its actual RESET event carries original requested scenario, operation ID, old/absent BEGIN episode, new END episode, reset result/physics state and error. BEGIN need not have the END episode; successful END must match the subsequently bound raw identity. The operation ledger is a second original join, but contains no UTC.

The existing recorder retains reset result/metadata but returns from `_on_boundary()` without a clock pair. Its `_clock_pair()` yields the exact sequence/monotonic-before/local-UTC/monotonic-after tuple used by existing raw intervals. Source binding occurs after RESET. A new `VisualResetClockRecorderV2` extends this class and owns the same observer: override `_clock_pair()` to tee the returned original tuple; override `_on_boundary()` to additionally allocate and sample RESET BEGIN/END before forwarding once to `super()`. No second observer, mutable backend access, rendering, stepping, command, network request, disk flush or blocking wait in the callback. Keep bounded in-memory records and append-only failures; publish originals after the callback. Clock queries run asynchronously outside the owner/controller thread. Observer overhead and query work are measured, never described as zero or identical wall cadence.

`execution.py:609` currently requires the exact old recorder type. A later explicit patch must accept the two exact concrete classes; the new one additionally proves an application factory receipt and unchanged source inventory. Do not replace this gate with `isinstance` or accept arbitrary subclasses. Its backend/capture/executor identity checks remain. Worker source-inventory assembly at 748 must include the new collector, clock client/verifier, publisher and clock-authority configuration before initialization.

The current marker V3 teacher calls `capture.apply_scene()` / `DIRECT_OFFLINE_SCENE_ADAPTER`; it does not enter native RESET/RawV3. It cannot be retroactively upgraded or counted as an independent calibration group. Native collection must compile the scoped model/config before RESET and borrow capture. The development asset remains excluded until its asset/domain is explicitly approved for the new calibration scope. Check object/contact/TCP/marker geometry, 640x480 top camera, original controller and depth-noise configuration: backend native initialization defaults to 0.001 m sensor noise while the offline scene adapter sets zero. ## Independent UTC: external signed originals, not telemetry

The local preflight reports NTPSync and upstream root distance 4057 us, but D-Bus client RTT 389599 us. The [systemd 255 implementation](https://raw.githubusercontent.com/systemd/systemd/v255/src/timedate/timedatectl.c) computes upstream delay/2 plus dispersion separately from client RTT. Those values do not bound local UTC for every pair. No extrapolated clock drift, inferred reset timestamp, local clock server, NTP flag/rootdistance/offset/jitter or caller accuracy scalar is accepted.

The first research candidate is a pinned external Roughtime source because original replies have publicly verifiable signatures. [Cloudflare's current official page](https://developers.cloudflare.com/time-services/roughtime/usage/) lists `roughtime.cloudflare.com:2003`, public Ed25519 key `0GD7c3yP8xEc4Zl2zeuN2SlLvDVVocjsPSL8/Rl/7zg=` and beta key rotation. This establishes documentation availability, not an actual successful query. Do not auto-update the key via DNS or install `@latest`.

The [official client repository](https://github.com/cloudflare/roughtime) identifies draft-08/draft-11 support and warns against production use. Its [official service inventory](https://raw.githubusercontent.com/cloudflare/roughtime/master/ecosystem.md) describes Cloudflare-Roughtime-2 as supporting Google and draft-08. The initial explicit research request should select draft-08 only, matching these documented client/server versions; actual wire support is still unproven. Its [version selection](https://raw.githubusercontent.com/cloudflare/roughtime/master/protocol/version.go) distinguishes Google/08/11, while [verification and encoding](https://raw.githubusercontent.com/cloudflare/roughtime/master/protocol/protocol.go) use microseconds for Google and seconds for the IETF variants. Discovery references at `master` are not frozen build pins. Before any pilot, freeze the exact upstream commit, small client/verifier source inventory, build/compiler/dependency and binary hashes, request/response version, signature contexts, units, epoch and UTC conversion. Verify delegation, original signed bytes, nonce inclusion, key validity, framing and exact supported response version; CLI displayed time is insufficient. Use the official Go protocol package with a small owned wire-capture wrapper, not newly invented cryptography.

The [legacy Google protocol](https://roughtime.googlesource.com/roughtime/%2Bshow/dd529367052d2d4e723407525887310fe866ddd8/PROTOCOL.md) specifies a 24-hour UTC leap smear; it cannot automatically describe a different response version. [Draft-08](https://datatracker.ietf.org/doc/html/draft-ietf-ntp-roughtime-08) specifies Unix UTC seconds and an issuer accuracy assertion; signature validity proves issuance, not correct time. The [roughtime.se operator](https://roughtime.se/) currently lists a UTC atomic-clock source, draft-19, a different key and port 2002; the cited Cloudflare client is not assumed compatible. This is an alternative issuer requiring its own supported client/version proof, not a fallback assembled from mismatched documents.

Freeze an app-owned issuer policy specifying whose accuracy assertion is trusted, supported protocol/UTC conversion and its uncertainty. A signed timestamp is conditional on that issuer's accuracy claim; it is not a metrological certificate. If such a policy cannot be justified, the Roughtime pilot demonstrates signatures only; genuine native UTC remains unavailable until an independently calibrated source (for example a separately sourced GNSS/PPS logger with original device calibration) supplies it. This decision belongs in the explicit source registration, not in a caller flag. No actual remote response or accepted UTC conversion has been collected in this design task.

## Causal slab coverage without frequency assumptions

For each slab preserve actual packet bytes, fresh random blinding material, nonce/chain commitments, remote endpoint, pinned issuer/key/protocol policy, client send/receive monotonic brackets and verifier completion bracket. A prior reply A must have been received and verified before every local pair in the slab. The later query B must be sent after every pair. Its nonce commits the complete ordered pair/journal digest and A's response via the pinned official chaining construction; retain the public blinding/commitment proof. Preregistration gets a distinct signed commitment to the immutable planned group inventory, policy/reference recipe, exact full horizons and source scope before acquisition.

Use conservative inequalities `A.verified_after <= pair.mono_before <= pair.mono_after <= B.send_before` in the same live process clock domain. If A's converted signed processing interval is [L_A,U_A] and B's is [L_B,U_B], causal ordering yields pair UTC in [L_A,U_B]. Include all protocol quantization, issuer radius and conversion errors. This is an inference from causality under the accepted issuer accuracy policy. It assumes no clock rate, delay symmetry or RTT/2 bound. Actual network delay widens the interval; gaps, reversed order, restart/suspend/domain changes, bad signature/version or lost replies retain unavailable pairs. Async workers snapshot immutable slabs without holding the backend thread; no per-physics-step UDP flood. Interval width may make current TTL/age/deadline tests fail; preserve those thresholds and all group allocations.
