## Behavior and admission limits

RecoveryRecord preserves the exact ten planned positional fields and six planned states. Version, original checkpoint/contract/condition identity, revisions, actual start/completion timestamps and provider scope are keyword-only metadata. DETECTED is the only public initialization state. Recovery/verification serializers reject unknown schemas, stale content hashes and SQLite payload/index identity disagreements. Initializer identities are idempotent; one failure event cannot acquire another record or share its attempt identity. Reads return detached copies, including recursively frozen condition tolerances.

The task has one durable VerificationBudgetRecord. Existing initialization preserves complete quotas, progress, limits and absolute deadline without updating SQLite bytes; its retry mirror derives from the existing RecoveryBudget, including already spent task counts. The authorization producer consumes that existing authority and atomically updates retry counts, recovery state and the verification pool under the memory lock or SQLite BEGIN IMMEDIATE. Canonical T10 inputs are frozen before the transaction; inside it only pure recomputation occurs against current event, active contract, checkpoint, cancellation and source clocks. Stale CAS values, safety faults, actual step/skill limits, expired source/deadlines, wrong targets or incomplete timeout coverage consume nothing. A fault after SQLite writes rolls back all three records. Exact duplicate authorization never grants a second execution permission.

A start receipt/ACK is not execution completion or resolution. RETRY_EXECUTED requires an injected canonical ReplanExecutionReceipt plus actual SkillExecutionResult completion source, current checkpoint digest/attempt evidence and ordered authorization <= start <= completion <= checkpoint <= current clock. A completed FAILED attempt may enter RETRY_EXECUTED but stays unresolved. Missing/start-only/wrong-identity/early/future sources do not assert execution.

Verification recomputes canonical evaluate_conditions from frozen required conditions and an injected OnlineEvidenceSnapshot. Supplied verdicts must exactly match the recomputation. Only nonempty all-PASS on current contract/checkpoint/episode/versions, a distinct source frame strictly after actual completion and safe connected RobotState enters VERIFIED_RESOLVED. FAIL/UNKNOWN/old/foreign/replayed sources do not resolve. Source acquisition has a preflight deadline/current-context/cancellation gate, and transaction validation rechecks after provider acquisition. Provider callbacks run outside repository locks; they acquire source evidence, never dispatch a motion.

Reobservation reservations spend the persistent task allowance before recapture, using a typed current-safe RobotState/checkpoint/time source; missing provider/source, stale state, unsafe robot or duplicate reservation cannot reserve. The initial post-execution verification source is distinct from additional reobservation reservations. No-progress uses best canonical condition name+target+tolerances+sensors state across events, excluding frame/event/time/confidence IDs. UNKNOWN->valid, FAIL->PASS or comparable attributed residual improvement resets only the no-progress counter. Distinct frame IDs, repeated best states, worsening residuals and new events do not reset it. Third consecutive no-progress round with cap three persists EXHAUSTED; spent reobservations, retry counts and deadline never refill on restart/new event.

Persisted `RecoveryRecord.evidence_scope` values are UNAVAILABLE (default), SOFTWARE_ONLY and ACTUAL_SOURCE. Synthetic authorization/execution fixtures explicitly use SOFTWARE_ONLY. **ACTUAL_SOURCE authorization remains unavailable:** current TaskStep list[str] does not supply a certified full frozen target/tolerance requirement binding, and legacy empty success_conditions have no certified mapping. A source flag cannot manufacture that proof. Nonempty actual step names cannot be weakened; the software GRASP floor requires canonical object_held, so target_visible alone cannot resolve grasp recovery. Root must add an actual frozen requirement source/provider and admission adapter before enabling physical recovery. There is no invented legacy geometry/condition mapping or automatic dispatch.

The latter excludes only ACTUAL_SOURCE+VERIFIED_RESOLVED, retaining software-only resolved diagnostic records and exhausted/unrecoverable failures. ## Exact producer/consumer seams

- initialize_verification_budget_if_absent(task_id, state) -> VerificationBudgetRecord; get_verification_budget(task_id) -> envelope | None.
- initialize_recovery_if_absent(record) -> RecoveryRecord; get_recovery(recovery_id), list_recoveries(task_id), list_unresolved_recoveries(task_id).
- consume_retry_and_authorize_recovery_if_current(*, recovery_id, expected_recovery_revision, expected_verification_budget_revision, expected_retry_count, step_id, skill, authorization: RecoveryAuthorizationEvidence) -> RecoveryAuthorizationResult. The result carries authorized, recovery, retry_budget, verification_budget and reasons. Only authorized=True is a newly consumed authority; it is not dispatch, completion or physical admission.
- advance_recovery_if_current(record, *, expected_state, expected_revision, expected_budget_revision, verified_transition: RecoveryTransitionEvidence) -> RecoveryRecord | None. The input must exactly match saved current content; the repository derives all effect fields itself.
- reserve_reobservation_if_current(*, recovery_id, expected_revision, expected_budget_revision, reservation: RecoveryReservationEvidence | None=None) -> RecoveryRecord | None. No supplied safe current source means unavailable.
- RecoveryLifecycleService(repository=..., execution_provider=..., evidence_provider=..., current_state_provider=...). Providers are optional and unavailable by default. advance_recovery(recovery_id, expected_state, next_state, verification) preserves the planned call. reserve_reobservation(recovery_id) returns a newly reserved record or None; it never captures a frame itself.
- RecoveryAuthorizationEvidence(recovery_id, decision, current, action, online_evidence, *, evidence_scope=UNAVAILABLE); RecoveryExecutionEvidence(receipt, completion, checkpoint_hash, *, evidence_scope=UNAVAILABLE); RecoveryReservationEvidence(robot_state, checkpoint_hash, captured_at, *, evidence_scope=UNAVAILABLE). v1 authorization explicitly scopes candidate_set_hash to the whole current contract and context_hash to the checkpoint; future T12 candidate-set identities require a binding adapter, not hash conflation.
