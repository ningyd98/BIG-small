## Implementation and boundaries

- Strict immutable source input contains full original/publication/CAS group, online observation/robot/facts, current step/attempt/phase, event key and authorized execution-contract view. It carries no trusted verdict/action/accepted flag. Typed constructors/strict JSON reject bool/float integer coercion, duplicate/unknown keys, nonfinite values and caller aliases. Current stored model rows are validated before decoding can discard unknown fields. Free-form evidence booleans remain legitimate data.
- Memory uses its existing lock; SQLite uses BEGIN IMMEDIATE. Validation and serialization precede mutations; SQLite rollback covers a real insert-abort trigger. Missing/coherently changed/cancelled groups return None, without creating pools or filling partial source groups. Current versions, checkpoint/hash, publication revision/generation, pool/retry hashes, full original condition policy and source identity all remain bound. Original limits/deadlines stay unchanged; observations debit exactly once, retries never debit here. Legal external retry changes make old publication unavailable, requiring an existing normal fresh publication before new routing.
- Stable source dedup binds original+versions+step+attempt+phase+frame ID/checksum+full requirements, independent of event UUID and publication generation. Same key changed bytes or same source frame changed evidence/semantic payload conflicts. Historical results cannot replay capture. REOBSERVE irrevocably reserves/claims one attempt; a lost response, crash, invalidation or unavailable future worker cannot refund it or replay its claim.
- Progress namespace includes full original requirement/spec/target, step/attempt/phase and each ordered verdict separately. Best verified history is retained, so equally named conditions for different targets do not alias. New frame ID does not count as progress. PASS retains existing no-progress count and spent quotas while recording best PASS history; exhausted pools stay STOP. Unsupported FAIL recovery remains STOP, and future conditional repair planning remains a separate PLANNING_ONLY module rather than a routing capability here.
- All seven phases have explicit source checks. Ordinary preconditions recompute complete original preconditions. Native phases recompute the actual pure native action factory/validator with full original duration/error/sensor/condition policy; future postconditions are frozen requirements, not required PASS before submission. PRE_SKILL invalidation stops without recapture into stale SafetyShield context. After-effect requires a fully bound typed completion and an independently new later frame; failed/missing result/source stops. Hold/terminal also require a complete registered phase mapping. No source flag supplies such a mapping.
- SOURCE checkpoint context and native role+full contract+step context keep distinct hash meanings; same frozen evidence-content hash binds the views. Normal publication v1/schema/operation-hash is unchanged; route history separately binds full inputs/outputs and recomputes canonical route plus entire after-pool on load, preventing a rehashed STOP→CONTINUE claim. Exact signatures and hash payloads are in `public-contract.md`.
- Optional original `camera_source_descriptor_sha256` tolerance is checked against exact fixedv1 source/width/height/intrinsics/camera_to_world/depth_convention/calibration_version mapping. Descriptor mismatch prevents routing. Without a registered descriptor, this is pure existing version/spec consistency only; a version string is never calibration authentication. Root's actual factory must register the full genuine descriptor.
