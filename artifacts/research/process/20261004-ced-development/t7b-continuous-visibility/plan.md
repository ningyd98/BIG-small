## Action, command, physics, and clock association

The teacher action observer supplies `start_step`, `end_step`, and one-based half-open command span `[command_seq_start, command_seq_end)`. It supplies no action BEGIN clock or callback for an exception before a result. Temporarily wrap the seven bound robot methods used by this exact teacher (`move_above`, `approach`, `grasp`, `lift`, `move_to_region`, `place`, `release`) and the teacher module's `_dwell`. Each wrapper allocates a monotonically increasing action ordinal, logs BEGIN before delegating **exactly once** to the saved original callable, and logs END/result or failure in `finally`. Reject unexpected nesting instead of creating duplicate actions. Restore every binding in outer `finally`; never modify production files or instantiate another executor. Initial settling is an acquisition phase, not an invented robot action.

Every allocated action, operation, actuator observation, and acquisition gets a record sequence plus two clock samples (start/end where applicable), each formed as `monotonic_ns()` → `datetime.now(UTC)` → `monotonic_ns()`. Store nanoseconds as integer nanoseconds, UTC as timezone-aware UTC, and simulation seconds as the original float. Store both monotonic brackets; do not substitute simulation time for wall time or invent UTC uncertainty. Compare the wrapper spans against the teacher's post-result spans, preserve unsuccessful/unframed actions, and join samples by exact episode/step/operation/action IDs rather than timestamp proximity alone.

Allocate and flush acquisition BEGIN **before** rendering. Save: allocation ID, sample ordinal, phase/action ordinal, episode/group/scene/asset IDs, actual step and simulation time, scheduled cadence metadata, last CONTROL/PHYSICS operation IDs, command sequence visible at that step, original camera/calibration values, physical-state hash before/after, both render-pass hashes, sensor frame ID/UTC/latency, observation checksum, raw-member hashes and lengths, start/end/save clock brackets, status and exception. Retain raw physical/actuator/command sources offline. Only the RGBD observation and exact `PoseMarkerRegistration(7, 0.045, outboard_asset_hash)` may reach `detect_pose_marker`; neither simulator object pose nor segmentation, action target, or scorer output is a decoder input.

Manual two-pass acquisitions bypass the decorated public CAPTURE operation, so identify them explicitly as `TEACHER_PHYSICAL_CALLBACK_RGBD`, not fabricated backend CAPTURE records. The existing `VisualRawRecorderV3` cannot ingest this private acquisition through a public producer API and its `execute_attempt` route would run a separate executor. Do not instantiate it here or claim a COMPLETE native raw-v3 envelope. A full raw-v3 producer integration would require a separate reviewed API change. This proposal records an inspectable **excluded teacher trace** with exact action/command/physics/clock association.
