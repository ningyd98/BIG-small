# Live verification routing: read-only integration design

**DESIGN_ONLY; no implementation or actual admission.** The inspected repository has no safe transaction for ordinary visual verification that updates its durable verification pool and its owner publication together. The recovery reservation API is intentionally narrower and must not be repurposed by fabricating a recovery. The smallest addition is one strict source-routing producer, an atomic repository route operation and a history getter. Its persisted records have fixed **SOURCE_ROUTE_ONLY** scope. CONTINUE means a local verification-routing result, never native/METHOD, physical success, authenticated owner, action ACK or permission to execute.

The exact26 references are in `source-hashes.json`/`source/`, manifest SHA256 `a3c82a49f8bf1274d5070e4a893c7814773f8c14f815371565463934a53ee85b`. Twenty-two source files are read from the accepted owner fix1 archive; three quiet runtime files were copied and hashed before reading; the final frozen worker-owner report is the26th reference. `reference-provenance.json` identifies each original. This selected design inventory is **not** a runnable transitive release. No moving worker_owner namespace was imported or read; the report declares its pure source-binding factory integration NOT_IMPLEMENTED. No existing freeze/report or production file is edited. No model/network/simulator-state/step/render/capture/control call occurs.

## Minimal proposed interfaces and files

Root-owned implementation may add `repositories/event_autonomy/visual_verification.py` for strict detached records/codecs and the pure transition producer; narrowly add two methods to protocol/memory/sqlite. Reuse owner fix1 canonical encoding, strict raw nested schema validation, VerificationBudgetRecord/copy_budget, original requirements, checkpoint validators, publication constructor and monotonic_pools. Do not add an executor, a callback that returns VALID, a caller-controlled accepted flag, or a replacement pool.

```python
route_visual_verification_if_current(
    *, request: VisualVerificationRouteInput
) -> VisualVerificationRouteWriteResult | None

get_visual_verification_route(
    task_id: str, event_key: str
) -> VisualVerificationRouteRecord | None
```

`None` means CAS/source/context unavailable; it authorizes nothing and performs no debit. The write result contains the immutable SOURCE_ROUTE_ONLY record plus an operation disposition **NEW_COMMIT** or **HISTORICAL_DUPLICATE**, not a physical/execution authority flag. The getter returns detached historical information only. A duplicate result must never trigger another capture or retry. A lost response/crash after NEW_COMMIT loses the spent allowance; restart must stop/reconcile, never replay or refund it.

The input carries exact original identity/hash, owner_epoch, expected owner_revision/publication_hash/state_generation, active contract/plan+command versions/hash, expected checkpoint hash, expected verification pool revision/content_hash and retry pool canonical hash, step/attempt, phase, stable event_key, full registered observation/robot/facts snapshot, full original ConditionSpecs hash, and frame ID/checksum/captured_at/calibration/source inventory. It carries no trusted verdict/action/status. It is snapshotted through strict schemas before acquiring the repository lock; raw integers/bools/nonfinite/unknown fields are validated before model coercion. Facts may contain legitimate booleans; do not indiscriminately ban bools in free-form evidence.

The record binds complete request content hash, dedup source key, source and produced publication revisions/hashes/generations, before/after pool revisions/hashes and state, canonical verdicts, route/reasons, transaction UTC, and the capture claim if REOBSERVE. Scope and lack of authority are literal class/schema invariants, not constructor flags. Existing publication schema can remain intact: generate its standard boundary-operation hash and append its normal next revision. The separate route record links that publication digest and the complete routing input/output. Do not insert unrecognized new fields into the strict owner v1 publication. If an implementation changes its hash/schema instead, it needs a versioned codec/migration and separate review.

The transaction reads the clock itself. For deterministic reuse, a narrow optional keyword `now` in route_verification can default to its existing UTC behavior for LEGACY; source producer supplies the transaction time. It must not monkeypatch clocks. A source-only progress projection uses full-spec stable keys while retaining original verdict names in audit records. Current all-PASS routing exits before tracking progress: source producer must explicitly preserve verified best PASS history for such results, without refunding any quota or resurrecting an exhausted pool; document/test that source-path difference rather than changing LEGACY implicitly.

## Atomic transaction, deduplication and quota rules

Memory holds the existing repository lock; SQLite uses BEGIN IMMEDIATE with rollback on any validation/write error. No provider, backend/capture, lease/mode repo IO, callback or network is invoked under this lock. The frozen request is revalidated against transaction-current stored rows; canonical conditions/native proof are recomputed in the pure producer, not trusted from a public callback.

1. Require the entire original + active contract + checkpoint + verification pool + retry pool + publication chain. Validate exact identity/epoch/original requirements and frozen source inventory. Partial groups stay unavailable; never reconstruct missing rows from the request. Check cancel state within the transaction. Expired original/task/contract/verification deadline stops, without extension. Reject future/stale frame/telemetry, mismatched calibration/version/hash/generation or action attempt/phase. Read actual supplied robot hardstop independently: estop, collision or disconnected stops before any quota debit/reservation. Record a source-bound STOP where coherent source exists; absent coherent source returns None.
2. Dedup on `(task, original plan hash, plan_version, command_seq, step_id, attempt, phase, frame ID, frame checksum, full ConditionSpecs hash)`. Bind each stable event_key to complete original request bytes/hash. Identical event is historical only; changed bytes under the same event_key conflict. A new random UUID, new publication generation, a restarted process or repeated old frame cannot create another verification round/reservation. Same-frame different genuinely registered phase has a separate key; it must not impersonate the next phase or future after-effect.
3. Check expected owner/publication/checkpoint/pool/retry revisions and hashes in the same lock. Use current decoded pool, never caller `budget_after`. Normal reobservation debits remaining_reobservations exactly once and persists no-progress/rounds/best-condition state. Original limits/deadline remain exactly unchanged; remaining reobservations/retries never increase. STOP cannot return consumed allowances. Verification pool revision and owner revision advance together; generation strictly advances. Persist route record, updated pool and matching publication atomically; a failure before commit leaves all three unchanged.
4. For this first increment capabilities are exactly CONTINUE/REOBSERVE/STOP. UNKNOWN can only STOP or reserve one reobservation; FAIL never CONTINUE. A future holding FAIL may be input to PLANNING_ONLY conditional repair and stays FAIL. No generic route retry debit: real recovery uses consume_retry_and_authorize_recovery_if_current exclusively, and real repair stage/activation/start uses the existing replan CAS/actual ACK/receipt path.
5. Progress keys include stable original requirement/target/spec/phase/step/attempt context. Only genuine canonical UNKNOWN→observed-valid, FAIL→PASS or comparable lower residual within the same condition source/context counts. New frame ID, newly introduced condition, omission, renamed phase, oscillation or a different object does not reset no-progress. Preserve best historical status/residual; do not transfer apparent progress across changed full requirements. Reaching frozen no-progress limit is permanent exhaustion for this task pool; no task/event/worker restart resets it.
6. REOBSERVE commit reserves and irrevocably claims this capture attempt in the same transaction. Only the designated worker consumer of NEW_COMMIT may proceed after fresh current source/lease/hardstop checks; returned route record itself supplies no authority. Duplicate callers never perform the effect. A crash, lost lease, capture exception/timeout or post-commit invalidation retains consumption and records failed/invalidated history. No automatic retry of a claim; a separately fresh route on an actually new current frame may reserve only remaining quota. Mandatory initial, post-action and supervision acquisitions need explicitly identified boundary provenance; they cannot be falsely labeled free retries or charged twice.

Existing external legitimate retry/recovery consumption can make a publication stale. The new ordinary producer requires a current publication or a separately fresh publication that snapshots the consumed current pools; it never repairs stale state by copying an old budget. This respects the accepted publish API's ability to refresh after monotonic external debit. Publishing does not debit; retry producer does not also route/debit the same verification round.

## Context versions and phase sequencing

Use two explicit, versioned context domains without changing the existing grounding contract: a **checkpoint grounding view** has context_hash equal to its exact source checkpoint hash; a **native action view** has the existing role + full current contract + full Safety-limited step hash. Both views must be built from the same frozen evidence contents (registered observation bytes/checksum/calibration, actual robot/facts and versions). A new SOURCE_ROUTE_ONLY boundary record binds their distinct hashes, shared evidence-content hash, original plan/requirements, source/current publication revisions and state_generation. The grounding binding's source checkpoint/revision/generation and payload hash must match this record. Never treat the two context hashes as interchangeable or rewrite a context after proof construction.

`state_generation` is the durable boundary sequencing identity, not proof physical motion occurred. Every phase binds the same worker-owned current observation source and exact generation; physical acquisition/frame identity is retained separately. After a route writes a new generation, a grounding or Safety update requires a fresh current publication/binding. Any action payload change (including Safety-limited parameters, timeout, retry, original conditions/tolerances/sensors or duration policy) requires recomputation and current binding. Hashing a changed payload alone does not validate it. Preserve separate `source_contract_hash` (the repository active/original contract) and `execution_contract_payload_hash` (the grounded/Safety-limited view). The latter may replace only the authorized current step through the reviewed grounding rules; all other steps, completed-effect identities and original timing/retry/condition policy remain frozen. Comparing either hash to the other would reject valid grounding or admit an unbound payload.

| Phase | Required source/check and permitted routing consequence |
|---|---|
| Ordinary PRECONDITION | Exact registered OriginalActionRequirements.preconditions, current frame/robot/context, evaluate_conditions. No weakened targets/tolerances. Empty or unmapped actual conditions stay unavailable; no new per-skill oracle or provider assertion. PASS routing is local only. |
| NATIVE_PRE_SAFETY / CLOUD_RETURN | Current native_action_contract and validate_evidence on the exact current contract/step with genuine current evidence. UNKNOWN may reserve capture before shield compilation; hardstop takes precedence. Future postconditions remain frozen requirements, never prematurely PASS. |
| NATIVE_PRE_SKILL | After SafetyShield resolves/limits payload, recompute current native proof and binding and recheck lease/cancel/clock. Invalidated proof stops; capture into the previous Safety context remains prohibited. A later permitted full restart recompiles grounding and shield from scratch, not a replay of the uncertain call. |
| AFTER_EFFECT / POST_HOLD / TERMINAL | Actual sole executor return/completion source and independently new observation after the effect/hold; canonical complete registered postconditions, not action ACK or nominal result success. UNKNOWN/FAIL stays unresolved; a submission PASS cannot replace this check. Additional hold/terminal requirements lacking a registered full-spec source are unavailable until explicitly registered/reviewed. |
| Recovery / repair | Real start plus actual completed result and fresh canonical conditions follow existing lifecycle; every SOFTWARE_ONLY resolution remains unable to unblock actual completion. Staging ACK, activation, resume ACK and actual start are separate durable facts. |

## Root-owned worker integration sequence

Keep default/LEGACY unchanged. Actual durable branch is explicit, fail-closed when source factory/registration is unavailable. Worker first checks exact current RUNNING job/lease/token/expiry/cancel and immutable job/scene/role inventory; constructs backend, robot and capture once; validates backend object identity; initializes original/checkpoint/pools once or loads the intact group. At every capture/request/grounding/Safety/executor/return boundary it rechecks those sources and closes the context record. Reconstruct runtime timeout from the minimum of the persistent original task/verification/contract deadlines and current job/lease bounds; never restart a full relative timeout. If clock/domain evidence cannot support that comparison, stop/unavailable instead of inventing a calibrated UTC-to-monotonic bridge. Under an existing registered contract this can feed the new route producer. An initial-cloud-plan workflow with no immutable original yet has no owner publication to route against: bootstrap capture/planning provenance and budget ownership need a separately reviewed initial-source contract, not a fabricated original or successful local CONTINUE.

The worker cannot make runtime-job lease, event repository and separate mode DB one transaction. Preserve exact lease/source reads before and after expensive work and immediately before the sole SkillExecutor; failed/missing lease stops and discards late authority. SOURCE/DURABLE_BINDING_ONLY records are not authenticated live owners. Mode selection remains NOT_INCLUDED and cannot be enabled by these records. No execute permission flows from route publication. The existing native gate, SafetyShield pre/post checks, original timeout/retry constraints, sole SkillExecutor and recovery/repair CAS remain authoritative; absent calibrated geometry/motion/native evidence still prevents real admission.
