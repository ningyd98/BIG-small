# T9 actual risk-source prerequisite audit

This is a read-only design audit. No model was fitted, selected, calibrated, enabled or admitted; no capture, provider request, key or account was accessed. Actual risk calibration remains NOT_RUN, INITIAL remains unavailable, and METHOD/execution remain UNKNOWN. Existing billing design and the 768-file T8/resource fix3 release are unchanged.

The smallest next implementation is **two new files**, `research/risk_sources.py` and `tests/test_research_risk_sources.py`: a server-registered, read-only raw-source auditor with separate RAW_EXECUTION and RISK_SUPERVISION scopes. It can independently reconstruct saved physical outcomes and raw execution consistency without granting risk or method admission. RISK_SUPERVISION cannot become VALID until the label definition, full source allocation, calibration basis, estimator scope and clock mapping described below are independently available. Existing `source_accepted=True` is never its acceptance authority.

## Existing persisted sources and reusable readers

1. T6 camera sources live below `datasets/<version>/episodes/<episode>/<sample>/`, with required RGB/depth/validity/instance/camera/scene/labels/state payloads. `COMMIT.json`, manifest/config/source, sample index and `reports/split_audit.json` bind committed samples. `DatasetWriter.load_records` scans commits rather than trusting an abbreviated index; `validate_dataset` compares full committed coverage and regenerated source-connected splits. `load_offline_observation` rejects traversal/symlinks, hash/shape/dtype drift and inconsistent three-pass state identities. These checks establish camera/source consistency, **not a physical risk-label recomputation**. `SampleRecord.execution_verified` is literally false.
2. The actual T8 collector in `scripts/run_rgbd_pilot.py` persists each assigned case's `physical-observations.json`, `actuator-steps.json`, `commands.json`, `fault-events.json`, `context.json`, frames/raw-frames/supervision-frames, policy/episode/physical summaries, verification envelopes and original wire/cost records. `context.json` is `rgbd.raw-episode.v2`, with reset0, every physics step through terminal, exact collector evaluation start120, full scene/assignment/episode hashes, initial controller targets and role-bundle hash. `_trace`, `_audit_ced_reset`, `_audit_actuators` and `_audit_ced_case` are useful existing readers but private and B0-specific. They do not currently expose a generic risk source API.
3. `simulation/mujoco/episode_evaluator.py:sample_physical_observation` derives each PhysicalSample from original PhysicsStepObservation; `evaluate_evidence` independently scores the full sample sequence. Task success includes lift, hold and terminal placement stability, with persisted scoped collision checks. A skill return, a terminal pose, a `failure` summary or a source-name string cannot substitute for this scoring.
4. The excluded marker-motion development run provides a useful second raw layout: `attempt-1/{raw-physics.jsonl,raw-actuators.jsonl,raw-actions.jsonl,commands.json,frames/...}` and original byte hashes. Root independently reconstructed **4807 physical samples**, checked **4806 actuator steps**, **743 commands**, **9 action ranges** and **10 RGBD frames/decoder results**. This seam proves the possibility of a real read-only raw re-reader; it does not make this excluded development run a risk calibration source.

The motion run's initial frame was OBSERVED, but all **nine post-action frames were UNKNOWN**. Its scoped simulator task success is distinct from missing online pose observability. Preserve both facts and the full missing-frame denominator. Do not use the source's offline simulator projection/occlusion diagnostic as an online feature, geometric bound, risk target or motion certificate.

Raw bytes plus hashes cannot independently prove who originally collected them. The reader therefore starts from **server-owned registrations and immutable original inventories**, not arbitrary uploaded roots, summary paths or caller-created receipt objects. It checks source consistency and recomputes labels; it does not claim cryptographic authenticity or full MuJoCo dynamics replay. A stronger dynamics replay would be a separate source capability, with an explicitly frozen simulator/version/tolerance contract.

## Minimal new owner API: first two-file task

Proposed new module: `src/cloud_edge_robot_arm/research/risk_sources.py`; dedicated tests: `tests/test_research_risk_sources.py`. No existing risk, admission, runtime, collector, protocol or frozen artifact file is edited in this first task.

The public interface is a registry-backed read-only auditor:

```python
class RiskSourceAuditor:
    def __init__(self, registrations: Mapping[str, RiskSourceRegistration]): ...
    def audit(self, evidence_id: str, *, scope: Literal[
        'RAW_EXECUTION', 'RISK_SUPERVISION'
    ] = 'RISK_SUPERVISION') -> RiskSourceAudit: ...
```

`RiskSourceRegistration` is supplied by the application owner, deep-copied and frozen at construction. It contains: one allowed artifact root; collector-layout version; expected original inventory/assignment/allocation paths and hashes; expected current source inventory; asset/camera/marker/estimator registration; evaluator criteria and collision scope; current RoleRuntimeBinding; INITIAL evidence ID/registered auditor; calibration-source registration; expected split/candidate/exclusion inventories. Optional absent registrations stay absent. No `accepted`, `source_status`, caller clock/fee/scope boolean or receipt file certifies a source.

`RiskSourceAudit` contains schema version, requested/verified scope, VALID/INVALID/UNKNOWN, explicit reasons, before/after byte inventories, source/current-role/asset/calibration hashes, original allocation counts, independently reconstructed physical/action outcomes, eligible/missing counts per label kind and immutable reconstructed label rows. It contains **no method or execution admission flag**. A serialized result is diagnostic: consumers must call the registered auditor again and compare current source identities, rather than trusting a stored VALID receipt.

The first RAW_EXECUTION implementation supports two explicit adapter versions: current CED pilot raw-v2 and marker-motion development raw-v1. It safely parses the exact expected layouts, rejects unknown schemas and omitted/extra/duplicate assignments or raw rows, joins reset-to-terminal physics, commands, pre-step controls, action/frame identities and recomputes physical outcome using the registered evaluator. Controller validation includes accepted command prefix, target clamp, error clamp±0.10, gravity bias/gain and control range; each control joins the previous physical state/time. The basis and initial controller state are source-bound, never inferred from a truncated table. Unsupported delay/controller versions remain UNKNOWN rather than copying a caller summary.

RISK_SUPERVISION adds the independently registered INITIAL source audit and every required source field below. The current sources lack these inputs, so this scope remains UNKNOWN with honest diagnostics. RAW_EXECUTION can be VALID for the original excluded development sample **within that source scope only**; `formal_source_eligible=false` remains immutable. Tests may reconstruct real saved development originals read-only or use explicitly SOFTWARE_ONLY fixtures for parser/controller math. No synthetic registration returns actual-risk VALID.

## Risk-label contract that must be frozen before collection

New risk data must have an original **pre-execution allocation inventory** plus append-only attempts, rather than only the samples that survived collection. Suggested versioned sidecars under a new data version are `risk/{allocations.json,raw-index.json,labels.jsonl,counts.json}` and source registrations; keep existing dataset/COMMIT bytes unchanged. All failed, cancelled, timed out, blocked, UNKNOWN and infrastructure-rerun originals remain in allocation closure. An infrastructure paired rerun has an explicit reason and parent attempt ID; it does not overwrite or remove the original.

Each derived label row binds allocation/group/episode/scene/physics seed, source layout and controller hash, policy/provider/model role identity, action/decision IDs, start/end steps and times, before/after original frame hashes, original command/control/raw-physics ranges, estimator and calibration source, independent label definition/evaluator version, split and missingness reasons. Hash and schema drift produce INVALID; missing raw evidence, a needed calibration or clock source produces UNKNOWN. Physical success/failure is recomputed; metadata merely describes what to recompute.

* **Global failure label:** register the exact prediction horizon and task outcome definition before collecting. For the current task-level label, use independently evaluated completion before the assigned deadline, with verified safety/terminal status; action feedback must not replace the episode outcome. Repeated frames from one task share a source group and are not independent calibration trials. Blocked/unstarted/timeout allocations remain failures in research denominators, but an incomplete physical trace cannot be converted into a fabricated measured geometric residual.
* **Action-conditional failure:** use only an actually started action/observation/remote request and its subsequent source-bound transition under a frozen action/horizon definition. No counterfactual outcome is copied to unchosen actions. No duplicate physical action can support two independent action labels. A sent cloud attempt, accepted candidate, ACK or skill return is not successful execution. REQUEST_CLOUD needs original wire plus actual subsequent contract/action provenance. STOP/REOBSERVE need explicitly registered non-motion outcome semantics rather than falsely setting an actuator-executed field. Until those source capabilities exist, unsupported action estimates remain None; LOCAL_RECOVER requires genuine verified lifecycle and development feedback, not formal G4 labels.
* **Geometry residual:** replay the exact registered online-only estimator on the original frame; compare its registered target point/geometry with independently reconstructed raw geometry offline. Freeze coordinate frame, units, target association and residual definition. A marker-center error does not by itself certify object extents, grasp offset, angular stability, whole-object identity or all obstacles. Missing/occluded marker or unresolved association is UNKNOWN, not zero error. If a broader geometry scope is needed, register it and its original geometry basis before collecting rather than changing the meaning of the existing scalar bound afterward.
* **Calibration residual feature:** the existing API passes `calibration_residuals` into an online feature. Its source must be an independently measured, preregistered sensor calibration artifact valid for that camera/asset/time, not the current sample's offline true localization error or future task outcome. Full calibration SHA, camera intrinsics/extrinsics/depth convention and measurement source are required; the current 48-bit floating fingerprint is a runtime guard, not an acceptance signature.
* **Motion residual:** replay current observable depth motion from two genuine new same-source frames; independently derive raw target/environment motion over the whole registered action-validity horizon. Freeze which entities and linear/angular/geometry displacement are covered. Endpoint agreement cannot rule out intermediate motion, lateral movement or occlusion. Missing angular/whole-geometry coverage does not silently become a scalar translational certificate.

## Clock gap: currently unresolved

`extract_risk_features` computes observed motion using the difference in **UTC captured_at wall acquisition times**. Camera acquisition also records sim_time_s, but these are distinct clocks. Raw physics step time and object velocities are measured in **simulation seconds**; T10 evidence age uses wall time. T8 may advance physics in chunks, including while waiting, and rendering pauses do not prove a 1:1 rate. The current raw-v2 header binds physics_dt_s, not a complete wall/simulation mapping for each step. It is invalid to subtract a simulation-speed truth value from a wall-speed feature and call the result a measured residual without that mapping.

A future collector must record a source-bound monotonic acquisition/step/action clock mapping and the declared time domain used by expected action duration. Replay checks clock continuity, step/capture ordering, uncertainty and complete action coverage. A fixed independently controlled simulator-clock policy may be an alternative, but changing online feature/T10 timing semantics requires a new version and review. Neither alternative is implemented or accepted here. Zero/nonmonotonic intervals, missing mapping, burst advancement or stale/cropped frames produce UNKNOWN. A caller-provided multiplier cannot certify the mapping.

## Train, calibration and selection replay

Use current `assign_splits` connected source/content/perceptual groups and its frozen 80/5/5/10 allocation rule; regenerate and compare the full committed splits. Identity/disjointness includes group, canonical physical+asset source, episode, physics state, content and perceptual duplicates plus raw action/ancestor frame identities. Viewpoint, corruption and derived frames remain in the same component. Compare all four risk partitions with T8 selection/foundation/power/formal/auxiliary pools and the union of development exclusions. Group-ID rewriting cannot erase the physical source. Keep risk parameter selection, B0-period selection and JOINT-weight selection as distinct registered inventories and purposes.

The current 101-group exclusion inventory and new marker-motion exclusion sidecar are separate originals. A new risk registration must explicitly union/revalidate both; this audit does not retroactively change the historical formal proof. Current role/source/asset versions must equal their registered basis or be explicitly versioned as separate domains; no cross-asset interpolation is claimed.

A second independently delegable task is new `research/risk_replay.py` plus `tests/test_research_risk_replay.py`, consuming the frozen reader contract. It replays each preregistered complete candidate parameter object/hash: train-only logistic/action fitting; calibration-only isotonic and grouped residual bounds; selection-only predictions and current minimum-Brier-then-parameters-hash rule. It compares all original model coefficients, normalization/ranges, calibrator blocks, group maxima/order statistic, predictions, scores and winner. Current SETTINGS and numerical rules remain unchanged; expanding candidate settings requires a separate versioned inventory, not an implicit YAML override.

All candidates use the same preregistered eligible selection population. Missing required predictions make the candidate selection incomplete; do not minimize a Brier score over a favorable surviving subset. Preserve original counts/UNKNOWNs separately from scored rows. Held-out test evaluates the frozen result only and never chooses candidates, thresholds or enabled actions. Reliability diagrams computed on calibration are labelled calibration diagnostics, not independent generalization evidence.

Current grouped residual calibration takes the maximum per group and rank `ceil((g+1)*0.9)`. At least nine independently labelled groups are needed for a finite bound under this current rule; geometry and fresh-motion eligibility are separate. The implementation skips absent residuals: the new reader must retain missing/allocation denominators and enforce the declared eligible population before replay, never interpreting skipped missing rows as full coverage. Both outcome classes are needed for logistic/isotonic probability preparation; uncovered action calibration remains None. Coverage0.9 is the frozen calibration setting, not a physical safety certificate or a change to formal NI/familywise gates. Action-condition estimates describe the logged behavior population, not an experimentally identified counterfactual recovery advantage.

## Integration ownership and noncircular admission

The first reader is independent of fitting, admission flags and runtime dispatch. The second replay task is independent once reader schemas freeze. Existing risk owner then adds a narrow registry-backed `VerifiedRiskEstimator.estimate(evidence_id, observation, previous_observation, current_binding) -> RiskEstimate` adapter which calls both reader and replay, checks current frame/calibration/assets/roles, and derives features internally. The legacy fit/calibrate/estimate interfaces stay available for explicit software math, but their flag or a caller-built audit object cannot be used as actual authority. Live-source changes invalidate any cached result.

Admission/runtime owner separately consumes the registered risk source/replay, independently reconstructed finite weight-selection outcomes, execution owner/checkpoint/current contract and capability evidence. Only that later complete METHOD audit can enable ordinary adaptive decisions; risk-source validity alone cannot authorize motion, LOCAL_RECOVER, cloud contract installation or formal execution. Fresh role probes and source inventories are required after changes to risk/runtime capability paths. Existing current capability set CONTINUE/REOBSERVE/STOP cannot be expanded by merely editing metadata.

Dependency order is: independent **T7b basic CV/Safety certificate and safe raw collection** → source-backed B0 selection/foundation/budget **INITIAL** → offline T9 risk source/fit/calibration/parameter selection → T10 calibrated gate → **SELECTION_EXPLORATION** for finite JOINT weights → accepted weight selection and registered owner/capabilities → METHOD → separate power/FINAL/formal. Risk data collection may use an explicitly registered safe baseline/offline teacher source without METHOD; it must not bypass current guards or require its own already selected JOINT winner. T7b baseline certification cannot depend on INITIAL-derived T9, or B0 foundation becomes circular. INITIAL's billing/baseline missingness remains an independent blocking prerequisite.

## Regression matrix and release conditions

`regression-matrix.json` names exact required cases and ownership. First reader RED cases cover malformed/unknown schemas, traversal/symlink, coherent rehashing of edited summaries, original allocation deletion, omitted failure attempts, reset prefix/terminal tail/action/command/control/frame omissions, foreign roles/assets, forged execution, partial safety scope and clock missingness. Reader software tests can verify reconstruction without admitting synthetic actual data.

Later replay RED cases cover counterfeit probabilities/parameter hashes, cross-split raw ancestors, test-driven candidate selection, duplicate action labels, per-sample oracle calibration residuals, missing geometry/motion rows, fewer than nine independent groups, stale pairs/domain drift and source-accepted rehash bypass. Integration RED cases preserve INITIAL/METHOD separation, own-selection exploration order, current-source reread, missing owner/capability failure and null bounds on required native motion.

This design package freezes inspected sources and read-only index/AST checks. It runs no physics simulation, model fitting or production test suite. Source/ref hashes verify what was inspected, not physical acceptance. The next implementation handoff should include RED→GREEN scoped tests, static checks, immutable dependency copies and independent review. Actual risk data collection, calibration, METHOD admission and formal analysis remain NOT_RUN/UNKNOWN until their own complete original sources are available.
