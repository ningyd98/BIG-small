# Original provider usage metadata reader

Two new isolated files implement an owner-registered reader for original provider-reported response metadata. This software work issues no network request, renderer operation or controller command and changes no collector, planning adapter, resource policy or protocol. Independent review is pending.

The reader first rechecks the complete original evidence inventory and current registered source hashes, then uses the existing original ledger/wire reader to bind every local attempt to its request and response bytes. Synchronous compatible Chat responses can supply an opaque response ID, exact model identity and nonnegative integer prompt/completion/total counts. Cached input and reasoning output remain subsets; they are not added again. The [official compatible Chat API](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions) documents these response and usage fields. A body response ID is preserved literally and is never converted into a native/header request ID.

Every original failed, timed-out or unsent attempt remains in the denominator. Missing, empty or partial responses, unsupported streaming responses, duplicate provider response IDs, incompatible model identity and inconsistent counts cannot provide observed usage. Rehashed wrong provider-version records, source drift, unlisted original files and invalid wire joins reject. The complete inventories are checked again after reading. This guards persistent changes during a read; it does not claim an atomic filesystem snapshot or remote-origin authentication.

Every result enforces `monetary_cost=None`, `billing_status=UNAVAILABLE` and `ORIGINAL_PROVIDER_USAGE_METADATA`. Token observations cannot prove settled fees, a tariff ceiling, full planning quotas, accepted assignment roles, INITIAL acceptance or execution authority. The registered owner inventory is a local source prerequisite, not evidence that a remote server produced the bytes. Existing actual billing remains unavailable.

The missing-module RED is retained in `red.log`. The first implementation's cold mypy arity failure is preserved in `first-cold-mypy-failure.log` and `first-type-failure-source.py`; replacing the variadic constructor call with explicit named arguments fixed typing without changing parsing behavior. Six additional negative cases cover empty/absent failure responses, wrong provider-version, streaming, reasoning subsets and source mutation during reading. They are additional verification, not retrospectively claimed RED cases.

Final local verification: 60 scoped tests passed in 3.04 seconds (22 new reader tests plus 38 existing resource-plan tests), Ruff passed for both owned Python files, and cold mypy passed for the new module. This is scoped software verification; no actual request or financial acceptance occurred.
