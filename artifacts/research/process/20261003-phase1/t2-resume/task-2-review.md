## Findings

1. **P2 — accepted camera dimensions can exceed the renderer framebuffer.** `src/cloud_edge_robot_arm/simulation/mujoco/camera.py:25` passes the requested dimensions directly to `mujoco.Renderer`. `SimulatorConfig` accepts widths through 1280 and heights through 720, but the supplied scene does not set offscreen dimensions. CPU-only inspection of `MjModel.from_xml_path("assets/robots/franka_panda/scene.xml")` reports `model.vis.global_.offwidth == 640` and `offheight == 480`. The installed MuJoCo constructor explicitly raises before creating a GL context when either request exceeds those values (`.venv/lib/python3.12/site-packages/mujoco/renderer.py:53–73`). Consequently an otherwise valid `MuJoCoCaptureSession(SimulatorConfig(camera_width=1280, camera_height=720))` cannot enter successfully. Configure the framebuffer to accommodate the requested bounded resolution before renderer creation, and cover the maximum supported dimensions with one real-render regression. Preserve the single-renderer lifecycle.

2. **P2 — the cross-pass calibration guard omits depth-conversion calibration.** `src/cloud_edge_robot_arm/simulation/mujoco/camera.py:86–96` snapshots and checks camera position, rotation and field of view, but not `model.vis.map.znear`, `model.vis.map.zfar` or `model.stat.extent`. The scene is prepared only once at line 100. The installed renderer subsequently reads all three model fields during each depth render to convert the frozen scene's depth buffer to metric depth (`.venv/lib/python3.12/site-packages/mujoco/renderer.py:185–210`). A persistent change to one of these fields after RGB rendering can therefore produce metric depth using different conversion parameters while passing every current physics/calibration check. Unlike the acknowledged mutate-and-restore race, this mutation remains present at all later checks and is directly detectable. Snapshot and check these depth-calibration inputs too; add a regression mutating each after the RGB pass and require rejection plus cleanup. This finding is based on the concrete installed renderer code path; I did not run a GPU reproduction while the root's full suite owned rendering.
