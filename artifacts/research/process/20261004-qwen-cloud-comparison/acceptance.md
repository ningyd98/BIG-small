# Qwen 云端接入与 RGB-D 能力对比

2026-10-04，已使用用户最后提供的 Key 和 Token Plan 北京端点完成 **4 个模型 × 16 个场景 = 64 次真实云端推理**。64 次均返回 HTTP 200、正常结束和符合 VisualDecision schema 的 JSON。逐次 socket 证据确认绑定物理网卡 `enp7s0`，禁用环境代理，没有回退到 `Meta` 隧道。

**本轮建议优先让 Qwen3.8-Max 进入后续云端复核实验。Qwen3.8-Flash 暂不作为直接生成抓放动作的主模型。** 这一建议来自当前协议下的开发测试，不代表所有任务的模型排名；尚未开展云端在线闭环、重规划或正式 G1 验收。

## 实测结果

| 模型 | 有目标时感知与规划通过 | 缺失目标时明确拒答 | 缺失目标却生成动作计划 | 响应 P50 | 响应 P95 |
|---|---:|---:|---:|---:|---:|
| Qwen3.8-Max | **10/12（83.3%）** | **4/4** | **0/4** | 3.63 s | 4.28 s |
| Qwen3.8-Flash | 6/12（50.0%） | 0/4 | 3/4 | 2.32 s | 3.20 s |
| Qwen3.7-Plus | 0/12 | 0/4 | 1/4 | 3.73 s | 3.89 s |
| Qwen3.6-Flash | 2/12（16.7%） | 0/4 | 0/4 | 1.26 s | 1.61 s |
| 本地 Qwen3-VL 4B，历史同图参考 | 12/12 | 3/4 | 0/4 | 未在本轮重测 | 未在本轮重测 |

“有目标通过”同时要求正确目标实例与绿色目的区域命中、有效深度、既有 RGB-D 顶抓几何门禁以及完整技能序列。它不是抓放成功率，也没有直接证明毫米级定位精度。“生成动作计划”只指现有适配器生成了非空步骤；本轮未执行这些动作。

拒答按既有 T3 规则判定：模型输出目标 null 或置信度低于 0.5，且没有形成已定位场景/动作契约。因几何门禁拦截错误坐标不计为模型明确拒答。因此，Qwen3.6-Flash 的缺失目标计划数为零，并不表示它正确识别了目标缺失。

延迟为非流式 HTTPS 完整请求耗时，包含连接时间；最多并行 3 个请求，四模型按同一场景轮流分组调用。未测 TTFT，也未测机器人任务端到端延迟。每模型仅 16 次，P95 仅作开发参考。

## 错误出现在哪里

1. **格式与连接都正常，主要失误在坐标和语义。** 四模型 schema 校验均 16/16；有目标时，目标实例命中分别为 Max 11/12、3.8-Flash 7/12、3.7-Plus 1/12、3.6-Flash 2/12。目的区域命中分别为 11/12、12/12、9/12、6/12。
2. **Max 的两个失败是目标点或目的点落到桌面。** `positive-01` 输出目标原图点 `[141,131]`，实际目标可见掩码质心 `[145.5,132.5]`，只有约 4.74 px 偏差，但采到的是桌面深度。`positive-12` 目标选对，目的点 `[127,78]` 落在绿色区域外；当前适配器仍生成了计划，离线实例判据将其判失败。
3. **3.8-Flash 存在高置信缺失目标幻觉。** 四个缺失紫色目标场景全部声称找到了紫色方块；三例生成 10 步动作计划。例如 `negative_absent-02` 实际选中黄色方块，仍报告“purple block”、置信度 0.95。仅靠有效深度/可抓取几何，无法保证物体颜色与任务一致。
4. **命中物体不等于可抓。** 3.8-Flash 的 `positive-07` 命中目标实例，但未通过顶抓几何门禁；因此目标命中 7/12，完整通过只有 6/12。

人工抽查了 `positive-01`、`positive-12`、`negative_absent-02` 三张 RGB 图，与上述目标/目的误选一致；未声称对全部图像做人工标注。诊断中可见表面质心距离不是独立标注顶面中心误差，不能拿它填 G1 的毫米级 P90 指标。

## 实验设置与证据边界

- 原始场景来自 T3 第一批 16 个开发场景：12 个存在目标、4 个不存在紫色目标。每模型每场景只调用一次，保留全部失败，没有重试取最好结果。使用已见开发场景，不是独立保留测试集。
- 320×240 同步 RGB 与深度可视化双图，`normalized_1000` 坐标；原始 float32 深度留在本地做几何计算。实例掩码仅用于离线评分，没有传给模型。
- 原有 `RGBDPlannerAdapter` 生成请求，经严格直连传输完成真实 HTTPS 调用，再由同一个适配器对真实响应做解析和几何检查。逐例验证云端与历史本地请求的提示文本及双图哈希完全相同。
- 四模型统一 `temperature=0`、`max_tokens=512`、`enable_thinking=false`、JSON object 输出。此次测量的是现有协议的直接适配效果；没有逐模型调提示、提高图像分辨率或开启思考模式。
- Token Plan 可用的四个实际 ID：`qwen3.8-flash`、`qwen3.8-max`、`qwen3.7-plus`、`qwen3.6-flash`。该套餐模型目录没有原计划的 VL-Plus/VL-Flash 或日期快照，所以没有用旧 Key 调用它们；别名可能随服务更新，不能宣称权重冻结。
- API 用量合计 **53,385 Token**：输入 43,072、输出 10,313。实际套餐 Credits/账单金额未测量，不能用按量 API 标价推算实际扣费。
- 默认运行模型、T3/T7 冻结证据和生产源代码没有变更；本轮没有模型训练、物理动作或真实机械臂动作。与本地参考的差异也不能外推为所有场景中云端必然更弱或更强。

## 凭证与网络

最终端点：`https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。

初始系统 DNS 把原工作空间域名映射到虚拟地址，路由指向 `Meta`；该路径在发送凭证前被停止。随后复用仓库 `datasets.external.network`，DNS 使用 `223.5.5.5` / `223.6.6.6`，DNS/TCP 均绑定 `enp7s0`，TLS 证书/域名校验保持开启。

旧工作空间 Key 仅用于一次模型目录请求，HTTP 200；新套餐 Key 在旧 URL 上一次目录请求返回 401；用户提供正确 Token Plan URL 后目录请求返回 200。所有 64 次推理均使用新套餐 Key 和最终端点。三个目录请求不计入模型能力分母。

密钥由隐藏输入读入进程内存，没有写入源码、配置、报告或请求文件；持有密钥的进程已关闭。逐响应文件包含实际 peer、绑定网卡、模型 ID、用量、请求哈希和原始输出。
