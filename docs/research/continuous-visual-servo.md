# 连续 OpenCV 视觉伺服（MuJoCo 开发模式）

在运动技能内部重新获取配对 RGBD、测量目标、检查动态安全条件，再更新关节目标。Sol/Molmo 保留原规划/初始选点职责，伺服循环不调用模型。相机可保持顶视方向在世界坐标中平移，每帧使用同时采集的外参与标定摘要。

默认物理频率 240 Hz，视觉周期 8 步（30 Hz），关节指令周期 5 步（48 Hz）。视觉期限可拆分物理步进，关节指令仍保持固定间隔和连续的速度状态。墙钟吞吐、采样耗时单独记录，不能把仿真 Hz 当成硬实时保证。

## 零模型本地验证

```bash
MUJOCO_GL=egl .venv/bin/python scripts/verify_visual_servo.py \
  --output experiments/results/phase9/visual-servo-new-run
```

输出目录必须不存在。默认验证固定相机、运行中平移相机、外力驱动目标移动，以及将相机移出目标视野后的停止。目标由 RGB 颜色测试夹具提名；不把它称为 Molmo/Sol 测试。控制残差和独立物理水平误差均记录，前三例均需不超过 5 mm；丢失例要求停止并 hold。它不是完整抓放成功率或泛化实验。

每次捕获的 RGB、原始 depth 和标定元数据、下发指令、视觉/控制样本及独立物理证据均保留；正式研究资格继续是 NOT_ACCEPTED。

## 接入既有组件诊断

在 `scripts/run_sol_molmo_single_episode.py` 原有显式组件执行参数中增加：

```text
--visual-servo --camera-position 0.35 0.00 1.35
```

相机参数单位为米；支持 x∈[-0.1,0.8]、y∈[-0.5,0.5]、z∈[0.6,2.0]。这些范围只约束开发相机，并不保证所有位置都看得见目标。相机参数、伺服配置和相关源代码摘要纳入角色绑定，job 与角色不一致时拒绝启动。没有新参数时沿用原模式。

完整源码绑定沿用原 worker 的技能边界核验；高频环在获取观测前、目标安全核验后重查当前租约、尝试、取消和期限。每帧不重复读取整套源码文件；模型配置也不在高频环使用。

模型执行仍需原有 profile、资产、`--execute --component-diagnostic --allow-paid` 等授权参数。本次实现验证不发起真实付费模型调用。

程序接口：`backend.set_camera_position((x,y,z))` 只更新相机位置，不推进物理；`backend.capture_sensor_frame()` 产生不含实例分割 ID 的新鲜 RGBD。相机调整发生在同一个仿真所有者线程中，禁止在 RGB/depth 两次渲染之间或物理观察回调中修改它。

## 测量与停止条件

- 初始目标必须通过原唯一颜色、深度和完整几何检查。注册标记先与初始目标建立 10 mm 内的关联，再连续提供当前位姿；标记丢失立即停止，不能复用旧坐标。无标记的颜色模式要求每帧完整唯一支持。
- 最大帧年龄/间隔 100 ms；拒绝参考帧重用、重复、倒序和未来时间戳。相机位置变化必须伴随对应标定版本变化，内参、方向、episode 或来源漂移拒绝。
- 单帧目标变化最多 10 mm，相对技能起始终点最多校正 50 mm。每个动态目标使用同一份 step/contract 再次经过 SafetyShield，原任务与技能预算不重置。
- LIFT/RETREAT 终点和 PLACE 工具高度偏移在技能开始时冻结。GRASP/RELEASE 保留原手指轨迹；速度、加速度、硬停止、租约和取消检查继续生效。
- LIFT 原有 0.5 秒双侧接触保持中继续按视觉期限采样与归档，固定终点保持不动；技能后的安全检查使用最后一帧与实际动态目标。
- 到达目标后还需三个新鲜样本满足位置误差 ≤5 mm、姿态误差 ≤5°，才报告该次运动收敛。所有运动退出路径先 hold，清除技能会话。

这是注册场景中的开发估计，未提供完整表面或标记误差的物理标定证书。真实可移动相机驱动、相机旋转/变焦、自动最佳视点规划、真机实时性及完整抓放验收仍需另行验证。相机外参语义参照 [MuJoCo 相机数据定义](https://mujoco.readthedocs.io/en/stable/APIreference/APItypes.html)。
