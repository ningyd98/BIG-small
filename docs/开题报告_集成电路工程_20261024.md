## 一 选题意义

本课题以《面向边缘智能场景的小型机械臂云边协同控制系统的设计》为毕业论文题目，针对边缘计算资源受限、云端响应存在延迟以及视觉信息可能失效的问题，研究云端规划、边缘决策与端侧感知执行相结合的控制方法。通过在任务成功率和安全约束下优化计算与通信分工，为面向嵌入式处理器的智能控制系统设计、接口组织和资源利用提供可验证的工程方案。

课题最终拟将系统封装为 **BIGsmall Embodied Harness，即面向具身智能的云边端协同运行与实验支撑框架**。它通过统一契约连接任务、模型、观测、技能和环境，组织受控执行、反馈、成本记录与独立评测，使研究方法能够在明确版本和条件下复用、比较和复现。首个参考场景仍为小型机械臂的受控桌面抓放，接口扩展性不等同于已经验证跨机器人通用能力。Harness 是三项研究成果的工程载体，其封装工作与方法创新、性能结论分别评价。

## 二 研究内容

### 2.1 技术背景与总体方案

云机器人利用远程计算与共享资源扩展机器人能力，边缘计算则关注靠近数据源进行处理，以应对响应时间与带宽等约束。[云机器人综述](https://doi.org/10.1109/TASE.2014.2376492)和[边缘计算研究](https://www.weisongshi.org/papers/shi16-edge-computing.pdf)为本课题的分层设计提供了背景。已有研究还将感知不确定性与通信成本纳入机器人卸载决策，并通过技能可行性将语言规划连接到物理执行。[网络卸载研究](https://www.roboticsproceedings.org/rss15/p63.html)、[SayCan 研究](https://research.google/pubs/do-as-i-can-not-as-i-say-grounding-language-in-robotic-affordances/)说明，云边分工和语言规划本身已有研究基础；本课题进一步关注观测过期、遮挡和执行反馈变化时，如何判断动作是否仍可执行，以及如何进行有界局部修复。

研究对象限定为小型机械臂的受约束抓取、搬运和放置任务。沿用项目现有云、边、端总体方案，保留已选定的可见姿态标记、顶视相机及控制器，以 MuJoCo 物理仿真作为近期主要验证环境。

商汤 SenseNova-RoboRSI 提供了共享运行时、Agent 配置、执行轨迹与评测的参考，并将固定模型参数下的 Harness 改进与模型训练区分说明。本课题借鉴其接口组织、配置指纹、反馈记录和版本复评思路，在现有系统上逐步封装，不另建执行引擎。研究重点仍是观测失效、风险与通信成本、有界恢复三类问题；外部榜单成绩不移用为本项目成果或验收指标。[官方说明][RSI-overview]、[Agent配置][RSI-agent]、[评测指南][RSI-evaluation]

| 层级 | 主要研究内容 | 职责边界 |
| --- | --- | --- |
| 云端规划层 | 按当前用户选定方案采用 `gpt-6.1-sol`，完成任务理解、初始规划、监督和重规划 | 通过 provider 接口输出候选意图；模型实际身份与参数纳入运行记录，不进入实时伺服环 |
| 边缘决策层 | 汇总观测和执行状态，检查任务契约，依据风险、时效与成本筛选可行决策 | 近期采用确定性规则与成本判断；边缘模型选型后置，启用前单独验证 |
| 端侧感知执行层 | 使用 OpenCV、RGB-D 几何和姿态标记构造视觉证据，通过现有技能执行器、控制器与 SafetyShield 执行动作 | 独立处理动作约束与停止；证据不足时保留“未知”状态 |

系统数据流为：**任务输入 → 云端结构化规划 → 边缘证据与能力检查 → 端侧受控执行 → 新观测与效果验证 → 继续、重观测、修复、请求云端或停止**。模型请求异步执行，普通决策在技能边界应用，硬停止独立于模型响应。

Harness 拟在这一闭环外统一配置、生命周期、观测证据、技能及环境适配和评测接口。Agent 输出始终经过既有 SkillExecutor、仓储 CAS、控制器与 SafetyShield；新增接口不能提供直达关节控制的旁路。每个 provider 在途请求上限为1，尚未验收的联合决策和局部恢复能力保持关闭。接口契约绑定任务、episode、观测时刻与有效期、标定、计划及配置版本；具体公开API在后续实现时冻结，不将规划名称写成现成软件接口。

### 2.3 拟开展的研究工作

**共同工程基础：云边端功能划分与 Harness 接口设计。** 明确云端任务规划、边缘状态处理和端侧控制的时间尺度，统一观测、契约、候选动作、执行反馈和环境适配接口，研究异步请求与本地控制的协调方式。记录处理器及运行环境、线程与队列配置、内存占用和接口开销。这是以下三项研究共用的实现与评价底座，不单独增加一个算法创新结论。

**第一，视觉观测与动作条件一致性。** 将目标身份、深度、相机标定、观测时刻及运动误差界与动作绑定，在云端返回和动作提交前复核。当目标缺失、遮挡、深度无效或证据过期时，区分“不满足”和“无法确定”，防止将局部可见、模型判断或执行器返回直接当作任务完成。Harness 统一记录三值条件、拒绝原因及新帧效果，与共同安全层上的B3基础门控比较，对应G3。

**第二，风险与通信成本约束下的协同决策。** 在继续执行、重观测、局部恢复、请求云端和停止等有限候选中，先筛除缺少能力或证据支持的动作，再依据经校准的风险及实际成本进行选择；局部恢复通过相应验收前不进入候选。Harness 固定共同模型、提示生成规则、上下文预算、经验版本、控制器及安全层，与合格周期监督B0、固定阈值B1及规则模式B2公平对照，验证请求节省是否同时保持成功率和安全表现，对应G2/G2a。

**第三，执行反馈与有界局部修复。** 根据证据依赖识别受影响的未完成步骤，使用新观测复核应保留的效果，在有限预算内实施修复并验证结果。研究任务重启、迟到回复、预算耗尽等条件下的重复执行防护，在同故障与预算下比较局部修复与B4完整剩余计划修复的成功率、耗时和通信成本，对应G4。Harness 保留修复前后版本、效果身份、原预算和失败记录，不能以重启刷新预算或重放不可重复动作。

### 2.4 研究目标与验证方法

以下指标继承当前项目规划，均为**待实验验证的目标**。

| 评价内容 | 计划目标与判定条件 |
| --- | --- |
| 基础感知与抓放 | 对正确识别且深度有效的目标，三维定位误差 P90 不超过 10 mm，并报告有效覆盖率；独立静态抓放成功率不低于 90% |
| 协同决策收益 | 相对合格周期监督基线，云请求均值降低至少 30%；成功率差的单侧 95% 置信下界大于 −3 个百分点，安全违规率差的单侧 95% 置信上界不超过 +1 个百分点 |
| 视觉证据门控 | 相对共同安全层上的基础门控，无效动作机会误放行减少至少 50%，且绝对误放行率不超过 2%；有效安全机会错误拒绝率不超过 5%，未知情况单列 |
| 有界局部恢复 | 在预定义的 200 个可恢复故障组中，恢复成功率不低于 80%，相对完整重规划的失败惩罚恢复耗时中位数降低至少 30%；已完成不可重复动作的重提交为 0 |
| 资源与接口性能 | 测量云请求数、实际收发字节、端到端决策延迟、CPU/GPU 占用及内存开销；应用字节减少至少 25% 和失败惩罚任务耗时 P95 减少至少 15% 分别评价 |

验证按“开发与标定—基线筛选—基础先导—方法冻结—功效先导—正式比较”推进。周期监督在 0.5、1、2、5 秒四种周期上筛选；只有静态成功率不低于 90%、整体成功率不低于 80%、安全违规率不高于 1% 的候选，才进入后续成本比较。

基础先导和方法冻结后的功效先导各采用互不重叠的 120 个场景组。正式样本量按预先规定的功效规则，从每方法 600、1,200、1,800、2,400 个配对场景组中选择。训练、标定、策略选择和正式测试按来源组隔离，在不同网络延迟、丢包、遮挡和深度噪声条件下进行对照，报告配对差异、置信区间和多重检验校正结果。

任务成功同时要求在线效果验证和独立物理评价成立，其中抓取抬升不少于 50 mm 并保持不少于 0.5 秒，释放后在目标区域稳定不少于 1 秒。离线真值不进入在线决策；失败、超时、停止和阻塞均保留在预分配分母中。当前阶段的结论限定于模拟云边端部署及物理仿真，资源测量注明实际运行设备，不外推为真实嵌入式板卡的控制性能或能耗。

上述评价继续服从G0—G5、B0—B5及INITIAL/METHOD/FINAL。周期selection使用120组，与新基础先导、功效及正式组互斥；按场景聚类和条件分层进行至少10,000次配对bootstrap，采用95%区间、Holm校正及α=0.05、power=0.8的原规则。任务失败惩罚 `Tcap=clip(ceil(P99_B0成功耗时×2/10)×10,120,600)` 秒、恢复失败惩罚 `Rcap=60` 秒保持；G5及训练扩展仍为可选。模型实际身份、配置、资产、物理时间/墙钟和等待期间环境推进方式均纳入比较条件，未知费用及纯推理时间记为null。

### 2.5 Harness 工程交付与独立验收

最终拟交付本项目可安装Python接口包与CLI、统一配置/schema、Agent/技能/环境适配规范和示例、受控桌面抓放参考场景、轨迹与成本报告、独立评测入口以及版本/依赖/许可证和证据清单。具体命令与API须在实施后验证，现阶段不将上游RoboRSI命令列作本项目使用方法。

工程验收分三层：先在声明的清洁环境安装并运行无凭据离线示例，验证契约和生命周期；再在具备资格与资源条件的MuJoCo环境验证正常闭环及规定拒绝/失败用例；最后依据冻结manifest复算指定实验结果、比较版本和追溯失败。接口替身、单次演示和安装成功不能替代正式成功率、成本或安全研究。未通过完整研究门槛时可交付标明限制的开发版，不能称正式研究验收版。

后置的受控离线改进只使用隔离开发来源，按“轨迹分析—候选提示/上下文/经验—固定条件评测与回归—审查批准—冻结发布—可回滚版本”推进。近期保持模型参数固定，正式测试不调参、不跨测试episode写入新记忆；经验坐标必须用当前帧重新定位，经验收益另设对照。自动扩展机器人种类、外部benchmark、VLA/27B训练和通用经验检索不纳入首版核心验收。

发行物与实验原件分层交付。凭据、完整批量raw、运行数据库、模型权重和第三方SDK按既有边界管理；说明数据访问、依赖安装和许可条件。清单及派生图表不能冒充完整远端复现包。详细收口任务见[现行项目计划书](plan.md)。
