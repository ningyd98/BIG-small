# RGB-D 直接输入与本地 MuJoCo 数据集设计

日期：2026-10-03。状态：供审阅的设计，不代表功能已经完成或已经获得实施验收。

## 目标与范围

用户要求当前项目以视觉和深度作为直接输入，并希望利用本地 MuJoCo 生成训练和测试数据。本设计统一这两条链路：在线视觉规划/仿真执行与离线数据集生成。数据集生成不依赖本地大模型在线；模型用于视觉规划与评测。数据导出包含训练所需标签和格式，但本轮不包含模型微调作业、云端训练或真实机械臂部署。

三个可独立验收的工作包：A：RGB-D 观测与在线规划；B：静态感知/定位数据集；C：物理技能执行、示范轨迹与闭环评测。B 依赖 A 的采集接口，不依赖视觉模型服务或 C 的抓取控制器。C 必须通过物理执行验收后才能生产成功动作示范。

## 当前基线

已有未提交原型：MuJoCo RGB/深度渲染、RGBDObservation、双图像模型请求、像素反投影、默认工作台 RGBD 分支、Isaac 图像传输。部分局部测试通过，仍需统一接口、完整回归、真实模型调用和独立审查；已知历史恢复验证存在回归失败。

`simulation/mujoco_adapter.py` 的 move_to_pose 当前只更新软件 RobotState；`simulation/evaluation/metrics.py` 的物理试验主要跟踪固定关节目标。现有 `assets/robots/franka_panda/scene.xml` 是简化参考模型，不能直接宣称真实 Franka 性能或物理抓取已验证。数据采集可以先交付，动作轨迹必须另补物理技能桥接。

## 固定约束

- 在线模型输入必须包含 RGB 与注册深度；禁止无提示降级为文字或 Mock。
- 深度语义为 optical_z_m：光轴方向距离、米、little-endian float32；0 表示无效。
- 相机坐标为 +X 向右、+Y 向下、+Z 向前；camera_to_world 为行优先 4×4 刚体变换。
- 默认采集分辨率 320×240，数据集配置可选择 640×480；最大宽高 1280×720。
- 在线观测在接收时超过 5000 ms 或超前服务器超过 1000 ms 即拒绝；离线数据通过专用读取器处理，不修改历史时间戳伪装实时数据。
- 默认本地模型 qwen3-vl:4b-instruct，默认服务 http://127.0.0.1:11434；不承诺未经实测的速度与精度。
- 初始每个 GPU 只运行一个渲染进程，批内复用模型和渲染器。
- 训练/验证/测试按 group_id 划分为 80%/10%/10%；同一 episode、多视角、增强样本和指令改写不得跨集合。
- 数据生成默认 smoke：100 个独立场景组、每组 1 帧；validation：1000 组；full：10000 组。轨迹集默认先验收 20 个 episode，再扩展。
- 每批采样尝试上限为目标场景组数量的 5 倍；不足时报告 INCOMPLETE，不无限重试或降低质量阈值。
- 运行大文件保存在 datasets/ 或 artifacts/；配置、代码、schema 与文档进入版本管理。
- 保留用户原有 docs/README.md、两份中文文档和 output/ 改动；本计划阶段仅写设计与计划文件。
- 本轮限本地仿真；不执行真实硬件控制或付费云推理。

## 两条数据路径与真值边界

在线：相机 RGB-D → 只含观测/指令/机器人本体状态的 PlanningInput → 视觉模型 → 像素目标与技能序列 → 深度定位 → TaskContract → 安全检查 → 仿真技能执行 → 新观测。

离线：场景采样 → 实际物理状态 → 同一状态的 RGB/深度/实例分割渲染 → 标签生成 → 质量检查 → 分组划分 → 数据集文件。读取仿真真值的组件仅限离线标注器、显式 GROUND_TRUTH_TEACHER 示范器和只读评估器。在线 VISION_POLICY 不得访问它们；文件名、提示词、缓存和日志构造也须防止真值被拼入请求。

通用视觉模型接收 RGB 和完整深度可视化两幅图，并附深度映射范围；原始浮点深度用于几何计算与数据集保存。这是双图视觉输入配合数值深度处理，不宣称原生 RGB-D 四通道编码。自定义深度编码器/原生 RGB-D 策略模型属于后续模型研究。

## 观测、标签与目录契约

每帧拥有 frame_id、episode_id、group_id、sim_time_s、captured_at、尺寸、K、camera_to_world、深度约定、相机名、状态哈希与文件校验和。RGB、深度、分割取自同一冻结仿真状态；渲染多个 pass 时不得推进物理时间。

RGB 使用 RGB PNG；深度使用无 pickle 的 float32 NPY（数据集）或原始 float32/base64（API），必须无损互转；实例标签使用整型 NPY，通过 geom ID 映射稳定的语义实例 ID；深度可视化仅用于展示与 VLM 输入。JSONL 只保存相对路径，不将大图片重复 base64 嵌入。

标签分层：

- PERCEPTION：语义类别、实例 mask、可见框、可见像素数量、物体真实位姿、目标区域、可见/遮挡状态。
- GROUNDING：任务指令、目标实例标签、可见表面像素、该像素深度与反投影位置、目标区域可用像素。物体中心、可见表面点和抓取位姿是三个不同字段。
- SKILL_PLAN：高层技能与参数，显式记录 label_source 与 execution_verified；模板计划不自动视为成功动作示范。
- TRAJECTORY：每帧观测、关节/夹爪状态、执行命令、技能边界、接触事件、下一帧、终态与原因；仅实际物理推进产生的轨迹可标为 PHYSICS_EXECUTED。

目录：

```text
datasets/<dataset_id>/
  manifest.json
  samples.jsonl
  splits/{train,val,test}.jsonl
  episodes/<episode_id>/
    scene.json
    frames/<frame_id>/{rgb.png,depth.npy,depth_vis.png,instance.npy,camera.json}
    labels.jsonl
    actions.jsonl                 # 仅轨迹集
    result.json                  # 仅执行集
  reports/{quality.json,rejections.jsonl,duplicates.json,split_audit.json}
  exports/{grounding_sft_train.jsonl,grounding_sft_val.jsonl}
```

schema_version 固定为 rgbd.dataset.v1。manifest 记录提交 ID、dirty tree hash、仿真器/渲染后端/模型版本、资产哈希、配置哈希、随机种子、采样与拆分算法版本、标签来源、失败计数、资源消耗和生成时间。可复现内容哈希不包含墙钟时间。跨 GPU/驱动不承诺像素逐字节一致，几何状态重放与同环境内容复现分别验收。

## 场景与自动标注

第一版支持桌面单目标方块放置，新增 0～3 个干扰物；自动生成与实际颜色/目标一致的中英文模板指令。物体尺寸、位姿、颜色、光照强度、相机姿态、深度噪声在配置白名单内采样；质量/摩擦/阻尼等复用已有随机化组件。变更必须反映到实际 MJCF/模型参数，不能只记录到 metadata。

先生成静态 RGB-D；有质量/摩擦等动态参数的样本需明确其尚未经过动作验证。物体投放后进行物理稳定性检查，拒绝越界、严重穿透或目标不可见的布局。首版正样本默认目标可见像素至少 100、目标有效深度比至少 95%；负例单独标为 REQUEST_MORE_OBSERVATION，不能伪造成功目标。

mask 必须来自实际实例分割 pass；可见框从 mask 得出，禁止把投影的完整几何框当成可见框。目标像素从可见 mask 内部选择并验证深度；目标区域像素需在可见区域内且没有占用。质检用已知平面/几何测试射线检查米制深度与坐标变换。

## 数据质量、拆分与恢复

先对基础场景配置分组与拆分，再生成其多视角和增强变体。分组确定性算法使用 canonical scene 配置与采样版本，排除 split 名称、文件路径、时间戳和纯命名 seed 差异。按组排序分配确定性配额；100 组得到 80/10/10。按内容/场景哈希检查跨集合重复；额外检测近重复并输出待审清单。

域外测试使用独立场景组和保留的相机/光照/干扰物组合，不把同一基础场景仅改噪声后当成独立测试。测试集不导入训练导出器，不用于反复调提示词；调试使用验证集。

逐 episode 写临时目录，校验成功后原子发布，再写索引；重启从 manifest 和校验和恢复，避免重复计数、半文件进入训练集及覆盖已有不同配置的数据集。限制总样本、磁盘空间与失败尝试次数；API 只接收注册配置和结构化参数，不接收任意路径/脚本。

## 物理技能与闭环

新建物理技能适配器实现现有 RuntimeSkillRobot，使用目标位姿求解关节目标并调用 MuJoCoPhysicsBackend 的 actuator 与 step。每个技能必须以实际状态、误差、接触和超时判定结果；技能执行期间禁止修改对象 qpos 来制造抓取或放置成功。抓取仅由夹爪接触/物理约束产生，任何辅助约束模型须单独标注并禁止混入无辅助物理基准。

现有 contracts.Pose 仅包含 xyz，不能表达抓取朝向。物理控制层新增 MotionTarget(position: Pose, orientation_wxyz: tuple[float,float,float,float])，四元数表示 TCP 坐标到世界坐标的旋转并校验单位长度；不破坏现有高层合同。第一版顶抓朝向由参考资产的工具轴和配置确定，定位点、TCP 抓取目标与物体中心分别保存；物体真值标签另保存 position 与 orientation_wxyz。物理到达测试同时检验位置与朝向，不能仅以 xyz 到达判断可抓取。

先验证当前简化资产的关节、夹爪碰撞与抓取可行性；无法物理抓取时修正当前参考资产的动力学与碰撞结构，记录资产新版本，不自动换成未审计资产。完成后至少通过：自由运动到达、闭合夹爪但未接触时失败、离桌举升、移动、释放、落位稳定、不可达及掉落处理。

真值教师可生成离线专家示范，标签来源必须明确。视觉闭环控制只读取 RGB-D 定位和机器人本体状态。关键技能前重新观测并检查场景变化；物理控制速率与模型推理速率解耦，模型超时可停止/等待而非保持过期目标运动。

实际完成判据：物体离开初始支撑面达到配置举升高度；放置后物体在目标区域内、已释放、在连续 0.5 秒内稳定。几何包含和接触由独立只读真值评估器量化；视觉验证结果也单独记录，不能把二者混成模型能力。

## 模型、工作台与评测

默认规划 API、工作台和 dry-run 共用活跃模型配置，切换模型后下一请求生效，并保留每次运行的配置快照。检查视觉能力，模型不可用返回 BLOCKED_BY_ENV。离线数据生成仍可正常工作。旧软件实验必须显式 LEGACY_PIPELINE，并保持历史含义。

工作台增加输入方式、任务指令、RGB/深度预览、模型像素标记、数据生成配置/进度/质检入口。运行类型区分 CAPTURE_ONLY、VISUAL_PLANNING、VISION_CLOSED_LOOP、DATASET_GENERATION。规划成功不等于执行成功；没有模型时不显示模型推理已完成。

评测分开报告几何精度、视觉定位、JSON/技能有效率、任务执行成功率、环境阻塞率和速度。记录冷启动/热启动、TTFT（仅实际流式测量）、完整有效决策延迟、采集/编码/传输耗时、推理耗时、GPU 显存、吞吐与资源峰值。非流式接口的 TTFT 标 NOT_MEASURED，不能拿整体请求时间冒充首 token 延迟。

验收阶段依次为：100 帧数据 smoke、1000 帧质量验证、20 次教师物理 episode、20 个独立视觉闭环测试场景，最后才启动 10000 帧批量生成。前述数量是计划配置，不是已完成结果或模型精度承诺。真实硬件与 sim-to-real 泛化不由本计划的 MuJoCo 测试替代。
